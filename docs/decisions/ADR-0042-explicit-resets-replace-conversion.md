# ADR-0042: Explicit resets replace pre-1.0 conversion

- Status: Accepted
- Date: 2026-10-18
- Decision: Owner direction for #266 and #188 (#297, #284; decision ledger in #278, "Pre-1.0 data"). Supersedes the conversion mechanics of [ADR-0039](ADR-0039-format-four-definitions-only-cutover.md) and, for format changes, the one-off-migration sentence of [ADR-0020](ADR-0020-clean-design-until-release.md).

## Context

The format-4 cutover (ADR-0039) shipped an offline store converter, a portable-export converter, automatic conversion of old imports and of browser device drafts, frozen format-2 and format-3 contracts, and an acceptance suite for all of it. The owner's store was converted on 2026-10-18 (`dcd90e6`, recorded on #280). Keeping that machinery means maintaining frozen schemas and conversion rules for formats that no supported store, export or device draft should still hold.

The owner's decision: prefer clean current-format code and explicit operator resets over historical conversion. Preserve current-format durability. Old stores, old imports and old device drafts refuse clearly; startup never silently wipes data. Existing damaged history may be deleted explicitly or repaired by hand; automatic preservation or repair is not required. An old cutover manifest is not standing permission for anything.

## Decision

**Current format only.** The build reads exactly one stored format, `CURRENT_DEFINITION_FORMAT` (4). An empty store is initialised (schema, migration ledger and format marker in one transaction); a store marked with the current format and complete structure is reopened; anything else is refused before any write by `guardCurrentStore`, with `UnsupportedStoreError` (`STORE_UNSUPPORTED`) naming what it found. Nothing is converted, stamped or repaired by inference.

**Refusals name the way out.** Startup refusal names the data directory, the database, the format found, the format required, the reason, and the reset dry-run command. `--preflight` reports the same store as a failed database check. Importing a document that declares another format answers `400 LOOP_FORMAT_UNSUPPORTED` with `foundFormat` and `requiredFormat`. A browser device draft in another format is shown as unsupported, never loaded, converted or overwritten; while one is held under the active or set-aside key, editing and device writes pause until the user discards it with **Discard this device draft**, whose text names the loop, the draft and that only this browser's copy is removed.

**The explicit reset** is a CLI action of the API binary: `node apps/api/dist/main.js --reset`.

- Without `--yes` it is a dry run: it reads the data directory and prints the manifest, and changes no byte of that directory. Private-copy housekeeping in the system temp directory is described below. It refuses while another process holds the data-directory lock (checked without taking it).
- `--yes --data-dir <path>` performs the reset only when `<path>` resolves to the data directory the same environment configures (`GG_DATA_DIR`, or `~/.graphgoblin`). Restating the target in the confirmation means a different shell or a stale environment variable cannot aim a confirmed reset at another store; a manifest hash was considered and rejected, because a reset removes the store whatever it now holds and a hash would add a second step without protecting anything the operator wants to keep.
- The confirmed reset takes the data-directory lock (refusing while an instance runs), plans again under the lock, prints the same manifest and removes exactly it: the run workspaces under `workspaces/` whose names are stored run IDs (when the store can be read), `artifacts/`, then the database and its `-wal`, `-shm` and `-journal` sidecars, and finally the lock file when it is released. Workspaces and artifacts go first so that a reset that stops part of the way still has the run IDs it needs when it is run again.
- Before printing or executing the locked plan, a readable preview followed by an unreadable locked read refuses, even if the preview found no run workspace. The refusal includes the read failure and says to run the reset again. It also refuses if the locked plan would keep any path selected as a run workspace in the preview, or a parent of that path, even when both reads succeeded but returned different run IDs. No removal starts and the acquired lock is released. Both reads unreadable retain the damaged-store behaviour: remove artifacts and database files, keep all unmatched workspaces. An unreadable preview followed by a readable locked read may proceed using the locked run IDs; an unchanged readable plan proceeds normally. This prevents a transient reader exit or timeout from discarding the only database that can identify those workspaces on a rerun.
- Listing stops at entries identified as symbolic links or junctions, and removal unlinks those entries themselves. Immediately before each removal it rechecks, using `lstat` with bigint device and file index values and the same volume-root identity construction, the identities captured by the fresh plan under the lock: the physical data-directory root, every physical ancestor (including kept database folders), and the entry itself. A moved, replaced or newly linked path stops the reset through its incomplete-reset report, naming the entry and the changed path and listing what was and was not removed; the replacement is left in place. Node offers no handle-relative removal, so these checks narrow but cannot eliminate a race with an external process changing the tree between the check and `unlink`/`rmdir`. The data-directory lock prevents GraphGoblin itself from changing the tree concurrently. Subject to that remaining race, repositories, user working directories and harness installations referenced by loops are untouched. It refuses when the configured database is outside the data directory, is not a local file, is reached through a link, is not a regular file (a directory, a link, a FIFO, a socket or a device is never a database file, and is refused before the store is read), lies inside `artifacts/` or `workspaces/`, or is named `artifacts`, `workspaces` or like a lock file: a database with one of the names the reset owns would be listed twice, or both removed and kept, so the configuration is refused before anything is listed. The configured database path is resolved segment by segment to the directory's own spelling of the same entry by filesystem identity (device and file index), never by letter-case folding: a different case or a Windows short name such as `GRAPHG~1.DB` resolves to the listed name, two distinct files whose names merely fold alike (`K.db` and the Kelvin-sign `K.db`, or two names in a case-sensitive directory) stay distinct, a spelling that identifies no listed entry or more than one is refused, every ancestor is checked to be a physical directory before it is entered, and on Windows a name with a trailing dot or space is refused because Windows resolves it to another name. The manifest spells the database, its sidecars and the reserved directories as the directory lists them, and entries are excluded from Keeps by identity, so a removed entry is never also kept under another spelling. The identity carries the path's volume root because Windows reports one device number for every volume, so a file index alone could repeat across `C:\` and `D:\` (two drive letters for one volume therefore compare as different, which only refuses more). The same identity rule decides whether `--data-dir` names the configured data directory (both must be directories with one identity; a stream or file that shares a directory's identity is refused). The database must lie under the configured data directory's own spelling or its physical path, compared exactly rather than by case folding, so a parent that keeps `Data` and `data` apart can never have one directory's database planned against the other, and a link to the data directory used only in the database path is refused as outside (linked database paths are refused); every segment below the data directory is then resolved by identity, with each ancestor checked to be a physical directory before it is entered; on Windows a name containing a colon (an alternate data stream of a file) is refused, because the stream shares the file's identity without being the file. A final check that the manifest names every path once and never both removes and keeps one guards the invariant.
- Special files are classified as `other` only when `lstat` can inspect them without following them: inside a removed directory they are unlinked, at the root they are kept, and as a database they are refused. If inspection fails with access denied (including Windows AF_UNIX socket reparse points), both dry and confirmed resets refuse before removal, name the absolute path and explain that it cannot be inspected on this system. The operator must stop the program using it, check permissions and move or remove the entry themselves before retrying. No fallback follows it or removes it blindly.
- It keeps `master.key` (key material carries no format, and deleting it would make the secrets in any backup of the database unreadable; the next store reuses it) and every other entry, and lists what it keeps.
- The store's format marker and run IDs are read from a private copy in a child process: opening SQLite, even read-only, writes `-wal`/`-shm` beside a database, and libsql on Windows keeps a closed database file locked until its statements are garbage collected. The dry run therefore changes no byte of the data directory. The copy owner runs detached with a hidden window, so Windows does not kill it when the CLI's process job closes. It owns the copy in a dedicated `gg-reset-store-<six random characters>` temp directory, records its PID and directory identity before copying, and records the SQLite worker PID before allowing that worker to open the copy. It waits for the worker to exit before removing the files, so Windows native handles are released; a 250 ms parent-liveness check stops the worker and cleans up if the reset CLI dies. If the copy owner is killed too, the next valid reset removes only marked physical directories with matching identities, both recorded PIDs provably dead, and only the known copy/sidecar/ownership files. The ownership marker is removed last, so interrupted cleanup remains identifiable. Live or uncertain owners, PID reuse, links, malformed/unmarked directories and unexpected contents are preserved; the prefix alone never authorizes deletion. Cleanup uses the same identity checks. If a stale copy cannot be removed, a one-line refusal names that directory and tells the operator to close the program holding its files, check permissions and run the reset again. The refusal says that nothing in the data directory was changed; cleanup may already have removed some payloads from its own stale copy, retaining its ownership marker until the remaining payloads are gone. This temp housekeeping also runs on a dry run; the data directory stays unchanged.
- A refused or cancelled reset changes no byte of the data directory. A reset that fails part of the way reports exactly which items it removed, which it removed partly (with counts) and which it did not, releases the lock, and says to run it again before starting GraphGoblin.
- Browser device drafts are not reset by the CLI; the editor's discard covers them.

**Boundary with schema migrations.** Drizzle SQL migrations remain ordinary schema evolution _within_ the current format: a later migration (0014 onwards) is applied to existing current-format stores at startup and must keep their data. A change of definition or store format is different: it moves `FORMAT_BASELINES` and `CURRENT_DEFINITION_FORMAT` together, older stores are refused, and the owner resets (or keeps running the build that wrote them). No conversion code, frozen contract or upgrade tool is written for it. A current-format definition whose only departure from the contract is a retired exit `event` destination does not make the store unsupported: that is the per-loop `LOOP_UPGRADE_REQUIRED` condition of [ADR-0044](ADR-0044-awaited-subloops.md), and the store guard lets such a store start unchanged.

**Retired (removed by #188).** The offline `graphgoblin-upgrade` tool and its resolution generator, `inspectDatabaseUpgrade`/`applyDatabaseUpgrade`, the bounded upgrade scan, the frozen `V2*`/`V3*` contracts and their capture scripts, the v1-to-v4 domain converters, API import conversion, web device-draft conversion and their tests and fixtures (#188).

## Consequences

Old exports and device drafts can no longer be brought forward by this build; an operator keeps the build that wrote them or re-creates the loop. Stored data that the owner wants across a future format change is exported and re-created by hand, or kept on the old build. The store guard, fresh initialization, corruption checks, the migration ledger checks, `check:migrations`, timer and identity durability are unchanged. `docs/guide/08-offline-upgrade.md` is now the reset and fresh-start guide; its file name is kept so historical links in ADR-0039, the CHANGELOG and QA records still resolve to a page explaining what replaced the upgrade path.
