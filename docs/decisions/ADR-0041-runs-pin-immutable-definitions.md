# ADR-0041 - Runs pin an immutable definition, drafts included

Date: 2026-10-18. Status: Accepted. Supersedes the draft-run gap in [ADR-0008](ADR-0008-runs-pin-versions.md); the rest of ADR-0008 stands.

## Context

ADR-0008 pinned a run to the loop version it started on, but a draft is one mutable row that the editor saves in place. A test run of a draft referenced that row, so every executor start (a wake after a wait, a resume, crash recovery) read the edited draft: on current code a draft run started with a mutation that set `old`, edited to `new` while it waited, finished with `new`, before and after a real SQLite restart. The run inspector loaded the same row and showed the edited definition for the old run. Model and effort defaults inherited from Settings were also read at every executor start, so a waiting published run changed models when Settings changed.

The owner's settled rule (#278, "Definition lifetime" and "Model selections"): every execution, draft runs included, keeps its original immutable authored definition for its whole life, through waits, resume, replay forks and restart. Only new executions use later edits. Active children keep their own pins. Later model edits or model-retirement upgrades reach new executions only.

## Decision

A run's `versionId` names an immutable definition record, and `run.pinned` describes it. The engine reads the definition only through that id and the inherited defaults only from the pin, at every step, wake, resume, replay fork and recovery.

- **Published starts** pin the published version, as before. Published versions never change.
- **Draft starts** freeze a snapshot of the draft: a `loop_versions` row with status `snapshot`, a new id, the draft's number and exactly the definition the start read and validated. The admission port commits it in the same transaction as the run, its `run.queued` event and its initial thread, so a run never references a missing snapshot and a failed start leaves none behind. A snapshot is never published, never "latest", never the loop's draft, not listed in the version history, and cannot be started directly (`VERSION_NOT_PUBLISHED`). `GET /loops/{id}/versions/{versionId}` still returns it, so the inspector shows what the run ran.
- **Immutability is enforced by storage.** Draft saves and publishes only ever touch `draft` rows. Two SQLite triggers refuse any update of a snapshot row (`LOOP_VERSION_SNAPSHOT_IMMUTABLE`) and the deletion of a snapshot that a run still pins (`LOOP_VERSION_SNAPSHOT_PINNED`). A snapshot is run history: run deletion removes the snapshots no remaining run pins, and loop deletion (ADR-0033) removes everything together.
- **The pin is visible.** `RunRecord.pinned` and the run's first event (`run.queued`, which also carries `versionId`) hold `source` (`published` or `draft`), the version number, the loop name in the pinned definition, a readable `label` (`Review v3`, `Review draft v4`) and the pinned defaults. They never change during the run, and renaming the loop later does not change them.
- **Inherited defaults are pinned.** At a top-level start the engine reads the owner's Settings defaults and the process defaults (`GG_DEFAULTS`) once and stores both in `pinned.defaults`; model resolution for every node uses node, loop (in the pinned definition), pinned owner, then pinned process defaults. Both levels are pinned because each silently changes which model or effort an inheriting node uses. Harness selection needs no extra pin: it lives on inference nodes (ADR-0019) inside the pinned definition. The model catalog is not pinned: it says whether a model is available, not which one a node selects, so a disabled or removed model fails the node explicitly (resumable `EVALUATION_UNAVAILABLE`) and is never substituted.
- **Classifier bindings are pinned.** A classifier decision names a catalog id; the catalog entry behind it (provider, provider model, endpoint, primitives, secret name) is owner-editable configuration that decides what the decision calls. At start the engine binds every classifier id the pinned definition uses to its entry as it is then and stores the bindings in `pinned.classifiers`; every execution, wake, recovery and replay calls the pinned binding. Whether the entry still exists, its enabled switch and the secret's value stay live: a removed or disabled classifier fails the decision explicitly (resumable `EVALUATION_UNAVAILABLE`) and nothing is substituted. An id with no entry at start has no binding; its decision fails `EVALUATION_UNAVAILABLE` without consulting the catalog and is not resumable, because restoring the entry reaches new runs only. The secret name is pinned with the endpoint it was validated with, so a bearer token never goes to an endpoint it was not configured for.
- **Children.** Parent-authored child target selection stays as ADR-0008 and docs/05 describe: `latest` references resolve when the parent is created (`subloopVersions`) and every child, on any later visit, uses that selection. Each child gets its own pin to the selected published version, inherits the parent's pinned defaults and keeps the parent's classifier binding for any classifier id they share (other ids bind at the child's start), so one tree of runs sees one set of defaults and calls one configuration per classifier. Editing or publishing the child loop while a child runs does not change it. No transitive snapshot of child definitions is taken: published versions are already immutable.
- **Replay forks** keep the source's `versionId` and `pinned`, snapshot included.
- **New runs** select the newer definition: a new published start uses the latest published version and current defaults; a new draft start freezes the current draft.

## Consequences

- `RunRecord.pinned` and `run.queued.versionId`/`pinned` are required contract fields. Migration 0014 adds `runs.pinned` and the `runs_version_idx` index, freezes the current draft for every run that still referenced a draft row (the snapshot takes the run's id), points those runs, their initial and saved threads and their first events at it, pins every run, `run.queued` event and saved webhook admission intent with the owner's current Settings defaults, no process defaults (`GG_DEFAULTS` is not stored) and the current catalog entries of the classifiers its definition uses, and installs the two snapshot triggers. A draft run's history from before the migration is therefore pinned to the draft as it was at upgrade time. The migration rewrites stored history only where it is valid JSON: a malformed thread, event payload or saved intent is left byte for byte as it was, for the unreadable-history diagnostics to report, and one damaged run cannot stop the upgrade of the others.
- A later offline cutover that rewrites definitions must delete or convert snapshot rows deliberately: the update trigger refuses silent rewrites of them.
- #255 can show the pinned label and identity; #262's retirement upgrades reach new runs only by construction.
