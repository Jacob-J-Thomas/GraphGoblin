# ADR-0068 — Chat reliability, bounded voice drafts and local pairing

Date: 2026-11-08. Status: Accepted for owner-authorized QA repair implementation; verification remains outstanding. Amends ADR-0065/0066 at the explicit boundaries below.

## Context

Native Chat QA reproduced structured-envelope failures, silent Ollama context loss, idle readiness recovery and pairing lifecycle defects. Audio was configurable but unfinished. The owner requests microphone recording with Stop retaining a draft, subsequent recording appended, and explicit Send/Enter submitting once; local transcription when capable, otherwise a guided cloud connection; same-machine and ordinary home-Wi-Fi pairing. Existing custom workflows, device clones and history must survive. The feature PR stays unmerged for local owner QA of the reviewed commit.

## Decisions

### Text and model boundaries

The standard chat seed captures plain model text through an explicit inference text-capture mode, then deterministically constructs the exact chat response envelope in its ordinary workflow. JSON-looking prose remains text. The response-variable, success-exit and read-projection validators stay strict. Arbitrary structured workflows retain their structured validation; no permissive extraction or broad automatic repair/replay is introduced.

The additive `output.capture` field is optional in the current definition contract. Omission and explicit `auto` both retain the previous JSON-or-text execution behavior; new standard Chat seeds explicitly select `text`. Do not materialize a schema default while reading or serving existing definitions: the response encoder must accept the omitted optional field, and stored definitions, historical versions, draft hashes and compare-and-set tokens remain unchanged. Invalid values and unsupported definition formats still refuse. Loading an editor must not create a dirty draft merely to add this field.

Every Ollama dispatch budgets the actual rendered prompt, server wrapper overhead and output reserve against an explicit selected context window. Advertised maximum context is not proof of effective runtime context. Conservative estimates require a verified tokenizer/renderer profile and live qualification; unsupported profiles fail visibly. Only recognized standard Chat prompts may re-render with oldest complete history pairs omitted, retaining the newest pairs that fit. Current input and authored instructions are never silently truncated. Omission is recorded without rewriting immutable initial history. Arbitrary prompts fail clearly when they do not fit. An editable finite interactive deadline retains native uncertainty/cancellation semantics.

Context support is a catalog capability, not an invisible dispatch restriction. Discovery, selected-node readiness/default diagnostics and dispatch share the same profile classifier. Models with unqualified tokenizer/renderer/runtime profiles remain listed with preserved Enabled preferences and saved selections, but availability is unsupported with an actionable reason. Supported effort choices intersect the context profile's qualified efforts; an authored unsupported effort is refused, never silently changed. The initial profile covers the observed Qwen3.5 byte tokenizer, template, absent renderer, none effort and Ollama 0.32.15. This narrows runnable model support and must be stated in Settings and release notes; it is not a claim that all discovered models are verified. Exact runtime version is a temporary evidence boundary for the fixed wrapper reserve, not a permanent product requirement. Other profiles/version ranges require independent renderer/tokenizer evidence and live qualification.

Each complete discovery scan observes runtime version once. Transient detail caches are keyed by connection revision, model digest, runtime version and context-policy version. A nullable persisted context-profile marker distinguishes qualified catalog observations from legacy or obsolete policy observations. Null or incompatible markers project unverified/unsupported without deleting models, Enabled preferences, selections or observation timestamps. A complete successful scan restores supported availability. Existing five-minute, manual and connection-change refresh behavior remains; failed refreshes never promote unverified rows. Selected-node admission and final dispatch read runtime version afresh, coalescing only concurrent checks; stale cached version evidence cannot authorize a changed server. Final dispatch reclassifies live model context metadata. This proves the supported context profile, not immutable model weights: catalog digest is discovery/cache provenance and may lag a replaced tag. An additional tags read would not atomically pin that tag through inference. These checks are read-only, never inference probes or stored loop rewrites.

### Voice drafts and media

Remove the attachment control. Browser AudioWorklet capture yields bounded PCM; verified native resampling handles supported non-16-kHz capture. One final WAV contains ordered frames with one header: mono, 16 kHz, signed 16-bit PCM. No compressed-container concatenation or ffmpeg dependency. Limits apply to the complete draft: 120 seconds, 10 MiB, 16 segments. Stop/cap pauses without sending. Send/eligible Enter freezes and finalizes once. Short utterances are not silently dropped.

Allow at most 32 unacknowledged transfers of 4,096 Float32 frames, a 512-KiB queue plus separately budgeted worklet/current-delivery buffers. This tolerates short main-thread stalls without removing bounded overflow failure or exact final sequence/frame acknowledgement. Create and resume the AudioContext synchronously from the recording gesture before awaiting permission/module work; every setup cancellation, timeout and late result must clean up its owned context/tracks without resurrecting recording. Do not claim an interrupted segment was finalized without its final acknowledgement.

At most eight dirty conversation voice drafts remain in memory; refuse a ninth rather than evict. Bound aggregate and transient memory, with one active finalization. Unsent audio survives Stop/rerender/conversation switching but not guaranteed full reload/termination. Disclose that limitation. Do not activate an update while an old-generation client has dirty voice or unresolved admission, or automatically reload any client with such state. Browser termination remains outside application guarantees.

Live PWA activation requires a compatible guard-capable active worker and shared registration-scope Web Locks acquired before pages enable dirty actions. The waiting worker queues its own exclusive lock before obtaining exact client safety acknowledgements and holds it through completed activation. Unknown/legacy worker generations, unresponsive clients or missing locking support defer activation until app windows close. Existing-client acknowledgements alone cannot protect a newly opened legacy client. Generic skip-waiting messages cannot bypass the guard. After activation, prepared old clients remain frozen until their locally safe reload; a new-generation client starting a draft does not invalidate another prepared clean client's delayed reload because that reload cannot affect the new client's state.

The gateway validates WAV bytes, frame/length/rate/channel/format bounds and sample-derived duration. Public upload operation identity is durable and audience-scoped. Unknown acknowledgement recovers through GET; no background upload or request replay. Native admission identity and existing consumed-audio retention remain authoritative. Existing custom normalizers retain their supported media path; the guided preset accepts canonical WAV only.

Optional audio caption is part of the public request and canonical engine input, request hash and admission equality checks. The normalizer joins caption, a blank line and transcript, then validates exact `{text}` against the existing 16,000-character bound. Empty/invalid transcription fails; content is not repaired or trimmed. One combined transcript is supported, not per-segment alignment.

### Guided transcription remains an ordinary workflow

Owner-only voice configuration/probe/install/preview/stage routes are separated from publication. Saving credentials or passing a probe does not publish or update existing device clones. Preview is pure. After explicit review, Stage transactionally compares expected draft/configuration/preview hashes, recomputes the precise protected normalizer edit and writes only the draft; it accepts no arbitrary replacement definition. Stale state refuses without writing. Owners publish selected gateway/device drafts through the existing editor, with dirty editor handoff protected.

Guided voice preview must establish that the response prompt consumes normalized text. Recognized current canonical text prompts receive the domain's precise audio rewrite. An authored prompt may retain its custom content when its explicit normalized-text reference is recognized and it does not directly read the absent raw audio text field; other prompts require manual editor review. Do not silently support or rewrite legacy prompt forms. Existing pre-repair loops receive their reviewed text-capture/envelope repair before voice publication; copied-store acceptance verifies the rendered audio prompt contains the transcript.

A portable built-in Script helper named `graphgoblin-voice-normalize` is resolved at composition through ScriptPort. It preserves native Script dispatch/cancellation/recovery and canonical normalization checks; no new execution queue or peripheral transcription API is added. Other Script commands delegate unchanged. Its protected thread/run resolves authoritative owner and audio metadata; it never trusts public owner or path fields.

The helper propagates sanitized native process disposition, termination-unconfirmed, timeout and overflow facts. It must not convert uncertain execution into a clean completed failure. Termination uncertainty takes precedence over an outer cancellation; an unclassified runner rejection after dispatch remains outcome-uncertain. Raw child output is withheld from these failure results. The engine retains its existing non-resumable termination safety behavior, and local capability is quarantined when execution remains uncertain.

Text pass-through happens before transcriber/secret requirements. Local invokes verified whisper-cli directly on canonical WAV with bounded process output and no shell. The first cloud adapter uses fixed OpenAI file transcription, native HTTP and the current `gpt-transcribe` model. Credential names resolve only on the selected cloud path through existing owner-scoped encrypted secret storage. No inference authentication is implicitly reused; no credential is embedded in a loop, browser, log or argument.

Auto mode prefers qualified available local runtime; otherwise preauthorized configured cloud. Select and record the route before dispatch. No provider switch after dispatch, and no ambiguous cloud-request retry. Ordinary readiness performs no transcription/inference. Distinguish graph configuration, runtime qualification and observed availability; custom normalizers cannot claim a health check solely from graph shape.

Local suitability requires unchanged qualified runtime/model identity and a recent matching representative speech probe that succeeds within the explicit 30-second probe threshold. Report this as observed performance under current gateway load, not a guarantee for every maximum-length recording. OS-reported free/unused memory is telemetry, not portable available headroom and not a hard suitability/routing threshold. Current-machine release evidence includes real transcription while the usual local inference model runs. Actual local timeout/resource failure invalidates successful readiness until an explicit retest; finite dispatch deadlines and no post-dispatch provider switch remain.

Probe evidence and quarantine update atomically per owner/route/configuration fingerprint. A failure generation prevents a probe started before a later failure from clearing that failure on completion. Only a fresh explicit successful retest against the unchanged generation can restore suitability; provider work never runs inside the database transaction.

A guided model installer supports allowlisted immutable model assets only when a verified local runtime exists. Pin model source revision, bytes/hash and licence; stream with bounded progress into a private owned directory and atomically install only verified bytes. Missing/unqualified runtimes on unsupported platforms receive a truthful cloud setup path, not shell instructions or a fictitious installer. Adding a package-manager installer requires separately verified package/version/dependency provenance. Source MIT alone does not qualify an installed binary or model. No ffmpeg exception is inferred.

Runtime qualification is a private server-owned attestation bound to canonical executable identity, dependency hashes, reviewed provenance and the repository's exact licence policy. Loader-scanned backend directories require an exact bounded inventory so an added unreviewed library invalidates qualification even when previously recorded hashes match. Public setup, probes and generic settings cannot create or replace this attestation. Missing or changed evidence fails closed; runtime execution removes inherited loader environment overrides.

### Same-machine enrollment and LAN

Configured GG_PUBLIC_URL remains authoritative; invalid explicit configuration refuses. When absent, enrollment may use a configured strict loopback hostname/address only when the actual listener is also loopback, using its actual bound port. Never derive authority from request/forwarded headers. Required-key mode and wildcard-owner creation remain mandatory; setup never silently changes auth/listening. The UI labels fallback same-machine only.

Nonloopback pairing still requires explicit canonical HTTPS. The peripheral navigates to its serving origin before claiming; no cross-origin credential forwarding. Device allowlists, explicit claim, single-use expiry, scope isolation, revocation and separate PWA credentials remain. Initial load and same-document fragments are captured/scrubbed without automatic claim.

Both actual same-machine browser-context pairing/chat/revoke and separate LAN HTTPS/phone installation/microphone tests are release requirements. Neither substitutes for the other.

## Storage, compatibility and delivery

Use ordinary additive migrations for new operation metadata. Do not rewrite stored loop definitions through migrations, introduce old-schema compatibility parsers or reset the store. The changed canonical audio input requires precise reviewed draft updates for affected saved loops; preserve custom graph content and publish deliberately. Used audio/reference cleanup and request tombstones continue to protect recovery and prevent duplicate admission.

Generic settings writes and deletes reserve the entire voice namespace, and generic settings responses exclude internal operation, route and probe metadata. Per-run route metadata is deleted atomically with its run. Setup operation identities remain owner-scoped and durable; retired result payloads never make an old identity executable again. Bound identities to 8,192 per owner, refusing new identities at capacity while preserving duplicate/status recovery. Compact terminal payloads after 30 days in bounded batches when implemented; retaining bounded small terminal records is acceptable for this release. These setup limits do not change audio-upload or native Chat admission tombstones.

Hold the PR unmerged with auto-merge disabled. Required gates and independent cross-family review approve an immutable commit before local deployment. Verify served frontend/service-worker and backend identity. Back up the complete stopped store and configuration and preserve old build for rollback. Changes after review/owner QA invalidate affected evidence. Only the owner's later explicit approval permits merge.
