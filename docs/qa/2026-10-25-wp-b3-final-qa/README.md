## Defects

### D1 (Low): a Windows AF_UNIX socket file anywhere the reset lists makes every reset refuse with a raw `EACCES`

**Reproduction** (`c10-review-threads.mjs`, scenarios b4 and b5; `af-unix-socket.cs` creates the socket by binding a Winsock `AF_UNIX` socket to a path; it runs from the target folder because `sockaddr_un` holds 108 bytes):

1. Seed a format-3 store in `%TEMP%\gg-qa-b3-int-c10-…\data` with run workspace `workspaces\01JQAB3INTRUNAAAAAAAAAAAAA`.
2. Create an AF_UNIX socket file `tool.sock` in that run workspace.
3. Run `node apps/api/dist/main.js --reset`, then `--reset --yes --data-dir <data>`.
4. Remove it with `fs.unlinkSync`, create `agent.sock` at the data-directory root, and repeat.
5. Separately, configure `GG_DB_URL` to a socket file named `graphgoblin.db`.

**Expected:** ADR-0042 and `apps/api/src/reset/tree.ts` say a socket inside a removed directory is unlinked like any other non-directory entry. A root entry that is not part of the store is listed under Keeps. A socket configured as the database is refused as `a special file, not a database file`.

**Actual:** In all three placements, dry run and confirmed, the command exits 1 with:

```text
reset refused: EACCES: permission denied, lstat '…\data\workspaces\01JQAB3INTRUNAAAAAAAAAAAAA\tool.sock'
Nothing was changed.
```

Nothing changes (tree identical), but no reset can proceed until the operator finds and unlinks the socket by hand, and the message gives no guidance. Node's `lstat` on Windows fails with `EACCES` for this reparse-point type (tag `0x80000023`). `identityOf` and `statEntry` in `tree.ts` rethrow everything except `ENOENT` and `ENOTDIR`. `fs.rmSync` also fails; `fs.unlinkSync` removes the socket.

**Severity:** Low. Windows only, fails safe, and needs a socket file in the data directory, which is plausible for tools run in a temporary run workspace.

### D2 (Low): a reset killed while it reads the store leaves a full copy of the database in the temp directory

**Reproduction** (`c11-extras.mjs`, E1 and E3):

1. Seed a format-3 store.
2. Run `node apps/api/dist/main.js --reset`, and terminate the process (`taskkill /F /PID <pid>`, as Task Manager or closing the window does) as soon as `%TEMP%\gg-reset-store-*` appears.
3. Wait 15 s.
4. Repeat with `--reset --yes --data-dir <data>`, terminating it as soon as `graphgoblin.lock` appears (the plan under the lock reads the store again).

**Expected:** `readStoreFacts` reads a private, temporary copy and removes it (`apps/api/src/reset/store-facts.ts`). The guide says the format marker and run IDs "are read from a temporary copy".

**Actual:** Both times `%TEMP%\gg-reset-store-<random>\store.db` (SHA-256 equal to the original database) and `store.db-wal` remain. The data directory itself is unchanged. The copy is removed only in the parent's `finally`, which does not run when the process is terminated, and the orphaned reader child does not remove it. Ctrl+C was not exercised separately; Node's default SIGINT exit does not run `finally` either.

**Severity:** Low. The data directory is untouched, but a full copy of the store (loops, run history, encrypted secrets) stays in the user's temp directory, and a large store also leaks its size in disk space. The dry run takes 5 to 12 s on this machine, so an interrupted dry run is a realistic way to hit this.

## Residual race (documented limitation, not counted as a defect)

ADR-0042 and `docs/10-testing-and-quality.md` say the identity checks narrow, but cannot eliminate, a race with an external process between the last check and `unlink`/`rmdir`. Two adversaries ran against the public CLI, in separate processes, with 12 trials each:

- **Directory swap** (`race-flipper.mjs`, `c05r-residual-race.log.txt`): repeatedly renames a planned run workspace away and a prepared junction to same-named decoy files into its place, then back. Result: 0 of 12 trials won. Every trial was detected at the first, third or fourth file of the attacked workspace (10, 1 and 1 trials), as `ancestor … is now a link` (2) or `was moved or removed` (10); 0 decoys were deleted.
- **Atomic file replacement** (`race-replacer.mjs`, `c05r2-residual-race-file.log.txt`): when file k-1 disappears, waits a random delay and renames a different file over file k in one operation. Result: in trial 3 the reset deleted two replacement files created after their identity checks (`f00001.txt` after 123 µs and `f00002.txt` after 141 µs). The third attempt landed after removal, so the run ended `ENOTEMPTY` with exit 1. In the other 11 trials the replacement landed after the unlink and survived, and the reset stopped with `ENOTEMPTY`. In this setup no trial was stopped by the identity check itself.

The documented race is therefore real and reachable through the CLI. Had the adversary stopped after its wins, the reset would have completed with exit 0 and the replacements would be gone without a report. Every fixed-point change in check 5 was detected.

  - the name while the reserved directory exists;
  - an absent `artifacts` or `Workspaces`;
  - the 8.3 names `ARTIFA~1` and `WORKSP~1`.

  Related cases are refused with their own messages:
  - `artifacts.` (trailing dot);
  - `graphgoblin.lock` and `graphgoblin.lock.reclaim`;
  - a database inside `workspaces/`;
  - a fully 8.3-spelled path (as outside the data directory).

- **(b) Non-regular database path:** resolved for every non-regular entry this host can create. The dry run and the confirmed reset refuse each one in 2 to 11 s, never block, and remove nothing:
  - a directory: `graphgoblin.db is a directory, not a database file; a reset removes only regular database files`;
  - a junction: `… is a link, not a database file`;
  - a `-shm` junction and a `-journal` directory;
  - a stream `graphgoblin.db:x`: `names a stream of a file`;
  - a live named pipe `\\.\pipe\…` in two URL spellings: refused as outside the data directory, and the pipe server saw 0 connections;
  - an AF_UNIX socket file: refused, but with the raw `EACCES` message of D1.

## Observations (not defects)

- **O1:** Startup refusal changes only `graphgoblin.db-shm`, and `--preflight` changes only its `mtime`, as the guide states.
- **O2:** When the root is swapped mid-removal (check 5b), the report names the first path whose recheck failed (`ancestor workspaces was moved or removed`), not `data-directory root`, because the swap landed between that entry's root check and its ancestor check. The path named is a real changed path on the route.
- **O3:** A current-format store whose reset stopped after removing workspaces and artifacts can still be started (E8). Artifact downloads then answer 404 `ARTIFACT_NOT_FOUND`. The reset output and the guide tell the operator not to start before rerunning, but nothing enforces it.
- **O4:** A hard link named `graphgoblin.db` to a file outside the data directory is a regular file. The reset removes the name, and the outside link keeps its bytes.
- **O5:** `GG_DB_URL` naming a DOS device (`<data>/NUL`) is planned as `no database file`, so a confirmed reset with that misconfiguration would remove `artifacts/` and keep everything else.
