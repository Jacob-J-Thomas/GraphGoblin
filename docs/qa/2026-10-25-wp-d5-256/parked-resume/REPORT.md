## 2. Per bolt

For #256's reviewed-observation Resume contract, paused Resume now takes the existing per-run lock, rechecks paused status and the reviewed durable tail, and admits `run.resumed` through the event compare-and-set **before** projecting waiting/running status. A losing append receives `RECOVERY_STALE`, leaves the row paused and records no Resume. Both parked and executing paused branches use this ordering; failed Resume retains its existing event-first path.

The projection also compares the fresh durable tail. A failure appended after admission cannot be overwritten by a stale row update. Timer re-arming, child reconciliation and executor enqueue occur after the journal and status writes. A committed intent with interrupted acknowledgement/projection is recovered at startup without another Resume event. A later deliberate pause supersedes that intent. While an admitted intent still has a paused projection, recovery reads refuse further actions as `RECOVERY_STALE`.

Evidence: [new public-port cases](../../../../packages/engine/src/parked-resume.test.ts), [engine recovery cases](engine-focused.log.txt), and the real-SQLite HTTP case in [API recovery eligibility](../../../../apps/api/src/recovery-eligibility.test.ts). The HTTP case returns 409 / `RECOVERY_STALE`, preserving the exact wait and paused row with no Resume. The positive case keeps the same run ID, wait ID and wait record, then consumes its input once. Timer/child cases preserve the original deadline/child and wake once. Bounded storage facts distinguish an admitted Resume from a later pause without scanning unrelated history: [storage cases](snapshot-focused.log.txt).

Include the latest pause in recovery facts to distinguish a pending Resume projection from a later intentional pause. This adds one indexed MAX seek with the existing at-most-three decoded payload bound and the same N+2 statement count for N definition nodes. No new migration, retry loop, timeout, debounce or product eligibility rule. Timer deadlines, wait identities, child identities and script consent rules are preserved. No owner product judgement is needed.
