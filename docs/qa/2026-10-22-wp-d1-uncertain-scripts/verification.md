## 7. Decisions and parameters

- Check dispatch provenance before script preparation on every handler entry. This covers recovery without edits to shared `run-manager.ts`.
- Visit identity is the first `node.started` sequence since this node last finished. A failure disposes an attempt while retaining the visit; only explicit Resume leaves a failed run. Every dispatch has a fresh ULID. A resumed dispatch interrupted again becomes uncertain again.
- A marker recorded before an actual spawn is conservatively uncertain if its disposition is lost. An in-memory refusal or observed process exit cannot be reconstructed as durable evidence after a crash. A durable start failure follows ordinary explicit Resume rules.
- Cancel in the recovery dialog cancels the recovery choice and preserves the failed outcome. Replay uses the existing fork-at-node API; both Replay and Resume may repeat an effect. No exactly-once claim is made.
- New native/browser stores use `%TEMP%\gg-wp-d1-*` and ports 5910–5919. The marker checks release every 25 ms and has a bounded 60-second test deadline (10 minutes for manual QA). No provider turn is used. The marker records its PID to allow cleanup to distinguish live processes from stale files after a hard kill.
