## 7. Decisions and parameters

**Fully finalized** means the current lifecycle is terminal, `finalizedAt` acknowledges the existing finalizer, and no pending webhook is reported. SSE additionally confirms that all durable rows through the current tail have been delivered under the existing single writer. Polling waits use terminal status plus the same marker/pending veto. A run is not complete merely because `run.finished` or EOF was observed.

The marker already exists in SQLite and is set after selected-channel receipt reconciliation, final webhook journal persistence and terminal cleanup/parent notification. Deriving a second aggregate from return.* alone would duplicate channel-selection, retired Event, recovery and cleanup rules and could complete too early. This is an exposed acknowledgement, not a second stored state. A failed-run resume clears it before run.resumed; pending snapshots veto a marker read that races resume. Public repository fakes now model that existing mark/clear behavior.

| State                             | API read                                                   | SSE/client subscription                         | Client/MCP wait                                                           | Inspector                                                                  |
| --------------------------------- | ---------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Execution active                  | current status, no marker                                  | live/reconnecting                               | unfinished                                                                | current execution                                                          |
| Execution ended, delivery pending | terminal status, no marker, pending delivery               | stays open; EOF retries                         | unfinished at deadline, terminal execution and pending snapshots retained | execution outcome + finalization pending + delivery pending; timeline live |
| Delivery finally delivered        | terminal status, marker, delivered snapshot                | stream.complete after durable tail              | finished:true, delivered                                                  | fully finalized + delivered; timeline complete                             |
| Delivery finally failed           | terminal status, marker, failed snapshot/error/uncertainty | stream.complete after durable tail              | finished:true, failed delivery evidence                                   | fully finalized + failed; execution outcome preserved                      |
| No webhook return                 | terminal status and ordinary finalizer marker              | settles immediately after ordinary finalization | finished:true                                                             | ordinary completion                                                        |

The required SSE finalization callback prevents execution-only completion by omitted dependency. One 250 ms timer per quiet pending stream observes the eventless existing marker; it bounds observation latency/store reads and does not change delivery timeouts or retries. It is cleared on close. The existing 1 s run-snapshot poll now also covers terminal-but-unfinalized reads; no new independent timer is added to the inspector. New remote history always opens SSE, even if execution ended between polls, because JSON history cannot authorize stream completion.

Tests use only public constructors, repositories, HTTP/tool/client/component interfaces and controlled receiver faults. No private access, monkey-patching production, test-only exports, live provider claims or backward-compatibility paths.
