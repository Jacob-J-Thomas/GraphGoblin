## Verdict by review focus

**Ownership proof before any removal.** `removeOwnRecord` removes a failed main record only after a
non-following `lstat` at the configured path matches either the handle identity read before the
single close (partial record: `dev`/`ino`/`birthtimeNs`, regular file, `ino != 0`) or the exact
random-token bytes (complete record). Absent → settled; non-file or different identity/bytes →
treated as foreign, kept untouched, reservation dropped; identity unavailable, lookup failure or
unlink failure → file and `heldPaths` reservation kept and reported as `lock-record` retained.
One unlink at most, no reattempt. Guard removal: own release calls the classifier only when this
release read its exact record and itself unlinked its marker (`removed && own`), with an identity
captured by the lstat → sole-own-marker listing → lstat sandwich, consistent with the staged
identity. Absent → success; unchanged, empty, unknown or unverifiable → original
`recovery-directory-remove` failure and the existing rollback. No path removes a file or guard
without proof. Confirmed natively in QA (A1–A8, D1–D5).

**Leases kept on failed closes.** `settleFailedSetup` sets `closed = false` on a failed read-only
close (whether primary or secondary) or a failed mutable close and then returns without calling
either `release()`, listing the database lease (when acquired) and the directory lease as retained.
Otherwise the database lease and then the directory lease are released once each, with `.catch`
so the first failure cannot suppress the second. Confirmed natively (B1, B1b: no lock unlink
attempted, both lock files left; B4/B5: both releases attempted in order).

**Primary error preserved; cleanup errors never printed raw.** `withStartupCleanup` returns the
exact primary when nothing needs reporting and otherwise builds one `StartupCleanupError` with the
primary as `primary`, `errors[0]` and `cause`, ordered `{operation, code, error}` steps with closed
labels and vetted codes, and retained ownership; a tagged primary is flattened in causal order.
`shellFailureOutput` prints the primary's usual rendering (known refusals: their explanation;
unknown: `util.inspect(primary)`) plus one `escapeDisplayControls`-escaped detail line; it never
prints secondary messages. `startupFailureCause` unwraps only `StartupCleanupError`. Probe failures
keep their raw cause non-enumerable, so `inspect` shows the label and code only (when within the
default inspect depth; see R2). Confirmed natively, including a data directory containing U+2028
(escaped as `\u2028` in the detail line).

**Windows guard identity/successor check vs #582 criteria.** The own-release path reuses
`hasLiveRecoverySuccessor` unchanged in its decisions: different physical directory, sole regular
single-link UUID marker not own token/name, descriptor/lstat match, record token, foreign live PID,
valid creation identity equal to the native lookup, liveness after lookup, final listing, marker
identity/times recheck and final directory identity. The only helper delta is the optional
`report` callback (failed lstat, liveness, identity lookup, inspection exception) and passing the
`ObservedGuard` shape. Win32-only gating is kept (`removeEmptyRecovery` and capture). Natively, D1
reached positive verification against a real live helper process's CIM creation time and kept the
main lock; D3 (recorded creation identity off by one) took the rollback with no probe entry.

**No behaviour change on the verified-successor `held(path)` path (FUP091).** Acquisition passes
`successor: 'held'` and throws `held(path)` exactly when verified; probe entries are discarded on
that path. Unit test pins no `code`/`operation`/`cause`, one shell line and `store-held`; native D4
printed exactly the ordinary one-line refusal and D4m recorded `store-held`.

**New error type and reporting shape.** `StartupCleanupError extends AggregateError` in a leaf
module with no API imports (no cycles). No change to the managed envelope, lock formats, reset
manifest or writer protocol. The pre-open generic `cleanupFailure` paths and the post-acquisition
rollback reporting are unchanged, as the contract requires.

**Docs / ADR-0091 accuracy.** docs/11, CHANGELOG and ADR-0091 match the code on every point
checked: one close, proof rules, non-atomic check/unlink wording, retained leases "until the process
exits", tagged-error shape, shell/managed reporting, win32-only capture and classification, closed
probe labels, unchanged verified acquisition refusal, explicitly excluded lifecycle paths, and the
evidence limit (controlled faults do not establish #471's cause or frequency). FUP-084's changelog
sentence (eighth unsettled read, final lost stale-marker unlink, read-only status guard) is present
in the #581 entry. ADR index entry added; ADR-0090 is absent from this base (number chosen by the
held contract).
