**Readback from `TOTALS-RESULT.json`.** Totals are shown as [contenders, acquired, refused, other]. Every artifact had 1 totals row and 7 receipts. The receipt-field SHA was the same in all of them: `0b89fa18…5c0a`.

All artifacts uploaded the same three files. The readback is sorted by totals, so I matched each variant to its label by its values.

- **Why changing one field alone can't be tested.** The recorder requires acquired + refused + other = contenders (1 + 4 + 0 = 5). Changing any one field breaks that sum: 6 vs 5, 6 vs 5, 4 vs 5 and 6 vs 5. The recorder would then reject the row, and the run would stop at `records-rejected` before the per-count checks in `successfulContention` ever ran. That is the same masking #539 reports. The test asserts that `validateRecord` returns false for each single-field change.
- **Why the variants change two fields.** Each variant moves its named field plus one other so the sum still holds (6=1+5+0, 5=2+3+0, 5=1+3+1, 5=0+4+1). Those rows are accepted (asserted true), and the only remaining refusal is the comparison against the unchanged receipts. The unchanged receipts are confirmed by the matching SHA and by a `deepEqual` assertion.
- **What each variant proves.**
  - The contenders variant isolates the receipt-count check (5 results and PIDs vs 6 contenders).
  - Each of the other three fails two of the checks acquired = 1, refused = contenders − 1 and other = 0.
  - Under the sum rule, any two of those checks imply the third. So the test shows a refusal for each wrong count, but it can't show that each individual check is needed.
- **Assertion-only facts** (the readback doesn't show these):
  - Exit code is 1 for `incomplete` and 0 for `native-failed`.
  - Observation bytes were byte-identical before and after finalizing.
  - Running `summarize` over the control plus an appended second row gives contention `[2,3]` and includes `contention-trials` in missing.
- **Existing assertions kept.** The test-file changes only add code. The existing duplicate-row and failed-artifact retention tests (including "structured cleanup failures remain readable and downloadable…") are unchanged and passed within the 43.
