# Exit evidence inventory after the decision-gate redesign (#129)

Bolt #129 (B58, with consolidated report #258), intent I07 #289, unit of work #310. The owner decided that loopback-node functionality and useful evidence must not be dropped unless the decision/exit design replaces them. Choice list-level help, unique-option constraints and criterion/output explanations stay where they still apply. Suppressed outputs must be understandable, and quiet exits remain valid. The protected #97/#98/#164 contracts are not reopened. This work changes presentation and evidence only, inside [ADR-0036](../decisions/ADR-0036-decision-gates-terminal-exits.md).

Sources for "before": [ADR-0010](../decisions/ADR-0010-exit-return-channels.md), [ADR-0026](../decisions/ADR-0026-exit-primitives-and-format-three.md), and the following files at `c379f80`:

- the guide (`docs/guide/03-run-and-observe.md`, "Use the inspector" and "Read returns")
- the node catalog exit section
- `ExitPredicateFields.tsx`
- `EvaluationDetails.tsx`
- `projections.ts` `describeExit`
- the `exit.evaluated` event schema
- the #129 comment of 2026-10-08 on the PR #126 exit-local Choice options array

Sources for "after": current `main` (`f157fc1`), reproduced in the built product, then this branch. The owner review steps, with their four loops, are in [2026-10-19-wp-g4-exit-evidence](2026-10-19-wp-g4-exit-evidence/README.md).

## Reproduction on `main` before the change

The product was built and run with the browser-spec harness: an in-memory store, ephemeral ports and the fake harness and classifier.

**Quiet exit** (`returns: "none"`, no destinations), and **exit with suppressed destinations** (`returns: "none"`, caller and log). Both runs show the same thing, and there is no Result card:

```text
Exit evaluation
Exited: success
```

Selecting `exit.evaluated` shows "Exit outcome: success. This exit is terminal. See the run result for the returned value." That points at a result that does not exist. The event log has no `return.*` event. Nothing tells the configured caller and log destinations apart from a quiet exit.

**Exit editor while Returns is None, with two destinations:** "No returned value." and the Destinations help "Return destinations; caller by default. No delivery when returns is none.". The list still shows "Destinations 1 / caller" and "Destinations 2 / log". A new exit from the palette shows "Default: [{"kind":"caller"}]" with no help.

**Mapping that evaluates to nothing** (`returns: "vars.missing"`): `run.finished` has `"result": null`, and `return.delivered` is recorded for caller and log. The snapshot drops the null, so the inspector shows no Result card.

**Classifier Choice gate** (repeat on "Again", maximum passes 3; the fake classifier always answers the first option):

- The Options list shows "At least 2 items. Two to sixty-four uniquely labelled options, each with a stable id and a nonblank criterion.". The per-option help reads "Stable provider key and output port…", "Unique readable option label." and "Authored criterion sent to the selected evaluator.".
- Entering a duplicate label shows "option labels must be unique" under the field.
- The timeline reads "Chose again with classifier via http (kev-latest) with confidence 1; passes 3 → 3 of 3; Limit reached (max-passes)". Details show Option ID `again`, Selected port `limit-reached` and the pass rows, but not the option's label or criterion.
- The top card reads only "Exited: exhausted".

**Expression gate routes:** the list help reads "Two to sixty-four stable readable routes.". It says nothing about uniqueness, and the route **Id** and **Label** fields have no help. A duplicate ID shows "route ids must be unique".

## After the change

- Quiet exit: "Quiet exit: Returns is None and there are no destinations, so nothing was returned or delivered. This is the exit’s configuration, not a failure."
- Suppressed destinations: "No value was returned: Returns is None, so no destination received anything (caller, log from the exit). This is the exit’s configuration, not a failure." Destinations added by the start request's `return` are named as "… from the start request".
- `null` return: Result shows `null`.
- Exhausted gate: "Last gate decision: gate chose again on pass 3 of 3; maximum passes stopped the repeat, so it took Limit reached." Decision details add Label "Again" and Criterion "More work is needed".
- The exit editor reads "No returned value. The run finishes without a result, and destinations receive nothing.". The Destinations help reads "Returns is None, so these 2 destinations receive nothing. Choose a JSONata expression to deliver a value, or remove destinations for a quiet exit." With no destinations it reads "Quiet exit: nothing is returned or delivered. The run still finishes with its outcome.".

The inspector derives the "returned nothing" line from the immutable run version and the absent `result` on `run.finished`, only when the pinned exit's Returns is None. A recorded result, including `null`, appears in Result. When the result is absent but the pinned exit's Returns is an expression, the inspector says that the history alone cannot show whether nothing or an unrecorded null was returned: an older build omitted null results. When the pinned definition or exit is unavailable, it says that the Returns setting cannot be shown. Section 6 of the owner review recipe reproduces the omitted-null case.

Not in this bolt: per-destination delivery status after the terminal event belongs to #185. Current storage preserves `null` results. The inspector shows the run row's recorded result, falling back to `run.finished` when the row has none; if both omit the result, no Result card appears and the explanation follows the pinned configuration as described above.
