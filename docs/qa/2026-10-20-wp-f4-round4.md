## 6. Docs

Docs/06 now explains that successful result acceptance is emitted immediately after validating
session, model, usage and result text; the engine records its visit/turn provenance before the
CLI-exit wait. Usage totals, completion and the final result still require a verified outcome.
A later transport failure preserves acceptance without publishing the buffered result.

The #244 CHANGELOG bullet adds: "Claude result-only acceptance is now recorded as soon as the
successful record validates, before process exit; usage and completed results still wait for
verified exit." The existing upgrade note, including automatic recovery of running inference
runs and the prohibition on resuming old inference failures without `harness.turn`, is unchanged.

### Kill-after-result recipe

1. Select Node 22, then `pnpm.cmd build`.
2. Run `pnpm.cmd test:prompt-restart` (or the filtered native command above for just the two new
   cases). The fixture selects a free port in 5840-5849 and creates its own
   `%TEMP%/gg-wp-f4-restart-*` store.
3. Complete node A, then start authored B using previous or named policy. The real fake CLI
   emits init and successful result, emits no assistant event, and stalls before exiting.
4. Observe `claude.result.hold` from the transport, then inspect `/runs/<id>/events` for B's
   `harness.submission {submission: submitted, marker: claude.result, visitId, turnId}`. Verify
   no B usage or `node.finished` event was published before exit.
5. Hard-kill the API, restart the built app against that exact disposable store, and wait for
   recovery. Require one resume on the recorded UUID with the continuation prompt, zero fresh
   calls, the same visit, a continuation-kind turn, and a succeeded run.
6. The fixture kills/awaits its owned API processes and removes only its validated own store
   in `finally`. The fake CLI exits on IPC disconnect so an API kill leaves no held child.

## 7. Decisions and parameters

- No new product policy: result validation is acceptance evidence independent of the eventual
  process outcome. The existing queue preserves its order with earlier adapter events;
  completion buffering no longer holds this evidence hostage to process exit.
- D-022 still blocks authored work with only an inherited session and no durable marker.
  Accepted work continues its recorded session. Pinned refusals stay non-resumable; Codex and
  Claude retain their confirmed family-specific generic-failure eligibility.
- The fake CLI's 600,000 ms stall permits a controlled kill. Native cases allow 180 seconds;
  marker observation allows 10 seconds and existing IPC/recovery waits allow 60 seconds.
  These test bounds do not change product limits.
- Native evidence is a real killed/restarted built app over a fake external CLI. Component
  evidence uses the public runner and engine ports. Neither claims provider behavior.
