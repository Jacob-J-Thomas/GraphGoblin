# Read-only assessment of the Linux performance CLI failure

The orchestrator reports that the browser workload failed on Linux at `70f85510` after `PERF_CASE 1000 complete`, while the same head passed on Windows. This is source analysis, not a reproduction or a verdict on that failure. No tooling file was changed or tooling test rerun here. `git diff --quiet 70f85510 HEAD -- tooling/perf` returns 0, confirming these tooling sources match the failing CI head.

`tooling/perf/measure.mjs:547-555` sets `summary.correctnessFailure` before printing the case-complete marker. Its `finally` then closes the worker, flushes the memory log and reads the CPU profile. Lines 628-633 exit 1 for any of `correctnessFailure`, `memoryLogError`, `closeError`, or `profileError`. Thus the marker does not establish that correctness passed, or that teardown/profile processing succeeded. The failing run's `raw-summary.json`/printed `PERF` record is needed to distinguish them.
