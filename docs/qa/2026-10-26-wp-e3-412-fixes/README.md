## 7. Decisions and parameters

| State or event                                            | Protection and eligibility lifecycle                                                                                                                 |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| New/active/paused/unfinalized or required related history | Protected as before; no inferred approval. Success/failure identical.                                                                                |
| Mark/withdraw/Resume/new dependency                       | Existing explicit selection, atomic preview confirmation and revocation are unchanged.                                                               |
| Fixed definition or workspace use                         | Observe physical identity outside the transaction; atomically store the source obligation and observation. Unresolved template use starts unknown.   |
| Incomplete refresh or unknown resolution                  | Keep workspaces. An incomplete sweep keeps pressure; it is not proof that no removable resource exists.                                              |
| Completed proof and approved owned resource               | Indexed overlap/unknown check plus positive ownership recheck, quarantine in short transaction, unlink after commit with identity checks and yields. |
| Restart/interruption                                      | Fresh reference epoch on restart; unfinished obligations/job generations remain durable, with no new consent or scope expansion.                     |

Public capacity port, fs.statfs and headroom remain unchanged: enter below min(1 GiB, 5%); leave at min(2 GiB, 10%); startup measure then listen/background cleanup, subsequent checks every 60 seconds. Record/use refresh is not on event append. The current append measurement is 80 VM instructions at both 100 and 10,000 history rows; Resume remains 297 at both sizes (r3-append-bound.log.txt).

Engineering bounds: 2,048 refreshed obligations per pass covers 1,000 workspace users plus fixed definitions; no maximum retained-store row count. Each filesystem resolution tries at most 64 ancestors and errors mean unknown. Deduplicate equal raw paths within a refresh batch. Each indexed refresh write handles at most 32 rows (at most 129 SQL parameters); staging remains seven statements for the measured equal-depth paths. Existing 20-root/500-record, 256-job/32-inventory, 2,000-entry inventory and 2,000-document/2-MiB artifact limits remain unchanged. Large refresh sweeps span minute passes, preserving responsiveness and jobs until complete.

The source index uses separator-terminated physical directory keys, indexed null checks, ancestor equality and descendant ranges. Its null obligations preserve unknowns; it never turns path shape into ownership. Reference triggers run only for source lifecycle changes, never event sequence, checkpoint or finalization updates.

Remaining external race: an alias can be created or retargeted after its row is observed and before staging. The next workspace use/publication or cleanup sweep detects it; a late-alias regression proves pre-sweep changes are caught. The exposure is the current sweep plus reaping batch, potentially several passes for large stores, not an indefinitely cached definition. There is no filesystem snapshot or absolute freshness guarantee against external mutation. The final owned-path identity/realpath guard still rejects substitution of that candidate. This is stated explicitly in ADR-0060; no claim of race elimination.
