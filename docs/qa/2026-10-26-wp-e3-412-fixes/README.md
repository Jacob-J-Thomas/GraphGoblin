## 7. Decisions and parameters

| History/event                                     | Protection/eligibility lifecycle                                                                                                                  |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| New history, active/paused, terminal unfinalized  | Retained/protected; no implicit approval.                                                                                                         |
| Terminal finalized complete component             | Explicit reviewed individual/bulk consent only; success/failure identical.                                                                        |
| Resume/new child/replay/relationship change       | Existing transactional revocation remains; approval is not restored.                                                                              |
| Retained artifact or physical workspace reference | Protected; canonical artifact form, native realpath aliases/deepest existing ancestor, platform case rules and unknown-keeps behavior remain.     |
| Successful mark/withdraw in Runs                  | Remove confirmed IDs from selection; deleted IDs require confirmed 404; retained outside-filter IDs stay selected.                                |
| Pending/quarantined resource                      | Keep copied original approval and positive owner/identity until a safe purge completes; a new original-path publication is a separate generation. |

Capacity port and thresholds remain engineering parameters: public StorageCapacityPort/FsStorageCapacity.statfs, enter below min(1 GiB, 5%) and leave at min(2 GiB, 10%), providing bounded proportional headroom/hysteresis. First startup sample precedes listening; initial reclamation follows listening; subsequent checks every 60 seconds, no after-write/event/confirmation hook.

Work bounds: 20 approved roots/500 complete run records; up to 256 resource candidates and 32 inventories/stages; 2,000 entries per inventory. The concluding resource census checks 256 plus an overflow sentinel; overflow/changes mean unknown and pressure. Workspace recheck admits 32 distinct paths and 64 total realpath/stat operations, preserving on exhaustion. These reduce locked I/O; artifact proof stays at 2,000 documents/2 MiB. Counts represent all kept pending resources including queued/deferred work, so the conservative wording adds deferred. No absence claim is made from an exhausted cursor/proof budget.

Only approved run components and their dependent SQL rows are removed; workspace ownership requires exclusive creation and stored device/inode/birth time, artifact ownership requires exclusive publication and the same identity. Resource path shape is never proof. Shared/fixed/user-owned/pre-existing resources, links, substitutions and unknown references stay. The short publication-gated transaction rechecks references and renames out of reach, records the quarantine generation, then releases both locks. Entry-by-entry purge checks identities and yields. Original-key state plus deterministic quarantine discovery recovers a rename before commit; a new publication moves the older pending generation to its quarantine key. Partial purge resumes; already missing bytes get no extra credit. Storage reports unlinked file lengths separately from reusable SQLite pages and never promises OS free blocks; no VACUUM/reset.
