## Deviations, decisions and caveats

1. **Header classes from 640 px changed** (the design said they stay unchanged). The baseline shows
   the nav overflowing at 640 and 768 px with 200% text on every route, so the header wraps at all
   widths when its content cannot fit. A row that fits is pixel-identical, per the unchanged
   cells.
2. **Fixture intent corrections** in `inspector-reflow.spec.ts`. MATRIX 1440/200 and
   ROUTE_LAYOUTS 640/200 and 768/200 change from `unchanged` to `reflow`, and the inspector route's
   1440/200 cell is recorded rather than held, because its history buttons sit below the run
   header that now reflows. On the build before the change these exact cells failed the fixture's
   own containment checks, so holding them unchanged would contradict its assertions. No assertion
   or oracle was removed; the same shared header stays held unchanged at 1440/200 on the other six
   routes. Reviewers should confirm this.
3. Changes beyond the design's list, each evidenced above: `fit-content(50%)` controls column; label
   wrapping on run controls, script recovery, review footers and Timeline paging (not only history);
   inherited `wrap-anywhere` on the selected-event column and around ExecutionContext (instead of
   only the event type). Header padding below 640 px is `py-1.5` rather than the design's `py-2`,
   so a 44 px coarse-pointer Menu keeps the 56 px row.
4. The credential check compares both `generation` and `rejected` for equality, rather than the
   design's literal `!rejected && generation === captured`. Every acceptance change is a new
   generation, so this is equivalent for gates issued while accepted. A gate issued while the key
   is already rejected keeps ordinary behaviour: its write gets the ordinary 401 instead of being
   silently ignored.
5. A write whose own 401 rejects the key settles under the new (rejected) generation, so it reports
   "requested before this browser's API key changed" rather than its 401 text.
6. If an earlier attempt from a review was refused under key A, and the key then changes, that
   refusal is hidden and the review closes with "Nothing was sent", which refers to the review's
   current choice.
7. `bindCredential` rebuilds a client from the app client's `config` (base URL, headers, fetch).
   Middleware added to the app client after creation is not carried over; `createAppClient` adds
   none.
8. A ScriptRecovery, fresh-session or WaitPanel outcome settled under another key is still reported
   after the control itself disappears (for example, the run moved on).
9. `pnpm check:qa` was not run: no `docs/qa` packet was produced, because the brief puts evidence in
   the delivery-evidence folder.
