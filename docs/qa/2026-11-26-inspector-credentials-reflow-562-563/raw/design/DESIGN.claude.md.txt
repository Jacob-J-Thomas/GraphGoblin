**#562 design**
1. **Gate:** read `generation` from the key store when rendering and add it to the `gate` memo's dependencies. A new gate identity then closes old reviews at commit through the existing identity checks. `open()` also checks the live store: `!rejected && generation === captured`. This live check is the only protection between the key change and React's layout-effect commit, because until then `latestGate.current` still points at the old gate. Don't use the header registry's scope as the token; it only changes later, on `lease()`.
2. **Atomic check:** the last check must run in the same synchronous step where `withApiKey` reads the key. Either prove there is no `await` between `assertOpen` and `fetch` in `runs.*`, or move the comparison into `withApiKey` and throw "not sent" without calling `fetch`.
3. **All writes covered:** pause, resume, cancel, replay, script retry, fresh session, and delete-ready preview/confirm. A preview token from key A must never be confirmed under key B. Include the Input requested submission if it writes. Typed drafts are kept; earlier clicks no longer count.
4. **Old review, nothing sent:** close it. Return focus to its trigger ("Replay…", "Review delete-ready history" or "Withdraw delete-ready mark") if enabled, otherwise to the status line (tabIndex -1). Never take focus from an open API-key prompt. Announce in a polite status region that is already in the page, below the Resume reason (history uses its existing live span). Copy: "Review closed: this browser's API key changed. Nothing was sent. Open Replay… again to choose with the current key." Reopening resets node, consent (false) and observed sequence.
5. **Queued but not sent:** use a new error, not the existing `NOT_SENT` text about a lost connection. Show it in the existing alert slot, outside the closed dialog. Copy: "Not sent: this browser's API key changed before {action} was sent. Choose it again to send with the current key." No retry, no reopening, nothing triggered automatically. The existing run refresh on error stays.
6. **Already sent:** one request, never cancelled or resent, cache refresh unchanged. If it finishes after the key changed: don't navigate, and don't show IDs or error text received under key A (#386 says evidence isn't shown across generations, and key B may not be able to read the new run). Copy: "{Action} was requested before this browser's API key changed. Its outcome isn't shown under the current key; check Runs before trying again." Controls stay pending until it finishes.
7. **Same key:** re-saving the same key doesn't change the generation, so the review and consent stay and one click sends one request as A. The same key after a rejection or "forget", and A→B→A, expire the review.
8. **Header:** don't remount anything. During a pending run read with no key change, "Status from event #N; the run record is updating." stays and the gate stays open.
