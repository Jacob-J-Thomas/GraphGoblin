## Comparison method and limits

The manager is stopped through its public scheduling method before each fork, so GET /runs/:id/thread can be checked while queued; then it is started and allowed to settle. Queued GET equals the repository initial thread. At every event sequence the inspector initialThreadFrom/tryThreadAt result is compared with domain replayThread from that actual repository seed, the same projection used by the executor. That oracle is also reconciled against the engine checkpoint at its saved sequence and the terminal public GET /thread. These are per-sequence authoritative projections, not claims of an HTTP read synchronized with every intermediate event (current-thread tail reconciliation belongs to #116). Full expected and actual threads, errors and differing top-level fields for every sequence are in [before.json](2026-10-22-wp-g1-245-before.json).

The source record, event page, initial thread and checkpoint serialize identically before and after all three forks (assert.equal on their JSON bytes). The API regression additionally compares all raw SQLite runs and run_events columns for the source.

## Root causes verified

- replay() passes the actual seed to admission.initialThread but omits queued.initialThread. All three queued events lack the seed. The inspector therefore uses its empty fallback, losing inherited state.
- Independently, threadAt() overwrites the domain projection nodeVisits with a count beginning at zero. Supplying the real repository seed still loses inherited counts at sequence 1.
- The executor increments the seed nodeVisits for every node.started. countEntries guards fresh entries using only attempt-1 events of the fork, and attemptFor uses its own unfinished starts. Gates preserve the seed and decision.made records absolute passes. Current runs keep iteration 1; replayThread preserves historical iteration.incremented values.
- Queued GET /thread already returns the seed. No endpoint or getThread fix is indicated.
