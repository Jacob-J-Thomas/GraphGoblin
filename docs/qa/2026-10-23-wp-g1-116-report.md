Domain `reconcileThread` owns reconstruction from the admitted seed and a durable event prefix. A checkpoint is usable only when its sequence exists in that prefix and does not exceed a selected historical boundary. Engine execution, REST current-thread reads, MCP's delegated current-thread read and both inspector reconstruction paths use it. Reads never save a reconciled snapshot, advance execution or finalize a run. A start contributes its recorded visit; only a durable completion supplies a patch. The replay open-visit guard survives a checkpoint and prevents duplicate completion patches.

The existing SQLite checkpoint read already returns a coherent thread/sequence pair and needed no change. The REST thread route and MCP already delegate to the manager/API respectively. `GET /runs/{id}` returns the run-record lifecycle projection and contains no context-thread field; its status agreed at every sampled baseline step. The raw SQLite checkpoint is deliberately still stale until the controlled FIFO flush. That cache is not a second current-thread authority.

An inspector catches up beyond historical terminal events with finite JSON event pages, then follows an active SSE tail. Durable lifecycle events decide the tail state if a page overtakes the captured run record. Two-second checks observe resumable failures and terminal status that has not yet reached the row; metadata can refresh without another event. The existing cursor and duplicate handling remain in use. `event-store.ts` and `RunInspectorPage.tsx` are unchanged.

## 7. Decisions and parameters

- Snapshots are verified caches. An unsequenced/unreachable/future checkpoint cannot determine a current or historical read. Sequence validity uses the existing repository contract; this is not a new snapshot-content checksum.
- Starts preserve visit evidence; only completed-node patches enter the thread. Carrying the open visit across a checkpoint keeps duplicate completion behavior consistent with full replay.
- Catch-up captures `lastEventSeq` and requests 500-event pages (the API default), bounding a pass even if execution keeps appending. A returned page can go beyond that captured cursor; durable lifecycle events therefore decide whether another live tail is needed.
- Two seconds bounds idle resumable/lagging-row observation to one check per interval. It is an engineering refresh choice, not an owner-approved SLA. Status agreement ends other terminal polling.
- Transport observation retries use exponential delays of two to thirty seconds. Permanent HTTP/data errors remain visible. No execution or mutation is retried.
- Aborting/unmounting stops observation and discards late page results. Read repair never writes.
- The actual admitted replay seed from #245 remains authoritative. Separate REST requests may observe different prefixes; this bolt does not make run-record and thread requests atomic or rewrite run-record finalization.
- #255 patch-diff presentation and exact-value work remain deferred. #186's SSE/backpressure work remains separate.
