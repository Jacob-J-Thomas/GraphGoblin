# Numeric Omit: built-browser regression

The correction is frozen at product commit `1ae90e2b35c2f2365efad4118e5cebf98ad1d3fd`. These checks were run by the orchestrator, separately from the [independent native QA](../2026-11-14-input-numeric-omit-independent/README.md). They establish the regression test and rebuilt component behavior; they are not an adversarial review or owner acceptance.

- The new native regression was first run against the preserved pre-correction web build, whose 25 recorded runtime asset hashes still matched the reviewed `e0ff50c5` build. It failed at the intended assertion: after Omit, native `badInput` remained true instead of false. The failure, error context and result are retained. The three source maps omitted by the earlier asset inventory are separately identified; all 28 current distribution files were hashed.
- The web package was then rebuilt, including both web shells, using project Node22.23.4 and `pnpm.cmd --filter @graphgoblin/web build`. The build passed. The main web asset manifest is `26a6b72052892845f17aa1d29f8118d421639db24fd78a362fdf2216e2daaec2`. The API entry hash and API/package source remained unchanged from the preceding reviewed build.
- All **nine form-control browser cases passed on the first corrected-build execution**, in50.3seconds, on Windows Edge with one worker and zero retries. The new case exercises native incomplete numbers through both New Run and Wait, by keyboard and click; it checks cleared native validity, returned focus, preserved neighboring text and zero, continued refusal of the required invalid number, exact submitted input, and the final run result.
- The unchanged coarse-pointer case also passed: a real44×44 target with safe spacing, surrounding-field taps that do not omit, and intentional button taps that do. The correction changes no geometry or class strings. The wider responsive suite was not repeated locally for this event-handler change; final full CI remains required.

The unit implementation record and its negative control are in the [review and correction evidence](../2026-11-14-input-presence-review/README.md). The component unit test models a native buffer; the browser runs here exercise actual native input behavior. A failed run on the old build is expected negative-control evidence, not a failed corrected-build attempt.

The raw JSON and logs preserve each command's result and timing. `before-build-binding.json` explicitly identifies old runtime/new regression source; `after-build-binding.json` binds the rebuilt files to the correction. `capture-build.mjs` is the original environment-specific hash collector. The nearly2MB old-build trace remains in the external QA archive with its path, size and SHA256 recorded in `external-trace.json`; the relevant assertion, source stack and page state are retained here in the result and error-context files.

Physical phones, assistive-technology speech and operating-system forced-colour painting were not tested by these checks. Native processes were managed by the existing Playwright setup/teardown. The separate subsequent QA record verifies its own explicit gateway/browser PID and lock cleanup. No owner app, store, provider or personal configuration was used. Current CI, reserved Astra scan3 and owner acceptance remain separate gates.
