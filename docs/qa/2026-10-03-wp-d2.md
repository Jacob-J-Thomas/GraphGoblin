# Adversarial QA pass - WP-D2 (2026-10-03)

The first full adversarial pass over the M5 web app and the API it uses (docs/10, "Adversarial QA"). An agent drove the built app (`apps/web/dist` served by the API) with Playwright on Microsoft Edge, scripted the fake harness through the E2E server's control port, and attacked the API directly with `fetch` and Fastify `inject`. Two live Codex sessions (`gpt-6-luna`, effort `low`, read-only sandbox) ran at the end.

Regression tests: `apps/web/e2e/qa.spec.ts` (9 specs), `apps/api/src/qa.test.ts` (8 tests), plus unit tests next to each fix. `apps/web/e2e/live.spec.ts` is the `LIVE=1` check.

## Measurements

- **1,211-event run** (one inference node streaming 1,200 harness items). Before the fix: opening the finished run took 7.15 s and made 1,213 `GET /runs/{id}` requests; following it live took 22 s for a 3 s stream with 1,208 refetches. After: a fresh open completes in 0.2 to 0.6 s with 3 to 7 run fetches, live follows the stream to completion 0.25 to 0.5 s after the harness turn ends, selecting event 601 renders its thread in 0.13 to 0.4 s, no gaps and no duplicates (all 1,211 sequence numbers present once), next animation frame under 1 ms. Session storage held 257 KB for that run.
- **Viewports**: no horizontal scroll at 1024x768 or 1440x900 on Loops, Editor, Runs, Run inspector, Events, and Settings; the canvas keeps its controls and the property panel scrolls.
- **Accessibility smoke** (manual: axe-core is not in the tree): every input, select, textarea, and button on Loops, Editor, Settings, and the Run inspector has an accessible name; tab order on Loops runs header navigation, create form, import, then each row's links and buttons. Status badges are `*-900` text on `*-100` backgrounds (above 10:1) with a glyph as well as colour. Two contrast failures were fixed (D23).

## Checked and found working

- **Loops**: create, rename (Loop settings → Name; the server renames the loop on the next draft save), delete with confirmation, export, import of a non-JSON file ("is not a JSON document"), and export → import → export equal apart from `exportedAt` (Unicode description included; `apps/api/src/qa.test.ts`).
- **Forms**: empty required fields, wrong types (`-5` and empty for integers), 5,000-character and Unicode labels (schema message, saved on the device only), unset restores defaults, variant switches.
- **Edges**: connections into a trigger refused, a second edge from a connected port refused, deleting a node removes its edges and clears an exit's loop-back target; self-edges are allowed (they feed D28).
- **Runs**: trigger input validated against `inputSchema` (400 `INVALID_INPUT` with the JSON pointer); ten concurrent runs of one loop; cancel when waiting and when finished, and a queued run in the existing engine tests (409 once terminal); pause and resume a waiting run; input twice (409) and input to a paused or finished run (409).
- **SSE**: reload mid-run resumes from the stored cursor with no gaps or duplicates; a terminal run opened fresh replays and closes; 1,211 events streamed live in order.
- **Failure reasons** shown in the inspector with their typed code: `HARNESS_TURN_FAILED`, `OUTPUT_SCHEMA_MISMATCH` (repair exhausted), `DECISION_NO_ROUTE` (decider unavailable), `SUBLOOP_DEPTH_EXCEEDED` (on the deepest child), `SUBLOOP_NOT_FOUND`; `maxIterations` reached ends as `exhausted`. A failed child does not fail its parent, as docs/04 specifies.
- **Secrets**: set, overwrite, delete, delete twice (404), odd names (400), empty value (400), 70,000-character value (400 above 65,536); the value never appears in any response or in the DOM after saving.
- **API keys**: create (token shown once), use, revoke, revoked key (401), malformed `Authorization` (401).
- **PWA**: offline banner; the cached shell opens offline, including a deep link to `/app/runs/<id>`, with explicit offline states; update toast (existing spec); `/` and `/app` redirect to `/app/`; a missing asset is 404; unknown client routes show "Page not found".
- **Static serving**: `/app/..%2f..%2fpackage.json`, `%2e%2e`, `..%5c`, `....//`, and `%00` all 404; with `GG_REQUIRE_API_KEY=true` none of `/app/../loops`, `/app/%2e%2e/loops`, or `/app/..%2floops` reaches an API route.
- **Webhooks**: bad signature, stale and missing timestamps, replays, oversized bodies, and the rate limit are covered by `apps/api/src/triggers.test.ts` (WP-C) and were not changed.

## Gaps against docs/09 (not defects)

- Replay-at-node in the inspector: WP-F1 (M8).
- Settings has no scheduler status card (docs/09 lists one); the API has no scheduler status endpoint yet.
- The Events screen does not list webhook endpoints; they are on `GET /loops/{id}/triggers`. A small editor panel per trigger node would fit.
- CodeMirror modes for Liquid and JSONata are stand-ins (Jinja2 and JavaScript); no completion against the sample thread.
- The canvas has no keyboard shortcuts for add, connect, or fit-to-view beyond palette buttons, the Connect form, and xyflow's controls; there is no undo.
- Variables are edited in the Loop tab, not a side sheet.

## Live check (Part 3)

`LIVE=1 pnpm --filter @graphgoblin/web test:e2e -- e2e/live.spec.ts`: two sessions in total. The UI created a loop, added an inference node ("Reply with exactly the single word OK and nothing else.", `gpt-6-luna`, `low`, read-only), wired it with the Connect forms, published, ran, and watched it to `run.finished`. Both runs succeeded with the assistant message `OK`; the first failed only on the spec's text assertion (the message list's text content joins role, node id, and body), which was corrected and passed on the second session in 9.5 s.

## Review follow-up (cross-vendor review, same day)

An independent review requested changes; all eight findings are fixed with regression tests:

- Engine: a pause landing during the yield between nodes now stops the run before `node.started` (7352e3c; `run-manager.test.ts`).
- Editor: draft saves for a loop are serialized, including the unmount save, and bound to loop id and editor generation; an older save can no longer overwrite a newer one or mark an older device copy as synced (1144ee7; out-of-order completion test).
- Editor: the set-aside device copy is persisted under its own IndexedDB key until restored or discarded (1144ee7; edit-then-reload test).
- Editor and inspector: after a 401, entering a key loads a cold editor deep link and restarts the run event stream (1144ee7; unit tests and an E2E for both deep links in required-key mode, edc254e).
- Forms: unparsed JSON text and its `FIELD_UNPARSED` blocker survive leaving the field until the text parses or is discarded (1144ee7).
- API: a self-referencing subloop pinned to a number must be the version the draft publishes as or an existing published version (04cd848).
- API key: Forget key is followed by other tabs through the `storage` event, which also drops their loaded data and restarts streams (1144ee7).
- API: import runs the shared validation, trigger checks included (04cd848; agreement test with create).

The size of `run.queued.initialThread` is documented in docs/05; offloading it to the artifact store stays a follow-up.
