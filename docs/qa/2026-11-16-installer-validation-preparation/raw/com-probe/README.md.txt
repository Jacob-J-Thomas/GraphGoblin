# #436 hosted Shell Link diagnostic proposal

Preparation only. The first hosted driver stopped during case 01 setup in `WriteAppId` with HRESULT `0x80070002`. The retained run lacks the requested link's state immediately after WSH `Save()` and individual native HRESULTs. [First hosted baseline report](../launcher/436-hosted-baseline-first/README.md)

The proposed probe creates two fresh shortcuts under the same owned runner-temp tree, in separate case folders. Unicode `Chrome α.lnk` runs first and ASCII `Chrome A.lnk` second. Both use the same hosted Chrome proxy path as target and icon, WSH `CreateShortcut`, the original profile argument and AppUserModelID, and the same App ID derivation as the sealed fixture. The probe uses a fixed loopback origin string because the original allocated port was unrecorded. It opens no socket.

For each case the probe records WSH `Save()` disposition, exact requested path and containing directory entries, native file ID and canonical path, hash, an exact copy of the initial link bytes when present, and WSH-decoded target, arguments, working directory and icon. It then records the native read/write factory, `SetValue`, `Commit`, and independent read-only reopen and `GetValue` HRESULTs as they return. The helper keeps the original native ABI, property key, variant, flags and COM method order. It exposes the factory's raw HRESULT in place of automatic exception translation. A successful WSH save with a missing file still enters the same property-store call with the exact original path. A WSH save failure is retained and stops that case before the property store. Cases also retain the final link bytes and state. The separate ASCII case continues after a recorded Unicode failure.

## Proposed hosted carrier

- Restore the ordinary post-#435 Windows workflow. Keep install, build, existing native acceptance and artifact behavior, and the other three jobs. Set Windows checkout fetch depth to 2 for the actual merge parents. Append the two steps in `carrier-steps.yml` to the Windows job.
- Copy exact `probe.ps1` and `PropertyStoreProbe.cs` bytes into the archived carrier's `raw/com-probe` under the existing byte-preservation rule. Use its unchanged raw native `windows.cs` for file identity. The wrapper checks all three expected input digests before and after the probe. It checks actual merge SHA, tree, parents, PR 497 and run attempt 1, and verifies tracked product inputs against the exact post-#435 base.
- A single x64 STA PowerShell child receives 45 seconds for actual exit and 5 seconds for independent stream completion. The wrapper retains exact launch inputs, PID, birth, separate exit, pipe close, streams and first wrapper failure. Its two-minute step limit handles infrastructure stalls. The wrapper sends no signals. Its always-upload step retains only the fresh owned attempt tree in `qa436-com-probe-first`, including both links.
- `diagnostic-complete` means both observations were recorded. A failed COM call can be a complete diagnostic. Read each case's receipts before updating the #436 baseline status. The probe launches no installer, browser or gateway, writes no profile or registry settings and starts no ETW session. It exercises Shell Link setup only. A later independently admitted 32-case run supplies product evidence.

The proposal uses the hosted Windows image selected by the ordinary job and records the actual OS, image version, profile SID, session and Chrome executable identity. The separate VM makes exact profile identity across runs unavailable. Syntax was checked offline. Native calls, C# compilation, GitHub execution and artifact upload await admission and were not exercised.
