## Running later on a bound hosted job

The parent launch below requires the GitHub-hosted Windows markers, x64 PowerShell 7 with an STA thread, a declared checkout HEAD and actual image-installed `chrome_proxy.exe`. The selected Node must be 22.22.2 or later within major 22, and the checkout must already be built. Use the exact installer, launcher source, dependency inputs and built outputs reviewed for that phase. The driver records selected SHA-256 file bindings and compares them on completion. The caller owns the complete source/index/build/dependency binding and actual driver exit/close receipt. This packet does not add a workflow job or step.

```powershell
$qaScript = '<absolute reviewed location on the hosted runner>\run.ps1'
$qaNode = (Get-Command node.exe -ErrorAction Stop).Source
$qaProxy = '<bound image path>\chrome_proxy.exe'
& (Join-Path $PSHOME 'pwsh.exe') -NoProfile -NonInteractive -STA -File $qaScript `
    -Phase baseline -Checkout $env:GITHUB_WORKSPACE -ExpectedCommit '<bound full lowercase SHA>' `
    -NodePath $qaNode -ChromeProxy $qaProxy -EvidenceName 'qa436-baseline-first'
exit $LASTEXITCODE
```

For the candidate supply `-Phase candidate`, its exact commit and a fresh name. Upload only `$RUNNER_TEMP\<evidence-name>\evidence`. The sibling `work` directory contains disposable inputs, including junctions. Keep upload traversal out of it. The hosted VM lifecycle handles work tree teardown. The only driver deletion outside its own tree is the exact Desktop fallback fixture, and only if its volume/file ID and bytes still match the created file after results are retained. Altered or ambiguous files stay for VM teardown and readback. No account, known folder, registry, browser or Explorer configuration is set up by this driver.

## What the driver observes

- **01–04, supported routes.** Real current Node, valid first install, same-path replacement and explicit existing pin, ordinary valid `-NoShortcuts` update, and default Node discovery against a controlled PATH. Real baseline/candidate execution compiles the product launcher from its bound source through the installer. Checks include a native x64 PE, config origin/runtime/store/checkout identities, stable launcher AppUserModelID, deliberate safe config change, and native link target, final config argv, working directory, icon and AppUserModelID. The original source and unrelated sentinel remain byte-identical.
- **05–11 and 32, Node refusals.** Blank/omitted/missing/unlaunchable paths and version failures. The C# version-only fixture is compiled inside the later hosted run and returns the labelled old/other-major/malformed/nonzero probe response. The unlaunchable fixture is a plain invalid image at an existing path. These are dependency fault fixtures. Real supported Node is used separately. Checks require actionable Node 22.22.2 guidance and check secret-like synthetic path/version canaries against actual stdout/stderr.
- **12–23, dependencies, source and destination refusals.** Missing helper, intentionally uncompilable source, reserved `GG_PORT` with and without shortcuts, missing source, wrong proxy/app ID/profile/origin/AppUserModelID and missing/invalid output prerequisites. Source-path negatives use actual native `.lnk` variants. Inputs protecting a prior install are created by a successful installer call in that case’s own directory. A failed baseline installation cannot change a different case’s sentinel.
- **24–31, native collisions.** Exact source/output equality, case variant, actual directory junction, actual hard link, desktop/Programs collision, pin/output collision, final config used as link output, and the collision with the default real runner Desktop. The junction and hard link use independent Win32 file identity comparisons. Case 31 requires existing Desktop and Programs directories within the runner profile and unused default shortcut names. The driver binds the directories, rechecks them and checks the names before creating its exact Desktop fixture with exclusive create. A missing, inaccessible, redirected or occupied path produces an explicit unavailable receipt for case 31. Other cases can still report results, and the overall driver remains incomplete. The driver creates no known-folder directory. The real product decides its first refusal diagnostic.

The source fixture is a real `.lnk` created through Windows COM and stamped through its native property store. Its target is Chrome's image-provided proxy, with independently generated app ID and synthetic profile metadata. The `-PinnedShortcut` file is an owned copy of a successful launcher output, which exercises the installer’s existing-file input. Actual Explorer pinning and PWA opening are outside #436. Supplemental browser-generated source provenance remains the plan-described optional observation. #438 log retention, #456 Finder/Dock and held #458/PR #460 stay separate.

## Receipts and remaining verification

Each invocation writes an attempt, direct child PID and best-effort creation timestamp, separate actual exit and pipe-close receipts, and the raw stdout/stderr bytes. `invoke.ps1` calls the public installer once using its existing named options and reports caught terminating PowerShell errors as exit 1 with the exception, error ID and script stack on stderr. The recorder captures the process status before stream finalization. The suite keeps independent case files and seeds, snapshots and raw copies of monitored artifacts. SHA-256, length, native file ID and decoded link properties let a reviewer verify exact refused-case preservation and the staged link’s final target. The candidate oracle runs against either phase. A complete baseline can record `baseline-difference` while retaining its actual installer exit and mutated-byte receipts. Candidate disagreements or unavailable required cases make the driver incomplete. An attempted positive failure aborts further native cases and preserves raw observations. A deadline leaves its PID/attempt evidence for the disposable VM lifecycle, without an automatic second invocation or process termination.

This packet has a 50 direct-child budget and a 310-second scheduling deadline, with bounded child waits and a separate stream-close interval. It records listener end states at independently selected loopback ports, plus empty disposable store readbacks. It does not continuously trace Chrome/gateway process births. For a full no-transient-launch assertion, collect process creation across the admitted run in the hosted job.

The missing-helper fixture is a small owned checkout projection and the compile-failure case uses bound API/web junctions with one deliberately invalid launcher source file. Check the admitted source/validation order before interpreting these diagnostics. The driver has no invented validation-only command, publication trigger or failure flag. For post-mutation rollback, the actual candidate must first establish a completed final-path mutation and later Windows publication failure, with observed exact restoration or documented recovery state. A sharing failure discovered in preflight establishes preflight only. A staged internal validation mode, missing system compiler handling, post-mutation rollback and any promised interruption recovery remain unexercised by this packet.

Preparation ran only PowerShell and C# syntax parser APIs. It did not execute either script, compile C#, invoke COM, start a fixture or launch the installer, Chrome or gateway. See `syntax-readback.json` and `SHA256SUMS.txt`.
