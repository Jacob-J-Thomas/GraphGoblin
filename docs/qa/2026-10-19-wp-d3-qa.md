# WP-D3 independent QA — 2026-10-19

## Verdict

**Fail acceptance in this execution environment.** Revision `7639cbf530561f116db986bbe8a2e69c6a20311e` passes 39 of 43 main runtime checks and all 4 supplemental checks. The four failures concern native script cancellation and timeout: Windows `taskkill` returns `ERROR: Access denied`, leaving the child alive until explicit QA cleanup. Decoder results after that cleanup are correct, but this does not satisfy native resource-release acceptance. This is an environment-dependent acceptance blocker; these observations do not establish a regression introduced by WP-D3.

**Orchestrator disposition (2026-10-19).** The four failing runtime checks are the Codex sandbox's `taskkill /T /F` denial (delivery register decision D-015), not a product defect: the Claude Opus 5.5 reviewer ran the same native cancellation and timeout tests outside the sandbox and every one passed (infrastructure 554/554, including the incomplete-UTF-8 cancellation case), and the recorded decoder outputs after cleanup are correct. ## Defects and acceptance blockers

### 1. Major — native cancellation/timeout cannot terminate script children in the managed Windows environment

**Steps:** run a script writing raw bytes `41 F0 9F` on stdout and stderr, then keeping its event loop alive. Abort the public `ProcessScripts` request, or set a 700 ms timeout. Repeat through real API script nodes with cancellation and a 1-second timeout. Check the recorded child PID. The QA watchdog observes a live child at its 3-second component / 4-second API deadline and explicitly terminates it. These watchdog values bound QA cleanup; they are not proposed product SLAs.

**Expected:** the owned child exits through the product cancellation/timeout path; final captures contain `A` followed by exactly one U+FFFD per stream, with 3 captured raw bytes per stream. The API reaches cancelled / `SCRIPT_TIMEOUT` without assisted cleanup.

**Actual:** all four runs require assisted cleanup. After cleanup, final captures are correct and API terminal states are truthful. A separate real child plus native `taskkill /pid <owned-pid> /T /F` returns exit 1 and `ERROR: Access denied`; its target survives. No unsandboxed reproduction was available. Do not attribute this environment-specific observation to the new decoder or declare ordinary Windows installations broken without further evidence.

**Evidence:** [component cancellation](2026-10-19-wp-d3-qa/component-cancel.json), [component timeout](2026-10-19-wp-d3-qa/component-timeout.json), [API cancellation](2026-10-19-wp-d3-qa/script-cancel.json), [API timeout](2026-10-19-wp-d3-qa/script-timeout.json), [native diagnostic](2026-10-19-wp-d3-qa/taskkill-diagnostic.json), [decoded output review](2026-10-19-wp-d3-qa/decoder-after-assisted-cleanup.json). The maintained `scripts.test.ts` incomplete-sequence cancellation test independently fails its `cleanupRequired === false` assertion.

**Disposition:** native cancellation and timeout remain unqualified. Recheck in an execution environment where native tree termination is allowed; preserve this failure record. No implementation changes made by QA.

## Decisions and parameters

The **65,536-byte** shared bound is the implementation's `PROBE_MAX_BODY_BYTES` engineering parameter, not an owner-approved number. Exact-cap data is accepted; overflow is explicit. For encoded HTTP bodies the budget counts decompressed bytes; empty 204/304/HEAD responses do not count representation Content-Length as a body. Items scripts request the same raw-byte cap and check both byte count and overflow flag.

EOF policy: incomplete raw bytes produce one U+FFFD for the held incomplete sequence; a character cut only because further bytes exceeded the capture cap is omitted. Default script capture remains **10 MiB per stream**. Raw-byte counts exclude the re-encoding size of replacement characters. QA's write delay, cleanup deadlines and startup wait are test parameters only.
