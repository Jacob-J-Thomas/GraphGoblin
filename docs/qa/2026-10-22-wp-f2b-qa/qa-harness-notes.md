# QA harness and observation corrections

These are QA setup/observation failures, not product fixes. The pinned product source remained unchanged throughout.

- The relocated Edge server initially could not resolve workspace imports. No tests ran. Its evidence-only imports were corrected. A subsequent source-package setup exceeded the original 60-second readiness budget under the broad test load; no spec assertion ran. The final adapter uses the already-built API packages and passed the unchanged tests with the original budgets.
- The first effort-only/high check closed the dialog while the asynchronous harness action was pending because both visible values already matched their old inherited/high values. The public harness radio must also be checked before Done. The corrected isolated check verified persisted model absence and the exact Opus/high CLI request.
- The first retry-after-failure check held every catalog attempt after attempt one. A subscriber's mount retry could occupy that hold before the user clicked Retry, leaving the button disabled. The corrected fixture keeps failures settled until the actual user retry, then holds that retry. It passed without treating recovery as a first load.
- A pointer click on the toolbar Undo is intercepted by the native modal dialog. The supported Control+Z / Control+Shift+Z shortcuts were used with focus on the harness radio. The final API-backed Undo check verifies all dependent fields and policy in a single history step.
- Clearing the last Settings default uses DELETE /settings/defaults, followed by GET, rather than PUT. The observer was corrected to accept the actual documented write. No setting assertion was weakened.
- Restoring catalog entries through an external API call does not itself refresh the editor's cached catalog. The final recipe check reloads to observe the restored catalog, confirms authored values remain, then switches explicitly. This matches the stated recovery rule.
- The effort-clearing fixture initially omitted all runtime model/effort defaults. The editor correctly saved absence but publication refused an unresolved inherited model/effort. The final case supplies loop model-only and process Opus/high, while its controlled catalog suggests unsupported minimal. The switch clears both node overrides; save/reopen/publication and the actual Opus/high request pass.
- A temporary PowerShell triage-script comment typo prevented parameter binding and ran zero tests. It was corrected before any isolated results were recorded. Later setup attempts with a missing optional page and a text-string apostrophe also ran no relevant assertions; corrected before the final cases.
- The initial broad web/API coverage runs overlapped at default worker counts. This produced worker-start failures and broad timing/assertion failures. Every failed test was then isolated and passed (58 web, 19 API). One bounded full invocation per package uses the original thresholds and timeout settings with a worker cap and a fresh report directory.
- The cached-catalog toolbar mismatch was observed in the adjacent-case run and reproduced alone. Its assertion was not removed or counted as a pass. The final checker records the complete recovery/API evidence and explicitly marks this case FAIL.

Final public-interface checks are in checks.json; the original observations and corrected selections remain in the source evidence files. No private editor state, production monkey-patching, weakened timeout, coverage exclusion, product test edit, commit or provider turn was used.

- The disabled-loop/defaults check initially compared cumulative counts after two navigations with a one-navigation expectation. Resetting that QA counter before reload restores the stated observation boundary; the isolated final check selects Opus/low and preserves the disabled Fable preference.
