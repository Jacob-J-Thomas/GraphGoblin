## 2. Final implementation

**(a) Gateway writer and production seam** — `apps/api/src/windows-log/gateway-log-writer.ts`
(built-ins only). Exactly `gateway.log` and `gateway.log.1`, 4,194,304 B each; complete UTF-8
records ≤ 65,536 B including LF, larger records replaced by a fixed marker; one file operation in
flight; queued + in-flight encoded bytes ≤ 262,144 B, excess dropped immediately with a bounded drop
summary before the next accepted record. Adoption accounts the opened size, repairs a partial
trailing record (scanning back in 64 KiB chunks), replaces oversized slots under ownership, refuses
links/non-regular/multi-link entries untouched. Rotation: verify previous identity → verify active
name == handle → close → rename-replace → exclusive create. Denied rename drops and backs off, never
truncates. Partial write → rollback truncate to the committed boundary or disable. Faults back off
1→60 s; 8 consecutive faults disable until restart. Each batch rechecks name vs handle; a removed
name is recreated, a foreign one disables the writer and is preserved. No staging/spill/TEMP file.
`write()` never waits; `writeAcknowledged()` resolves true only for that record's completed bytes;
`settle(ms)` bounds flushes. The writer exposes no `emit`/`flush`/`end` (Pino duck-types them; found
and fixed during this work).

**Production seam export/usage:** `openGatewayLog({ root, fs?, observe?, schedule?, now? })`.
`fs: LogFileSystem` = `lstat`, `open(path,'existing'|'create')`, `rename`, and handle `stat/read/
write/truncate/close` (default `nodeLogFileSystem`); tests and QA wrap it to stall/fault the exact
reached operation on real files. `observe(event)` reports every `adopt/write/rollback/rotate/drop/
suspend/disable` transition with paths and byte counts. `schedule` controls backoff/settle timers.
Built path: `apps/api/dist/windows-log/gateway-log-writer.js`.

**(b) Guarded entry, Pino composition, private/public, startup** —
`apps/api/src/main.ts` statically imports only `./entry-point.js` and `./windows-log/guard.js`
(transitively `gateway-log-writer.js`, `managed-root.js`, all `node:` built-ins; enforced by
`main-entry.test.ts`) and declares `export const WINDOWS_LAUNCHER_LOG_PROTOCOL = 1;` (emitted at
bytes 522–569 of `dist/main.js`). `main()` dynamically imports `serve.js` (former body) and returns
the same `{ app, container }`; CLI flags dispatch dynamically with unchanged precedence and exit
codes; import is inert. As physical entry it deletes `GG_WINDOWS_LAUNCHER_LOG_DIR` under every
spelling in all modes; managed mode only on win32, no CLI flag. The guard (`guard.ts`) resolves the
root, binds the pipe (70 on EADDRINUSE), runs the read-only privacy query, admits the slots, then
imports the app (72/73) and serves with stage reporting (74/75); only completed records count as
written (≤ 250 ms). `serve.ts` reports stages `configuration/store/recovery/http/bind`, flushes
≤ 250 ms after graceful cleanup, keeps the emergency exit. `gateway-logger.ts`: shell logger
unchanged; managed logger keeps level and engine records, `req`/`res` serializers carry only method,
registered route template, status. Instance protocol 2 (`instance-identity.ts`); fingerprint keeps
canonical `main.js` and PID.

**(c) Windows ownership, native process, installer** — `managed-root.ts`: realpath to a local drive
path, alias and canonical identities must match, pipe
`\\.\pipe\GraphGoblin.GatewayLog.<sha256("graphgoblin-gateway-log-root/v1\0dev=…\0ino=…")[:40]>`
(Node core net, connections destroyed, unref'd, held until exit); privacy via bounded system
PowerShell (Fixed NTFS, owner and every Allow ACE trusted, no null DACL; managed names not
reparse/dir/device). `Launcher.cs`: config validation requires the exact marker in the first 4 KiB
and `apps/api/dist/windows-log/guard.js`; reserved variable refused case-insensitively and set only
in `GatewayEnvironment`; pre-spawn root/entry validation and legacy read/no-write-share probe (waits
within the existing release deadline, then destination-in-use, never writes or prunes); NUL stdin
(read) and NUL stdout/stderr (write) as the only inherited handles; retained `CreateProcess` handle
via `ChildProcess` (disposed on every return); closed outcomes for 70–75/unknown; closed
presentation with validated ≤ 260-char locations; `launcher.log`/`.1` (256 KiB each, records
≤ 4 KiB, one 250 ms `Global\GraphGoblin.LauncherLog.<key>` acquisition, drop on contention/fault).
Installer requires the guard module; staged `--validate-install` enforces the marker.

  writer unit tests on real files plus one native oversized/restart case; QA's V2 workload remains.

## 5. Unresolved items for root

1. **Owner profile privacy:** this host's profile grants Allow ACEs to other local principals
   (CodexSandbox accounts and group, an AppContainer capability SID). By the contract's rule the
   default `%LOCALAPPDATA%\GraphGoblin\Launcher` here is not private, so the upgraded launcher would
   refuse with the unsafe-folder outcome (and drop launcher.log records) until that folder's ACL is
   restricted (guide 07 remedy). Needs root/owner handling before installation; nothing owned was changed.
2. Focused refusal runs 1–2 displayed the launcher's existing interactive error dialog until a 30 s
   timeout killed the process; no process remained.
3. The four-intent register (root-owned) is not updated.
