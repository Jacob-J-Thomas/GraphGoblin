## Gateway writer (production seam)

- Module `apps/api/src/windows-log/gateway-log-writer.ts` (built `dist/windows-log/gateway-log-writer.js`).
- `openGatewayLog({ root, fs?, observe?, schedule?, now? })` → `GatewayLogWriter`.
  `fs: LogFileSystem` wraps exactly `lstat(path)`, `open(path, 'existing'|'create')` (r+ / wx+),
  `rename(from, to)`, and handle `stat/read/write/truncate/close`; default `nodeLogFileSystem`.
  `observe(event)` receives every transition: `adopt`, `write` (position, bytes, records,
  bytesWritten, complete|partial|failed, code), `rollback`, `rotate` (close|rename|create),
  `drop` (pending-limit|suspended|disabled|fault|closed), `suspend` (faults, delayMs), `disable`.
- Writer API: `write(chunk): boolean` (Pino stream; never waits), `writeAcknowledged(record):
  Promise<boolean>` (true only when that record's bytes completed), `settle(ms): Promise<boolean>`,
  `close()`, getters `state`, `pendingBytes`, `size`. No `emit`/`flush`/`end` (Pino duck-types).
- Constants: slot 4,194,304 B; record 65,536 B including LF; pending 262,144 B (queued + in
  flight, markers and drop summaries included); exit flush 250 ms; backoff 1,2,4,8,16,32,60 s;
  8 consecutive faults → disabled until restart.
- Marker: `{"level":40,"time":<ms>,"pid":<pid>,"msg":"gateway log record omitted: it exceeded the 65536-byte record limit"}\n`.
- Drop summary: `{"level":40,"time":<ms>,"pid":<pid>,"msg":"gateway log records dropped","dropped":<n>}\n`,
  enqueued before the next accepted record when it fits.
- Adoption: previous slot then active. Oversized (> 4 MiB) slot truncated to 0 under ownership;
  otherwise trailing partial record truncated to the last LF (scans back in 64 KiB chunks; none →
  0). Active created with exclusive create if absent. Identity of name vs handle compared.
- Rotation: verify previous is absent or the admitted/rotated identity; verify active name ==
  handle; close; `rename(active, previous)` (MoveFileEx replace); exclusive create of active.
  Denied rename → drop queue, backoff, no truncation; retried later.
- Every batch: `lstat(active)` must equal the handle identity; absent name → recreate; foreign
  entry → disable and preserve it.

## Startup records and exits

- Closed record: `{"level":50,"time","pid","msg":"GraphGoblin startup failed"|"GraphGoblin application import failed","stage","cause","detail","guidance"}`.
  Stages: `import`, `configuration`, `store`, `recovery`, `http`, `bind`. Causes: see
  `STARTUP_CAUSES` in `apps/api/src/windows-log/guard.ts`.
- Exits before readiness: 70 in use (pipe EADDRINUSE); 71 unsafe/unavailable (root, metadata,
  slot admission, other bind error); 72/73 dynamic import failure with/without the record
  acknowledged within 250 ms; 74/75 `serve()` rejection likewise. Cleanup (`app.close`,
  `container.stop`) completes before the record is written.
- Graceful exit after shutdown: `server.close` → `owner.dispose` → `writer.settle(250)` →
  `process.exit(0)`. Emergency (`abandoned`) exit unchanged (no flush wait).

## Native launcher

- `NativeProcess.Start`: stdin `CreateFile("NUL", GENERIC_READ, share RW)`, stdout = stderr =
  `CreateFile("NUL", GENERIC_WRITE, share RW)`; `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` = exactly those
  two; flags `CREATE_NO_WINDOW|CREATE_NEW_PROCESS_GROUP|CREATE_UNICODE_ENVIRONMENT|EXTENDED_STARTUPINFO_PRESENT`
  (unchanged). Returns `ChildProcess` (pid + process handle); thread handle closed immediately;
  process handle closed by `using` on every return.
- Before spawn (`Gateway.AdmitLogRoot`): root admission + `gateway.log.1`/`gateway.log` entry
  validation (71-equivalent refusal `destination-unavailable`), then legacy probe:
  `CreateFile(gateway.log, GENERIC_READ, FILE_SHARE_READ, OPEN_EXISTING, FILE_FLAG_OPEN_REPARSE_POINT)`.
  `ERROR_SHARING_VIOLATION` → retry every 200 ms until the existing release deadline
  (`StartupTimeoutSeconds` from the first probe), then `destination-in-use` without spawning.
- Outcome codes (launcher.log `code`): `destination-in-use`, `destination-unavailable`,
  `import-failed-logged`, `import-failed-unlogged`, `startup-failed-logged`,
  `startup-failed-unlogged`, `unknown-exit`, plus pre-existing closed refusals
  (`configuration-refused`, `foreign-listener`, `store-held`, `store-unverified`, ...). Unexpected
  exceptions → `unexpected` with fixed text naming the step.
- Rendered locations: rooted, no C0/C1/format/line/paragraph separator characters, ≤ 260 chars
  (leading `…` keeps the end). Fields: `Log folder:`, `Configuration:`; lock path inside the
  closed ownership text.
- `launcher.log` records: `{"time","pid","outcome":"refused","stage","code","childExit"?,"message","config","logFolder"?,"lock"?}\n`,
  ≤ 4096 bytes (locations dropped first if needed). Slots 262,144 B each; oversized history
  replaced; partial tail repaired; rotation close → `MoveFileEx(REPLACE_EXISTING)` → `CREATE_NEW`.
  Written only on failure (success is quiet).
