## Defects and limitations

No blocker, major or minor runtime product defect is confirmed for #321. One verification defect is confirmed outside the #321 diff:

**QA-321-01 — minor, inherited #320 test-fixture cleanup failure.** After building, run API coverage, then isolate `src/child-creation-restart.test.ts` with `-t 'kill 0ms'`. Expected: behavioral assertions pass, all owned processes exit, the fixture is removed and `afterEach` settles inside its existing 60-second bound. Actual: the test logs the correct one-child cardinality for all 24 parent visits, but `afterEach` at line 22 times out in `fixture.dispose()`. The same cleanup-hook timeout occurs in the full coverage run and isolated invocation. Evidence: [api.log.txt](api.log.txt), [child-zero-isolated.log.txt](child-zero-isolated.log.txt), exact commands in [gates.jsonl](gates.jsonl). These test/fixture files are unchanged relative to the #320 base. This prevents a clean API gate; the underlying cleanup mechanism is not fully isolated, and it is not classified as a load-only timeout or a #321 runtime regression. No fix was attempted.

The following host/evidence limits remain distinct from that finding:

1. **D-015, host limitation:** full infrastructure coverage has 7 native termination failures. A selected affected test also fails alone. [taskkill-diagnostic.json](taskkill-diagnostic.json) records `taskkill /T /F` returning exit 1, `ERROR: Access denied`, with the controlled child still alive; direct PID termination then succeeds. No test assertion or production termination implementation was changed.
2. **Native deadline/cancellation limitation:** the initial independent unbounded subprocess probes did not settle by 60 seconds. Later finite 5-second probes verify `SCRIPT_TIMEOUT` and `cancelled` classification after process exit, but do not establish timely process-tree termination. Both initial failures remain in [initial-results.json](initial-results.json).
3. **QA fixture corrections:** the initial non-script expression used `expression` instead of the schema's `jsonata`; its HTTP 400 is retained. The initial MCP probe used CommonJS require on an import-only package entry. Both probes were corrected without product changes. The initial no-reload counter counted frame navigation, including same-document URL changes; the corrected check compares `performance.timeOrigin`. A narrow-viewport probe initially collided with another QA listener; the corrected probe requires its own startup log and uses 5928. These are probe failures, not successful product regressions or retry-to-green suite results.
4. **Cleanup timeout persists in isolation:** the full API run and isolated zero-delay test both report `Hook timed out in 60000ms` in `afterEach`. This is the minor verification finding above, not a failed cardinality assertion. Both invocations remain failed.
