# Orchestrator dispositions for the #270 QA round 1 (2026-10-24)

The independent QA at `f2fce3ae` failed on two major and one minor finding. The orchestrator (Claude Opus 5.5) records these dispositions. Round 3 (`836d9ff6`, evidence in `docs/qa/2026-10-23-wp-f3-270/round-3/`) addressed them.

- **D1 (major as filed): an inference output-schema repair ignores the structured completion deadline.** Not a defect. The repair runs as a turn on the node's own harness session, so ADR-0051 leaves it to the node's `timeoutSeconds` and the run deadline. The QA brief wrongly expected the structured limit to apply. The help text invited that reading, so round 3 made the help, docs 05 and 06 and ADR-0051 say exactly which completions the limit bounds (LLM decision evaluations and output-transform repairs through the structured port). It also added a test that a schema repair fails at the node timeout (running at 999 ms, `INFERENCE_TIMEOUT` at 1,000 ms).
- **D2 (major): a stored loop without the new field cannot reopen.** Accepted. The same failure affected every definition stored before #243 (`runDeadlineSeconds`) on `main`; the owner's instance could not open any loop after the 2026-10-23 upgrade and was fixed by hand on 2026-10-24. Round 3 adds migration `0020_completion_deadline_defaults`. It writes the null defaults once into drafts, published versions, run pins, queued-event pins and admission intents, keeping authored values and damaged JSON as they are.
- **D3 (minor): structured repair timeouts omitted provider, model and effort.** Accepted; the timeout records them as LLM decision timeouts do.
- **Gate failures.** Infrastructure native process-control files (register D-015) and the API-client templates timing, in files #270 does not change; CI is the clean run.
- **Record edits.** Local profile paths in eight logs are written as `%USERPROFILE%`. The QA's own redaction script copy (`seal-evidence.mjs.txt`) had the local user name in its patterns, now written as `<user name>`.
