## Defects

### D1 — Major: an inference output-schema repair ignores the configured completion deadline

Reproduction, using the built API and FakeHarness:

1. Create and publish an inference loop with \`settings.structuredTimeoutMs: 500\` and \`output.schema\` requiring a number, with one repair attempt enabled.
2. Script the initial inference answer as \`bad\`, then script the same-session repair answer as \`7\` with an 1800 ms delay.
3. Start the run. After observing \`harness.resume\`, inspect the run 750 ms later.

The isolated recheck also left the run ${repair.delayed?.status??'unrecorded'} and its second run ${repair.queued?.status??'unrecorded'} beyond the deadline; explicit Cancel ended ${repair.cancelled?.status??'unrecorded'}. Its sample/cancel observation was ${repair.sampleAfterRepairObservedMs??'unrecorded'} ms after observing repair entry.

Expected: abort the overdue repair, fail with \`STRUCTURED_COMPLETION_TIMEOUT\`, release capacity and retain a resumable failure. Actual: the run remains \`running\` beyond the limit, then **succeeds** with the late repaired output. There is no typed timeout to resume. The guard covers StructuredPort repairs, but this schema repair uses HarnessPort.resume directly.

Evidence: [initial reproduction](inference-schema-repair.json), [QA script](api-cases.mjs.txt), [initial assertions/results](api-results.json), and [isolated recheck](schema-repair-isolated.json) / [script](schema-repair-isolated.mjs.txt). The recheck was run alone after other QA gates; its outcome is recorded without replacing the original.

ADR-0051 explicitly retains node/run signals for same-session harness repairs. That documented exception does not satisfy the assigned Case 6, which asks for an inference output-schema repair to fail at this limit. QA made no product decision or production change to resolve that mismatch.

### D2 — Major: a saved current-format loop without the new field cannot reopen

Reproduction:

1. Create a disposable current-format (format 4) draft using the built API.
2. Stop that API process. In its disposable SQLite store, remove only \`settings.structuredTimeoutMs\` from that draft's persisted definition. All other fields remain the current parsed values. This represents the stored shape from immediately before the additive field.
3. Start a new API process on the same store and request \`GET /loops/{id}\`; open the editor in Edge.

Expected: HTTP 200 and Unlimited. Actual: HTTP **500 RESPONSE_INVALID**; Edge shows “Could not load loop” and “the server produced a response that does not match its schema”. The contract successfully parses the identical stored definition and defaults the field to null, so this is not an old-format conversion request or malformed fixture.

Evidence: [stored before/after JSON](legacy-storage.json), [fixture writer](legacy-storage.mjs.txt), [HTTP and contract result](legacy-reopen.json), [browser screenshot](legacy-reopen-failure-390.png), and [capture script](restart-evidence.mjs.txt). Creating a new loop with the field omitted does pass; that does not establish reopening an existing record. ADR-0051 and the CHANGELOG promise no storage rewrite is needed for this additive default.

## QA methodology and corrections

The first API script incorrectly required provenance to equal a shape without the extra nullable classifierId field and treated the export envelope as definition instead of loop. Those were QA harness errors. The corrected checks were run only for those affected cases and passed; original failures were retained. Initial browser launch/capture scripts also had fixture/Fetch API assumptions corrected; final six viewport checks passed. An extra inspector capture originally looked for an exact standalone code label; its corrected capture removes that unsupported text assumption. The initial isolated-file selector read UTF-16 PowerShell logs as UTF-8 and selected no tests. Its decoder was corrected before any isolated rerun executed; the retained isolated-results.json records the actual one-file runs. The public Node MockTimers check emitted its documented experimental API warning; all four stored cases passed their outcome, terminal-count, abort and late-barrier assertions. No product failure was erased by those harness corrections. [Initial API log](api-cases.log.txt), [corrected API log](api-supplemental.log.txt), [initial browser log](browser-cases.log.txt), [completed viewport log](browser-cases-2.log.txt), and [extra capture log](browser-adversarial.log.txt).

The probe tolerance (450–2000 ms for a 500 ms deadline), 450/500/550 ms race offsets, 122000 ms Unlimited dwell and native watchdogs are QA engineering choices, not product defaults or owner-approved numeric policy. The Limited UI suggestion is 120000 ms; the actual contract default is null. No behavior docs, ADRs, CHANGELOG, generated references or production tests were modified by QA.
