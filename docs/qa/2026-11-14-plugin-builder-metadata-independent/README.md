# Plugin builder metadata independent QA

[PR #462](https://github.com/Jacob-J-Thomas/GraphGoblin/pull/462) A1 correction at product head `6fff3987068059ca5d9d798c61224bf5e555d711`, parent `934971a3f3dd0a17489883907127721c12752b18`, and main target `b3b5e1874a8252cc01c065d18fef42cbfbe075b4`. This is independent behavior QA for the preservation correction. Whole-repository gates, adversarial review, and the targeted Astra audit have their own records.

## Windows public CLI

The native CLI runner used Node v22.23.4, Windows x64 build 26300, and an NTFS fixture. It copied the actual compiled Codex CLI, assembler, manifest module, checked-in plugin assets, and runtime dependencies. The CLI source is unchanged across the correction. The runtime loaded the corrected tooling files from the copied package. Source hashes and clean Git state agreed before and after. All output paths resolved beneath that disposable fixture.

- A genuinely empty output root assembled and rebuilt with a different MCP entry. Path literals included spaces, brackets, an apostrophe, ampersand, dollar, exclamation, an accented character, and a Han character. The rendered MCP path matched exactly. Only the generated MCP configuration and its ownership marker changed on rebuild.
- A named ADS on each of an otherwise empty root, an owned root, a generated file, a generated subdirectory, and the ownership marker produced a refusal. The marker stream named `$DATA` had a zero-byte payload and still blocked replacement. Every refusal preserved the exact named-stream bytes and the entire ordinary directory inventory and file digests. Both the stream name and a randomly generated synthetic credential value were absent from captured CLI output. Generated ordinary files also passed the value check. The supplied synthetic value was never an actual credential.
- In a separate fault-injection case, a disposable PowerShell inspector answered both checks, then returned nonzero and emitted a synthetic value to stderr on completion. The actual public CLI refused replacement after quarantine, restored the same incumbent directory identity and digests, kept the value out of its output, and left no stage directory. The fixture verified that the directly spawned inspector had exited by CLI return. Restoring the exact inspector bytes allowed a normal rebuild.
- All 14 child invocations completed within the runner's 25-second watchdog. The product's Windows inspector uses a 15-second deadline, collects the direct helper and closes the builder's pipes. The implementation previously observed `Add-Type` spawn `csc.exe`. The independent check found no live recorded PIDs or matching fixture-process command lines afterwards. Native compiler or console descendant-tree termination was outside this test.

## Native macOS, separately observed by the coordinator

On arm64 macOS with Node v22.22.2, the exported builder refused xattrs on an empty directory, generated file, marker and generated subdirectory, plus a generated file with a resource fork. All five data hashes matched before and after; the stream-free control rebuilt with changed generated bytes. This exercised the real macOS filesystem and `/usr/bin/xattr` through the builder entry point. Native macOS CLI packaging and privileged metadata namespaces were outside the run.

The run preceded the commit and named its runtime inputs by hash. The two actually exercised modules matched the committed correction exactly. The copied auxiliary Windows and Linux files also matched, and the Mac path did not invoke them. The native run and copy both exited zero. ## Reproduce

Copy the Windows runner into an external disposable directory. Select project Node v22.23.4 and supply the built clean product checkout named above. The script makes its output fixtures beside itself and uses a copied CLI and helper.

```powershell
node '<external>/verify-344-win-metadata-independent.mjs' '<built checkout>'
```

The [Mac runner](mac/native-qa.mjs) runs in an external writable directory beside the two exact-hash runtime modules from the checkout. Node 22 and the OS's `/usr/bin/xattr` are used directly.
