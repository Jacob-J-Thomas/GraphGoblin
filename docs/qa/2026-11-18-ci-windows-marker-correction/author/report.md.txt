## Finding confirmed

The audit's claim holds on the original source. Three places in the type-discrimination path called `Object.hasOwn(SCHEMAS, x)`
without first checking that `x` is a primitive string. `Object.hasOwn` converts its argument to a property key.

| Place | Original line | Effect |
| --- | --- | --- |
| `rejected.recordType` field validator | 206 | Accepted any value whose key conversion names a record type. This includes `Object('child')`, `['child']`, `[['child']]` and `{ toString }`. |
| `Recorder#write` schema lookup | 711 | Converted a non-string type. If the conversion threw (e.g. `Object.create(null)`), the outer `catch` returned `null`, so no rejection was written or counted. |
| `Recorder#rejection` marker | 746 | Retained the original non-string value as `recordType`. |

`validateRecord`'s own `type` check (line 307) was already strict. `factKey` (line 332) is reached only with records that have
passed `validateRecord`. `summarize`'s `Object.hasOwn(cases, record.case)` runs only on validated records, where `case` is a
validated string or absent. The remaining `Object.hasOwn` calls use constant keys. None of these needed a change.

### Benign demonstration on the original source (`logs/01-demo-original.json`)

`scripts/demo-marker-contract.mjs` runs entirely in memory. The recorder has no descriptor, so no files are written. The
script first ran without the `Object.create(null)` input and the null-fields residual check. Both were added, and it was rerun
on the same original source before any change. Both runs exited 0, and log 01 is the second run.

- **Producer.** Boxed `'child'` became marker `recordType` of type `object`, serialized as `"child"` and accepted by the
  validator. The one-element array `['child']` kept its structure: `"recordType":["child"]`, accepted by the validator. An object
  with `toString` gave `"recordType":{}`. `Object.create(null)` returned `null`, so the record was dropped without a rejection.
  Genuine `'child'` and `'rejected'` gave the same strings. `'not-a-type'`, `42` and `null` gave `'unknown'`.
- **Validator.** It accepted boxed string, array, nested array and object-with-toString values. It refused `'not-a-type'`,
  `'toString'`, `1` and `null`.
- **Reader.** `parseObservations` returned `valid` for canonical lines whose `recordType` was `["child"]` or `[["child"]]`. It
  returned `invalid-record` for `"not-a-type"`, `1` and `null`.

## Correction

In `tooling/scripts/windows-launcher-evidence.mjs`, 4 lines are replaced and 2 are added: 6 insertions and 4 deletions
(`source/correction.diff`). One helper holds the rule:

```js
/** A primitive string naming a record type; any other value is never converted to a key. */
const isRecordType = (value) => typeof value === 'string' && Object.hasOwn(SCHEMAS, value);
```

It is used by the `rejected.recordType` validator (`value === 'unknown' || isRecordType(value)`), the `validateRecord` type check,
the recorder's schema lookup and the rejection marker (`isRecordType(type) ? type : 'unknown'`). Every string input behaves
exactly as before. Every non-string type is a counted `rejected` record with `recordType: 'unknown'`. The reader refuses any
`recordType` that is not `'unknown'` or a supported record-type string, so finalize rejects the whole observation file and does
not upload it.

`tooling/scripts/windows-launcher-evidence.test.mjs` adds three tests (+135 lines). Existing tests are unchanged.

- *A rejection marker names a requested record-type string, and unknown for any other value.* This covers a real recording
  through the public API. The genuine supported strings `child` and `rejected` are kept. `not-a-type`, a boxed string, an array,
  an object with `toString`, `Object.create(null)`, `42` and `null` each give `unknown`. Every marker validates, the file lines
  match, the closer counts all 9 rejections, and finalize gives `incomplete`/exit 1 with `valid` observations (`records-rejected`)
  and 3 uploaded files.
- *The reader refuses a rejection marker whose record type is not a supported string.* The validator accepts the supported
  strings (`child`, `cleanup`, `rejected`, `recorder-open`, `unknown`). It refuses non-string, inherited-name, wrong-case and empty
  values. Canonical streams with `child` or `unknown` parse as `valid`. Streams with an array, a nested array, an object, a
  number, null or an unsupported string are rejected whole as `invalid-record`.
- *Finalize never uploads observations whose rejection marker holds a structured record type.* A real recording has its genuine
  `child` marker rewritten to `["child"]`, the same in-test rewrite the existing closer-count test uses. Native `success` gives
  `incomplete`, and native `failure` stays `native-failed`. Both exit 1 with `rejected`/`invalid-record`, missing
  `observations-rejected`, and upload only `manifest.json` and `result.json`.

No numbered doc was changed. `docs/10-testing-and-quality.md` already states that a record holds closed enums only and that
invalid records become `rejected` records. The correction makes the code conform to that contract without changing it.

## Residual limits and observations

- The reader checks shape and consistency, not authenticity, as `docs/10` already states.
- No hosted run has exercised the corrected head yet. Current-head hosted CI, independent behaviour QA and the D-035 correction
  review remain with the root. The local native `pnpm test:windows-launcher` was not run. Every recorder call in
  `windows-launcher.acceptance.mjs` passes a literal string type, so the native recording path is unchanged.
- Out of scope and not changed: `recorder.record('<type>', null)` returns `null` and writes or counts no rejection, because
  `Object.hasOwn(null, …)` on the `fields` argument throws into the `#write` catch. This is pre-existing and concerns `fields`,
  not `recordType`. Before and after are shown in `residual` of logs 01 and 04. The acceptance suite always passes object
  literals. It is left for the root to disposition.
- Full `pnpm check` and other packages' gates were not run. Tooling is JavaScript and has no typecheck task.
- A concurrent folder `../pr508-marker-independent-qa/` appeared in the QA root during this work. It was neither read nor
  modified.
