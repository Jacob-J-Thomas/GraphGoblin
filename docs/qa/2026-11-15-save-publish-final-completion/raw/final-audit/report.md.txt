| Unknown outcome and retry | Uncertainty is retained separately from mutation feedback and scoped to its originating editor load. Local refusals leave it intact. A failing actual retry GET grants no POST; a successful divergent readback records conflict before a later held-input refusal can erase the evidence. A healthy pending acknowledged draft permits one fresh POST after the GET. Known API refusals remain failures. |
| Conflict and device preservation | Divergence enters the established recovery flow only for the same generation still on the acknowledged token (`usePublish.ts:214-227`). | Fresh list/detail and async errors | `refreshLoopAfterWrite` (`queries.ts:291-312`) cancels exact pre-write reads before invalidating them, including cold reads with no prior data. TanStack's normal error state retains failed refetches; this helper's promise does not become an unhandled read rejection. |
| Dependent validation | Publication cancels other loops' in-flight validation before marking it stale with no forced refetch. The publishing loop's validation keys are excluded. No new backend API, conditional publish contract, migration, stored/export/device format, provider behavior, dependency or architectural layer is introduced. Imports remain through package boundaries. The only new formatting exclusion is raw QA TSX archives, preserving historical bytes without weakening product formatting or coverage. |
