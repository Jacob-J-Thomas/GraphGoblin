**Change (lines 216–237 of the test file only)**
- **Deadline:** an 8 s deadline now starts when the request is sent, matching the existing 8 s client timeout. Every wait in `abandon` is raced against it: arrival at the hold, the health/current reads, the close and the settlement.
- **Cleanup on timeout:** the existing `finally` destroys the history client and releases the hold. A new outer `finally` clears the deadline timer.
- **Unchanged:** the client's `setTimeout(8_000)`, the 20 s Vitest limits, every assertion (the order of recorded steps, close-without-finishing, settled = 0, operations, no sends, no errors), the yield test body and its cleanup, the fixture (300 events, 128-row pages, loopback port 0), the provider-disabled `createTestApp`, and all production files. `run-history.ts` was not touched. As instructed, I didn't hash it.

**What happens when a wait stalls (from reading the code, not a run)**
- **Health or current read hangs:** the deadline rejects at most 8 s after the request started. `abandon` destroys the history client and releases the held callback, which then runs. The yield test's `finally` restores `setImmediate` and `events.read`, releases again, and destroys only the test's own agent. That ends the stuck read sockets, and their errors are already caught.
- **Close or settlement hangs:** the same cleanup runs. If settlement hangs, the callback has already been released.
- **Deadline fires before the hold is reached:** nothing is held. The original functions are restored, and any later hold passes straight through because the release has already happened.
- **Total time:** the test body ends within about 8 s plus synchronous cleanup, well inside the 20 s test limit. The test-local `Agent` and the abandoned request are the only HTTP clients destroyed.
