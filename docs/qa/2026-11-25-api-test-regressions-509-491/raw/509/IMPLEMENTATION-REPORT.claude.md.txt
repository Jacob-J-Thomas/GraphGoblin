## What changed (unstaged, only the two test files)

**`apps/api/src/testing/api-port.test.ts`**
- **Ollama override:** the existing invalid-`GG_PORT` subprocess call now passes `GG_OLLAMA_ENABLED: 'false'` explicitly. Every original assertion, skip rule and timeout is unchanged, and the shared subprocess helper is untouched.
- **New concurrency test.** It first reserves a port normally, which keeps the other test workers off it. It then switches to a fresh claim folder of its own (under the test run's port folder) and starts 8 real `reserveApiPort(port, 1)` calls at once, then waits for all of them to finish. It checks that:
  - exactly one call gets the port and the other 7 are refused with "Ports are reserved by tests or in use";
  - the claim folders show one live owner;
  - after release, a second round of 8 again produces exactly one winner, in a new generation.
- **Stale release:** the old winner's second release, run alongside 8 more claimants, succeeds without effect. All 8 are refused and the replacement stays held.
- **Cleanup:** the test checks that both releases leave the expected "released" markers and that its own folder is removed afterwards. Claiming itself is not mocked; the real filesystem decides the winner.

**`apps/api/src/testing/api-port-platform.test.ts` (new, 8 tests)**
- These tests temporarily override `process.platform` and record every listen attempt, then call the real public `reserveApiPort` on one held port.
- For both `win32` and `darwin`, the exact attempts are 127.0.0.1, then 0.0.0.0, then ::.
- The `linux` control attempts 127.0.0.1 only, including when 0.0.0.0 would report a conflict.
- For each of win32 and darwin, a simulated conflict on just 0.0.0.0 or just :: makes the port refused.
- Hosts without a simulated conflict still do real binds.
- Every override is restored right after the call, and a check after each test confirms nothing was left changed.
- The file states that these are controlled observations, not native OS evidence. Native listener behaviour stays in `api-port.test.ts`.
