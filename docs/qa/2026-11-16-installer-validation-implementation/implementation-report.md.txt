## Implementation

- The installer discovers and probes Node with a bounded `--version` call before output
  work. It uses fixed diagnostics, with a validated version triple eligible for display.
- Windows handle identities protect the source link and all final output pairs across
  path aliases, junctions and hard links. Existing targets are rechecked at publication.
  Each output is staged on its destination volume.
- Native `--validate-install --config <stagedConfig>` validates or refuses before normal
  launcher startup. It runs for both shortcut policies. Staged link creation records the
  final EXE, final config argv, working directory, icon and AppUserModelID.
- The publisher records each attempted entry before actual replace or move. Its rollback
  inspects the failing entry and backup as well as earlier successful entries. It verifies
  restored managed files and retains the stage folders when it cannot verify recovery.
- The permanent Windows PowerShell 5.1 group performs a real install with native links,
  decodes each link's final target/config/AUMID, then challenges reserved `-NoShortcuts`
  config, hard-link collision and missing-Node diagnostics with exact byte readback.
  The 17 existing native cases retain their bytes.
