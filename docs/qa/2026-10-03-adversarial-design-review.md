# Adversarial design and behaviour review — 2026-10-03

Reviewed the engine, domain operations, API, triggers, SQLite stores, schedulers, process runner, and Codex adapter against the numbered design documents and accepted ADRs. This is a bounded behaviour review, not a claim that every interleaving or deployment is safe.

Eight defects were fixed locally; eight remain open: **six major, two minor, no blockers**. Of the 19 requested invariant groups, eight hold in the exercised cases, four have fixes, six have open defects, and one has an environment-limited result. Several groups contain both passing cases and defects; the table uses the least conclusive result.

## Evidence and method

The four new `adversarial.test.ts` files contain **93 cases: 84 active cases and nine TODOs**. Eight TODOs preserve executed failing reproductions for open defects; the ninth preserves the attempted Windows process-tree probe. Engine tests use `createTestEngine` and the existing fakes; API tests use `createTestApp`; infrastructure tests use in-memory SQLite and the existing forks-pool configuration. The real Codex adapter is exercised with an SDK stream double, without contacting Codex.

Crash tests freeze the old executor at a particular asynchronous boundary and create a replacement manager over the same stores. Calling `stop()` alone is insufficient to simulate process death: it deliberately lets active nodes finish. These tests model selected durable-write gaps, not an OS power cut or corruption of a SQLite WAL.

Larger fixes remain TODOs with their reproduction immediately below them. No existing test, threshold, or coverage exclusion was weakened. The small fixes and corresponding numbered-document clarifications are present in the working tree on `codex-adversarial-design`, based on `d8954d8`. The requested commits could not be created: Git was denied permission to create `.git/worktrees/codex-adversarial-design/index.lock`. ## Open findings

### ADV-004 — latest subloop references change during an existing parent run

**Severity: major.** Reproduction: publish child version 1; start a parent that waits for input before invoking that child; publish child version 2; provide input. The resulting child pins version 2. The test expected version 1, as promised by domain-model versioning and ADR-0009's “new parent runs only” rule.

The suspected cause is resolving `latest` only when the subloop handler starts its child, rather than persisting a resolution with the parent invocation. Fix by resolving and persisting the parent's referenced versions at run creation, including a policy for recursively referenced graphs, and passing that version ID into child creation. Files: `packages/engine/src/run-manager.ts`, `handlers/subloop.ts`, `ports.ts`, contracts for persisted run metadata, and SQLite/fake repositories. Keep historical version retention consistent with these references. Regression: `packages/engine/src/adversarial.test.ts`, ADV-004 TODO and comment.

### ADV-007 — a native JSONata regex bypasses the expression timeout

**Severity: major.** Reproduction: evaluate `$match("` followed by 32 `a` characters and `!", /^(a+)+$/)` with `timeoutMs: 10` in a disposable Node subprocess. A separate 2500 ms watchdog had to terminate it; no expression deadline error arrived. The commented test includes the source-loader bootstrap needed to run the domain module without a build.

`packages/domain/src/expression.ts` checks elapsed time at evaluator entry/exit hooks. Those hooks cannot interrupt a synchronous native RegExp call. The same architecture cannot enforce a hard memory ceiling. Execute untrusted evaluation in a worker/process with an external deadline and bounded input/output, or restrict the supported expression/regex language with a documented compatibility decision. Preserve the pure domain boundary by introducing the appropriate evaluation port rather than adding I/O there. Involved files: `expression.ts`, `mutations.ts` for related regex operations, `packages/engine/src/ports.ts`, and an infrastructure implementation. Regression: domain ADV-007 TODO. Liquid resource limits need an explicit separate policy; disabling filesystem access alone is not a CPU/output bound.

### ADV-008 — authenticated keys bypass read scopes

**Severity: major.** Reproduction: enable required-key mode; create a key with only `runs:write`; `GET /loops` returns 200 instead of 403. The commented reproduction enumerates additional resource collections. Authentication succeeds, but the private GET handlers generally do not call `requireScope`.

Apply a documented read-scope mapping consistently to list, detail, export, event-stream, settings, metadata, and validation endpoints; authenticate and authorize before reading data. Retain public health/docs/hooks semantics and local trusted mode. Files: `apps/api/src/plugins/auth.ts`, `routes/loops.ts`, `routes/runs.ts`, `routes/settings.ts`, `routes/system.ts`, `routes/triggers.ts`, and API docs/client contract snapshots if scopes become OpenAPI metadata. A centralized route policy avoids another collection/detail discrepancy. Regression: API ADV-008 TODO. This is data-access isolation between scoped keys, not a demonstrated plaintext-secret disclosure.

### ADV-009 — ID routes do not validate ULIDs

**Severity: minor.** Reproduction: authenticated/trusted `GET /loops/not-a-ulid` returns 404, not a typed request-validation 400. The TODO's table covers loop/run detail, version/export-related paths, events/thread, and API-key deletion.

The path schemas use unconstrained strings. Reuse the contracts' ULID schema for true resource IDs across all routes; keep node names, signal names, secret names, model names, and opaque endpoint tokens as their respective non-ULID types. Files: `apps/api/src/routes/*.ts`, shared API parameter schemas, and generated API-client artifacts. Regression: API ADV-009 TODO. No SQL injection was demonstrated.

### ADV-011 — timer delivery can be lost permanently in a crash gap

**Severity: major.** Reproduction: park a duration wait backed by `SqliteTimerStore`; stop its manager; advance past the deadline; let `TimerService.poll()` remove the due timer before a manager handles it; start a replacement manager and poll again. The run remains waiting with no timer. This models a crash after deletion and before the wake command.

`TimerService.poll()` deletes before dispatch, while `RunManager.recover()` assumes persisted timers will wake waiting runs and does not reconstruct missing timers. Implement durable delivery acknowledgement or reconcile waiting timer/deadline specifications at recovery, using idempotent wake identities so competing recovery/delivery does not duplicate execution. Files: `packages/infrastructure/src/scheduler/timer-service.ts`, `sqlite/timers.ts`, `packages/engine/src/run-manager.ts`, and `ports.ts` as necessary. Regression: infrastructure ADV-011 TODO. Cover timeout timers as well as duration/heartbeat wakes.

### ADV-012 — concurrent cancel requests duplicate their audit event

**Severity: minor.** Reproduction: park an input run and call `Promise.all([manager.cancel(id), manager.cancel(id)])`. The log contains two `run.cancel_requested` events. The separately exercised inference case still aborts once and terminates once.

`cancel()` reads `cancelRequestedAt`, then writes it and appends the event without an atomic claim. Add an idempotent cancellation-intent repository operation, with its event committed atomically or an equivalent durable dedupe token. Files: `packages/engine/src/run-manager.ts`, `ports.ts`, `testing/fakes.ts`, and `packages/infrastructure/src/sqlite/runs.ts`/`events.ts`. A status-only compare-and-set against `running` is insufficient because marking intent deliberately preserves that status. Regression: engine ADV-012 TODO.

### ADV-015 — a fast child can finish before its parent parks

**Severity: major.** Reproduction: allow two concurrent runs; pause the parent's transition to `waiting/child` until the minimal child is already succeeded. After releasing that transition, the parent remains waiting forever. The test controls this legal schedule through the repository transition boundary.

Child completion checks the parent's current waiting state. If the parent is still running, the notification is discarded; the later park does not reconcile the completed child. Atomically register the parent wait before child execution, or reconcile the child's terminal outcome immediately after parking and during recovery with idempotent delivery. Files: `packages/engine/src/run-manager.ts`, `handlers/subloop.ts`, and run repository ports/implementations. Test success/failure/cancelled children and parent restart, not only the successful fast path. Regression: engine ADV-015 TODO.

### ADV-016 — a completed node executes again after a cursor-update crash

**Severity: major.** Reproduction: run an inference node and freeze `runs.update` when it advances `currentNodeId` to the exit, after `node.finished` is already durable. Replace the manager on the same stores. The harness starts twice and the same node receives two completion events; the test expected one each.

The event append, saved thread, and durable execution cursor are separate writes despite the execution document's transactional invariant. Recovery trusts the old cursor even when the event log records a completed node. Introduce an atomic repository boundary for node completion, patch/projection, and cursor/status advancement, or a carefully specified replay-derived cursor with idempotent side-effect handling. Include accepted wake and terminal-transition crash gaps in that design. Files: `packages/engine/src/run-manager.ts`, `ports.ts`, `packages/infrastructure/src/sqlite/runs.ts`/`events.ts`, schema/migrations if needed, and the fakes. Regression: engine ADV-016 TODO. ADV-003 repairs the thread projection; it does not close this execution-cursor gap.

## Design observations (not additional defects)

- The current target is one local API process. Two scheduler objects sharing one SQLite store both fire the same slot in the test. SQLite's in-process mutex, scheduler `busy` flags, the event bus, and webhook rate tracking do not provide a distributed lease. Hosted scheduler leases are already post-1.0 work in the security document.
- Recovery legitimately logs a new `node.started` with an incremented attempt for an interrupted turn. “No duplicate starts” should mean no duplicate execution of the same attempt or an already completed node, not forbidding a documented retry. `stop()` is graceful, not a crash primitive.
- Resumable `failed` runs intentionally leave their failed status when the operator resumes them. Non-resumable failures and failure exits are now rejected. A blanket “terminal statuses never transition” assertion would contradict the documented repair-and-resume workflow.
- External return delivery occurs after the run outcome is committed. A delivery failure is logged and does not rewrite successful execution; a terminal SSE consumer may need a later event-log read to observe delivery events. Caller return is an internal value handoff, and result variable names are map keys rather than implicit nested JSON pointers.
- Negative/nonnumeric SSE cursors fall back to zero; beyond-last cursors yield no past events, and terminal subscriptions close. These inputs are not currently validation errors.
- A successful Codex `turn.completed` with usage but no final assistant text produces an empty result with usage. A stream with no terminal event rejects. Those are distinct cases.
- Liquid's no-filesystem adapter prevents include/render/layout reads. It does not specify a wall-clock, memory, or output-size ceiling. JSONata's current hook-based deadline is cooperative; ADV-007 shows why it cannot serve as a hard sandbox boundary.
