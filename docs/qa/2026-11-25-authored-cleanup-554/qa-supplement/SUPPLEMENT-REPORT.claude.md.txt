## Evaluator text (resolved; not a #554 defect)

The policy files are unchanged:
- mutate.ts, common.ts, failure-publication.ts, errors.ts, event-validation.ts and docs/04 are byte-identical to their baseline blobs.
- None appears in run-check's enforced changed-path set.

How the mutate node publishes evaluator text:
- It passes only an ordinary mapper and no `mapFact`. So `rethrow` sends domain-class errors there, including target faults.
- That mapper publishes `boundedAuthoredCause(error.message)` in both `failure.message` and `details.cause.message`. This is exactly what tests 80–108 expect.
- Other thrown values come back unchanged and become INTERNAL_ERROR with fixed copy and a private diagnostic.
- Bounds:
  - the cause is limited to 1000 characters;
  - the message is limited to the schema maximum via `boundedFailure`;
  - the event and the run record receive the same bounded failure.
- Truncation bounds length only. `$error(secret)` in a Context mutation still publishes the secret up to that bound.

This is the pre-existing Context mutation contract. docs/04 promises a "bounded cause", and docs/05 puts mutate under "Other failures carry no boundary".

The no-evaluator-text claim covers only the newly typed sites (`evaluateAuthored`, `predicateAuthored`, `renderAuthored`), which produce fixed copy.
- In run-manager, their failures are logged without `errorDiagnostic`.
- Unclassified `valueAt` rethrows fall under the Bug row.
- A genuine target fault reaches `mapFact` and gets fixed "target is invalid" copy. The control shows exactly `[{kind:'target'},2,'coerce']`.

I found no contradiction. Whether Context mutations should also suppress evaluator text is a wider policy question outside #554.
