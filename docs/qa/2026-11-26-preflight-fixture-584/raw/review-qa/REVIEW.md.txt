## Do the fixtures still exercise what the test names claim?

- **Pending-migration store.** `pendingFixture` still migrates through the real shipped prefix to `0026_chat`, asserting 3 later migrations, and seeds the given rows. Each test asserts `WARN Database 3 migration(s) pending`, `preMigrationCatalog == rows` and an unchanged migration ledger. Startup then reaches `pendingMigrations() == 0`. Applying every shipped migration instead (M05) makes all six #546 pending tests fail on the "3 migration(s) pending" line.
- **Unsupported-format store.** The store is format 4 with `format_version = 3` written in place, and the test asserts `FAIL Database The store is format 3; this build reads only format 4` and startup `STORE_UNSUPPORTED {foundFormat: 3}`. Removing the downgrade (M04) makes the unsupported case fail with exit 0. Replacing TRUNCATE with PASSIVE (M07) fails at the fixture's all-zero gate before the copy. A pre-existing target (M08) fails with `EEXIST`, so the exclusive copy is in force.
- `stagedStore`'s new strict checkpoint gate on the pending path is a strict addition. The old `pendingFixture` ignored the checkpoint result. Switching to PASSIVE (M06) fails 24 of 31 tests at that gate, every test that builds a store through `stagedStore`.
