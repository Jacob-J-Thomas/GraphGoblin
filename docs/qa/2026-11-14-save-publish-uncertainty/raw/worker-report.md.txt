The defect is fixed: after a lost publish reply whose check also failed, the next Publish now checks the server first, even if a Publish was refused in between. Tests, a forced build and the copied native diagnostic all confirm it. This doesn't make #237 complete: broader QA, parent integration, current CI, the two reviews and owner acceptance are still open.

**Fix.** The fact that an earlier request's outcome is still unknown is now kept separately from the latest attempt's result, so a refusal no longer erases it. It is tied to the editor load (loop and generation). It is set when a request gets no answer and its check also fails. It stays set through:
- held-input refusals
- failed-save refusals
- refusals met when the queue reaches the attempt
- further failed checks

It clears only when a check of the server answers or the server answers a request. Reads the editor makes in the background do not clear it. The refusal still shows as **Publish failed**. Nothing else changed in behavior or wording. Four files changed (`usePublish.ts`, `EditorPage.publish.test.tsx`, docs/09, CHANGELOG); `useAutosave` and all other paths are untouched.
