## Systems touched and how each was tested

1. **Reset planner sidecar selection** (`sidecarEntry`, `nativeChoice`, configured/stored check): through the built CLI `node apps/api/dist/main.js --reset [--yes --data-dir]`.
   - Each run used the default private-copy store reader and a real seeded format-3 database plus committed WAL (the repository seeder).
   - Fixtures use real NTFS hard links, case and Unicode aliases, look-alikes and copies.
2. **Root Keeps and the private manifest pair exception:** checked from the same runs.
   - Dry-run and confirmed Removes and Keeps are compared with each other and with expectations.
   - Disk state is checked independently: names, file IDs (lstat bigint dev:ino), nlink and SHA-256.
   - `fsutil hardlink list` gives a kernel witness of every name of each linked file, before and after.
3. **Ownership-role overlap refusals, held and unverifiable locks, strict collisions and special files:** through the built CLI.
   - Live locks are held by a separate process through the built lock module.
4. **Refusal branches NTFS does not produce on demand:** through the built `runResetCli` in-process, with the real default reader.
   - Covered: wrong-parent, unlisted and failing native answers; locked-replan ambiguity; configured/stored short-name disagreement.
   - Exactly one query is controlled per case: `fs.realpathSync.native` for one path, or an lstat alias for a simulated `GRAPHG~1.DB`. Each such case is labelled controlled.
5. **Docs and CHANGELOG:** read against the observed behaviour (REVIEW.md R3).

## What the cases establish

- **Wrong-entry removal is gone:**
  - Root and nested WAL, SHM and journal, with an earlier (`00-unrelated`), later (`zz-unrelated`) or no other name: the confirmed reset removed exactly the configured sidecar name in all 18 rows.
  - Removes was identical in the dry run and the confirmed reset.
  - The dry run changed no name, ID, nlink or byte.
  - The native NTFS listing put `00-unrelated` before and `zz-unrelated` after the sidecar, as each case asserted.
- **The owner's other link keeps its bytes and identity:**
  - Every surviving link kept its SHA-256 and file ID, and its nlink dropped by exactly one (2→1; 4→3 in the three-name case).
  - `fsutil hardlink list` lists only the surviving name afterwards.
  - Root-level links are listed under Keeps as `another name for <sidecar>; the file stays under this name`. Nested siblings and links inside kept directories get no row and survive.
- **Unrelated data unchanged:** `master.key`, `notes.txt` and the kept `workspaces/not-a-run` are unchanged. The recorded run workspace, database and WAL are removed. No `gg-reset-store-*` residue remains in the reader TEMP after any call.
- **Non-exact spellings (real NTFS):**
  - With the WAL listed only as `GRAPHGOBLIN.DB-WAL`, the reset removes that entry and keeps another link.
  - The real native final path answered `GRAPHGOBLIN.DB-WAL` (C0).
  - A configured `GraphGoblin.db` and a configured Unicode `οσ-1.db` (listed `ΟΣ-1.DB`) both agree with the stored spelling and keep the other link.
  - A Kelvin-sign look-alike is kept as a distinct file. A same-bytes copy is "not part of the store".
- **Overlap with reset ownership roles refuses before any change:**
  - Sidecar = data-directory lock or database lock (root and nested, holding a dead-PID record). The refusal names both.
  - Sidecar = `workspaces`, `artifacts` or `chat-audio`. The refusal names both.
  - Sidecar = `graphgoblin.lock.reclaim`: the earlier lock gate refuses with "reclamation guard is not a physical directory…", which does not name the sidecar (REVIEW R3).
  - Sidecar = lock with no valid record: the earlier "could not be verified" refusal.
- **Held locks (a live process holding the lock through the built lock module) refuse with the existing held diagnostic:**
  - data-directory lock;
  - database lock;
  - a sidecar name that is a hard link of the live lock file.
  - The holder then released normally (`release:removed`).
- **Special files:**
  - A junction at the exact SHM name, or listed only under another WAL spelling, refuses as a link.
  - A directory at the journal name refuses.
- **Strict collisions:**
  - Another SQLite part, an entry in a removed run workspace, `artifacts/` or `chat-audio/`: "would list … twice".
  - A non-run file directly under `workspaces/`: "would both remove and keep".
- **Controlled refusals:**
  - Wrong parent, unlisted name, EPERM and ENOENT from the native query: refuse with exact text in the dry run and the confirmed reset, nothing changed, store never read.
  - Locked-replan ambiguity refuses with no Removing marker. The store is read once, and the locks are released; the stale-lock variant reports what was reclaimed and released.
  - `GRAPHG~1.DB` vs `graphgoblin.db`: writer-only, reader-only, two files and two hard links each refuse before any store read. The agreeing case reads the stored spelling.
