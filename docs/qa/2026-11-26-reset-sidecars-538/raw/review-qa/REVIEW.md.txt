**R1. Kelvin escape claimed but absent.**

- `reset-sidecars.test.ts:323-325` says the Kelvin sign is "Escaped, so no editor or formatter can turn it into an ASCII `K`".
- Line 325 actually holds the literal U+212A (bytes `E2 84 AA`).
- The author report also says the line is `'\u212A.db-wal'`.
- Behaviour is correct, because line 326 asserts it differs from ASCII.
- Fix: write `'\u212A.db-wal'`, or correct the comment.

**R2. The order-matrix test drops the refusal text when the exit code is wrong.**

- `reset-sidecars.test.ts:214-215` and `:234-235` assert `code` before `err`.
- This lost the diagnostic in the R4 failure.
- Fix: assert `{ code, err }` together, as the refusal cases already do.

**R3. Guide over-claims "naming both" for guards.**

- The new paragraph in `docs/guide/08-offline-upgrade.md` says the reset "refuses, naming both, when a sidecar is the same file as one of its lock files or guards".
- For a guard name, the earlier read-only lock gate refuses first: `Store ownership could not be verified (reclamation guard is not a physical directory with one valid owner marker): …graphgoblin.lock.reclaim`. That message does not name the sidecar (QA case `R-wal-as-datadir-guard`).
- The CHANGELOG and ADR wording is accurate.
- Fix: drop "or guards", or say a guard name is refused earlier by the lock check.

**R4. One unexplained intermittent failure.**

- In one of two runs of `vitest run src/reset/`, `reset-sidecars.test.ts > root -journal, other hard link: none` got confirmed exit 1. Its stderr was not captured (R2).
- The record is kept verbatim. Everything after it passed:
  - the single labelled diagnostic re-run;
  - the same scenario 6 times through the built CLI (three journal cases);
  - 320 source replays, 240 of them alongside real private-copy reads in a shared TEMP.
- Cause not established:
  - A cross-file `cleanupStaleStoreCopies` race in the shared temp was tested and not reproduced.
  - A transient Windows sharing error under concurrent machine load (another worker's coverage run) is not excluded.
- It is not the #489 signature: no tree-fixture rename EPERM occurred.
- Fix R2 so the next occurrence is diagnosable. Open an issue only if it recurs, using #489's recording rules.

**R5. Windows-only native proof runs in no CI.**

- The `windows-launcher` CI job runs `db.test.ts`, `config.test.ts`, the launcher suite and `main.test.ts`, but not `src/reset/`.
- So the win32 native final-path cases are proven only on local Windows runs (author's and this QA's), and the ubuntu coverage gate leaves the win32 branch of `nativeChoice` uncovered.
- API coverage on ubuntu with this change has not been measured here.

**R6. `listedName` keeps #538's root cause for reserved roots.**

- `listedName` (still used for `workspaces`, `artifacts` and `chat-audio`) takes the first listed name with the same identity.
- Built-CLI dry run: with a regular file `workspaces` hard-linked to `notes.txt`, Keeps shows `notes.txt — a file, not a directory` and omits `workspaces` (`oos-reserved-root-listedname.log`).
- No wrong removal is possible (only directories are removed, and directories cannot be hard-linked). The manifest label is wrong.

**R7. `master.key` as another name of a removed sidecar.**

- A `master.key` that is a hard link of a removed sidecar is kept, but labelled `another name for <sidecar>` rather than with the secret-store reason (the author's caveat 2).
- Its bytes survive, and the configuration is pathological.
