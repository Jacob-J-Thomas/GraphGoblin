**What I checked:**
- **The fix.** Node keeps the alias spelling in `argv[1]` but loads the module from the real path, so the old check never matched through a link. A small probe in the review folder confirmed this on Node 22.23.4. The new check resolves both paths with the same native call, so they match through a link and two different files can never match. If resolution fails, the helper stays silent and the launcher refuses as before. The fingerprint, store-state and write behaviour are unchanged. Launches through the alias and the real path can't race, because the launcher's locks are keyed by data directory and port.
- **Built-helper test.** On the old build it failed exactly the three intended checks; on the candidate it passed 2/2. Both runs used the same test bytes as the published file.
