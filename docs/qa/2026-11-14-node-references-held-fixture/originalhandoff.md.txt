## Bottom line

1. **Fixed: the held-input test now passes, and so do all five `rename-references` cases (5/5).** The only change is the fixture's setup of the unfinished Variables text. No product code is touched.
2. **Cause (root's finding, confirmed in code):** the old `code()` helper did select-all, `Backspace`, then `insertText('[1, ')`. In `apps/web/src/forms/fields/json.tsx`, `validateText` treats empty text as valid (`text.trim() === ''` gives `value: undefined`), and the field's `onChange` then calls `onChange(undefined)` (I read that path in `json.tsx`; I did not read the record row's handling of `undefined`, but the retained trace shows the variable gone). So the `Backspace` alone removed `variables.key` from the draft, and autosave (`AUTOSAVE_DELAY_MS` = 600) saved `variables: {}` before any rename. The text typed afterwards is invalid, so it is held and never changes the draft, which left `{}` as the saved value. This was a fixture defect and not a rename regression.
3. **Evidence of the sequence in a real Edge run** (`held-variable-trace-readback-pass.json`, same extraction method as root's script):
