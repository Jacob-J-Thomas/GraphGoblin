# Independent baseline QA

Windows, Node 22.23.4, built API and web shells at base `b3b5e1874a8252cc01c065d18fef42cbfbe075b4`. The [replay](qa-helper-diagnosis.mjs) invokes the built helper and compiles the baseline native executable into a disposable worktree directory. It uses a loopback ephemeral port and a new store fixture. Only the timed PowerShell executable is substituted in the synthetic cases. The [raw output](qa-helper-diagnosis.json) records subprocess exit codes, elapsed wall time and probe activity.

| Probe                                                                                                  | Outcome                                                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Real WMI, four records scoped to a live disposable test PID with a different Windows creation identity | The ownership helper returned `free` in 3,198 ms.                                                                                                                                                        |
| Synthetic WMI, four separate queries each returning a different creation identity after 4.1 seconds    | The actual ownership helper returned `free` in 18,121 ms. Both data-directory and database guards and lock files retained their original bytes.                                                          |
| Same synthetic ownership path through the native baseline, configured startup allowance 60 seconds     | The launcher exited 1 in 16,612 ms. The generic helper timeout occurred after the initial identity check and during the fourth ownership query. No gateway was started.                                  |
| Synthetic WMI with a first query longer than the 5-second foreign query limit                          | The actual helper returned `held` in 6,435 ms, named the data-directory guard, and reported the 5,000 ms WMI timeout. The later ownership records were not queried. Fixture bytes matched the originals. |

Measured across four sequential warm repeats, the identity helper took 1,369–1,647 ms and the empty-store ownership helper took 1,382–1,731 ms. Loading the SQLite barrel in a fresh Node process took 1,343–1,515 ms, compared with 1,190–1,308 ms for the SQLite database module directly and 290–409 ms for the configuration, lock and canonical-path modules. These measurements show import overhead on this host and a reproducible timeout with valid slow ownership probes. The original incident log identifies neither the helper stage nor the earlier timings.

To replay, select the project Node 22 runtime, build the documented baseline and run `node docs/qa/2026-11-13-launcher-timeouts/qa-helper-diagnosis.mjs` from the repository. The isolated fixtures are retained under `.tmp/qa-helper-fixtures-*`.
