## Design critique and bounded corrections

The independent-lane design and typed projection direction were implemented as accepted. Items
1 to 6 below are corrections or hardenings within that direction; 7 to 11 are flagged risks or
limits, with no change made.

1. **Correction (found by the real native run): the required-observation rule.** My first rule
   required child-process records for every case. Lock contention starts its contenders with
   `spawn`, not `execFile`, so a fully passing hosted run would have been `incomplete` and failed
   the Windows job. The first local bundle shows `lock-contention-children` in its `missing` list
   (`local/candidate-positive/`, kept as the record of the defect). The fix makes that case's
   requirement its three single-owner contention trials. The unit-test model now mirrors the real
   suite, and the final bundle (`local/candidate-final/`) no longer lists it.
2. **Correction: the evidence variable.** The contract passes the path through a test-specific
   variable. Several suite children inherit `process.env` (compiler, `whoami`/`icacls`, the
   installer's launcher fixture). The recorder therefore removes `GG_TEST_WINDOWS_LAUNCHER_EVIDENCE_DIR`
   from its own environment before any child starts. A real `node --test` subprocess test shows a
   child cannot see it. The launcher already strips `GG_*` from gateways.
3. **Hardening: write-once files.** Nothing is rewritten in place. `init` writes `manifest.json`,
   the suite creates `observations.ndjson` and `finalize` writes `result.json`, each with
   `CREATE_NEW` (`wx`) plus an `fstat`/`lstat` identity and single-link check. A planted file,
   hard link or junction at any name is refused, never written through. Tests: `exists` refusal
   with the outside target unchanged.
4. **Hardening: canonical bytes.** Parsing and then validating JSON would let a duplicate key carry
   unvalidated text past the check (`{"type":"<canary>","type":"child",...}`). `finalize` requires
   each line to equal the recorder's own serialization of the validated record, and otherwise
   rejects the whole file. Rejected observation files are never uploaded.
5. **Hardening: exact upload paths.** `upload-artifact` treats every `path` line as a glob. The
   evidence path is validated free of `* ? [ ] { }`, newlines and a leading `!`, and only the
   finalized file list is passed (`if-no-files-found: error`, `include-hidden-files: false`,
   attempt-specific name).
6. **Hardening: the native step condition.** The native step runs as `!cancelled() &&
   build == success`, so a failed `init` cannot suppress the native result. The job still fails
   through the failed `init` step, and `finalize` and upload are skipped when `init` produced no
   directory.
7. **Workload risk, no change (owner-fixed numbers).** The contract's "4m38s headroom" is measured
   against the slowest *complete* coverage step (20m22s, #487 first). The two other deadline
   attempts (#485 and #490 first) were cut off at 20m08s and 20m16s, with tooling (99 to 133 s
   elsewhere) and both plugin groups outstanding, which projects to about 22.5 to 22.6 minutes.
   Against that, the 25-minute cap leaves about **2.5 minutes**. A breach fails Coverage and Gates
   (fail-closed) and still uploads partial reports. Tooling grew from 175 to 219 tests on PR501.
   Root should watch hosted durations; this slice adds 21 fast tooling tests (about 2.4 s locally).
8. **Design confirmed: `always()`.** The aggregate must not use `!cancelled()`. A skipped job
   satisfies a required status check, so a cancelled run would leave a green-equivalent Gates.
   `always()` runs the aggregate on cancellation, and it fails there.
9. **Limit: reparse detection.** Node's `lstat` reports symlinks and junctions. Other reparse tags
   are not distinguishable without native attributes. Mitigations: a fresh directory, `CREATE_NEW`
   writes, a canonical `realpath`, `fstat` identity before reading and `nlink == 1`. Hosted
   `D:\a\_temp` is the expected root.
10. **Limit: diagnostics without log reads.** Per root's preference, no gateway or launcher log is
    read. Launcher outcomes come from a closed classification of the first 4 KiB of stderr: 26
    launcher, installer and PowerShell classes, plus `none`, `unavailable` and `unclassified`. Real
    runs mapped `foreign-listener`, `store-held`, `store-unverified`, `listener-not-ready`,
    `configuration-refused`, `startup-failed-logged`, `destination-in-use` and
    `destination-unavailable`. New launcher wording falls back to `unclassified`, never to text.
11. **Limit: the numeric job ID** is not available inside a job and is not invented. Root binds it
    from `gh run view --json jobs` and the same job's upload log.
12. **Review point: helper size.** `windows-launcher-evidence.mjs` is 1,258 formatted lines, more
    than "small". Prettier puts each enum value on its own line; the record schemas and enums take
    about 280 lines, the recorder about 260, and `init`, `finalize` and the CLI about 400. Each part
    serves a stated criterion: typed allow-listed records, bindings, refusal of links and unowned
    destinations, completeness and bounded output. No dependency was added. A reviewer may judge
    whether any part (for example the stderr classes) should be trimmed.

docs/10 previously said "three jobs" (base has four) and omitted `pnpm test:chat-restart` from the
Gates list; both are corrected.

## What was implemented

**#488 (`ci.yml`).** `repository-checks` (**Repository checks**, 30 min) has exactly the base Gates
steps minus Chromium, coverage and coverage upload, in order, with identical commands: 24 steps,
including Chat restart and the final licence, docs, contrast and audit checks. `coverage`
(**Coverage**, 30 min) does its own checkout, pnpm, `.nvmrc` Node, frozen install, full
`pnpm build`, Chromium install and `pnpm exec turbo run test:coverage --concurrency=1` with
`timeout-minutes: 25`. It then uploads the unchanged `coverage` artifact with the three summary
paths on every outcome (`if-no-files-found: warn`) and a summary step that reports the step outcome
and the summary count, and marks summaries partial unless the step succeeded. `gates` (**Gates**)
`needs` both, `if: ${{ always() }}`, 2 min, `permissions: {}`, no checkout. Results arrive through
`env`, never interpolated into the script; it writes a summary table and passes only on
`success`/`success`.

**#496 (`ci.yml`, suite, helper).** Before Install, `init` creates
`<runner.temp>\windows-launcher-evidence-XXXXXX` and writes `manifest.json`. The manifest binds the
repository, workflow ref, job key, run ID and attempt, event, ref, SHA, event head and base; the
checked-out HEAD, tree and parents from the raw commit header, so shallow merge checkouts work;
match booleans; the runner OS, arch, image and Node; and an `unavailable` list. The suite appends
typed records: `case-start` and `case-end` with failure kind, code, exit and signal; `child` with
tool, mode, outcome, exit, error code, signal, killed, timeout, elapsed, byte counts and diagnostic
class; `alias` and `alias-round`; `contention`; `cleanup`; `fixture`; `fixture-state` (`lstat`
only, at exit); `rejected`, `overflow` and `recorder-open`/`-closed`. Failing cases also print their
end record and last child record to stdout. `finalize` always validates the directory and files and
writes `result.json` with statuses `complete`, `incomplete`, `native-failed` and `not-run`. It exits
non-zero for `incomplete`, rejected or refused evidence, and passes the exact file list to the
upload.

## Artifact privacy limits

Three flat files below 256 KiB total: manifest ≤ 8 KiB, result ≤ 16 KiB, observations ≤ 192 KiB,
with records ≤ 1 KiB each, ≤ 1,024 records and the closing records reserved. They contain no
paths, arguments, environment values, keys, tokens, store bytes, command output, error messages
or log text: string values are closed enums, recognised error codes and signals, SHAs and
validated IDs. Fixtures are identified by their random `mkdtemp` suffix. The manifest includes
public run bindings (repository, refs, SHAs, image and Node version). Local logs in this folder
(`local/*/native.log`) are ordinary TAP with host paths and local canaries; they are QA logs, not
artifact content. Residual: suite children never receive the evidence path, but another process
on the runner could still find it in the runner temp folder. `finalize` refuses any unexpected
entry, link, hard link or non-canonical byte instead of uploading it. A race between
`finalize`'s checks and the uploader's read remains theoretically possible.
