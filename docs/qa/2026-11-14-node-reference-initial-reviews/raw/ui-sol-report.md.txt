The operation itself survives in the same position, yet the open row collapses. If the pending ID instead commits by clicking the visible Source input, focus follows the vanished-row fallback to the collection control instead of the corresponding Source input.

**Cause.** The new `formEpoch` key at `apps/web/src/editor/NodeEditorDialog.tsx:693` remounts `SchemaForm`. The form recovers collection identities by the exact config object in a WeakMap (`apps/web/src/forms/SchemaForm.tsx:183`, `apps/web/src/forms/disclosures.ts:39–57`). The repaired object has no snapshot. The array allocates fresh row IDs, and disclosures for rows present at mount start collapsed without their old keys (`apps/web/src/forms/fields/structure.tsx:329,348,451–461,1028`). The new blur path calls `keepFocusThrough` (`NodeEditorDialog.tsx:320–327,530`), which falls back when old row IDs are absent (`apps/web/src/editor/useUndoShortcuts.ts:241–263`). The target's rename kept the form mounted because it never repaired these sources. The new remount therefore introduces the failure.

**Required outcome.** Since this repair replaces source strings without inserting, removing or reordering rows, carry the same collection and disclosure identity through the replacement, then exercise the real ID-field Enter and blur paths. The focused regression should show the repaired source and its existing operation disclosure still open on Enter, and the same nested input focused on blur. If adding a pointer test, exercise a real nested control and verify any intended activation separately from focus. ### U3 · P2 · FIX-IN-PR · Preserve pending section JSON when a rename makes it equal to the applied section

**Reproduction from source.** In an Inference node `work`, use Context → Input with one append-message mutation containing `{{ counters.nodeVisits.work }}`. Open Input's **Edit as JSON**, change only the structured template source to `{{ counters.nodeVisits.draft }}`, and leave the valid replacement awaiting **Apply JSON**. Keep its shape otherwise identical to the current value. Rename the node to `draft` on Enter. The accepted Input now matches the still-unapplied document. The remounted JSON editor automatically clears the held state and records a second history step. The first Undo targets the synthetic held-input step instead of restoring the ID, source and edges in one undo, and remounting with the same equality can clear the restored hold again.

**Cause.** The rename moves the raw hold with the node and bumps the config form key (`apps/web/src/editor/store.ts:718–731`). The new `JsonText` takes its text from that hold, then derives `undefined` as the error because the valid replacement is now structurally equal to the applied section (`apps/web/src/forms/fields/json.tsx:123–137`). Its effect reports the cleared parse state (`json.tsx:183–194`). An existing hold removed without a user action is still treated as an authored change, since the feedback exception requires a previous and next entry with equal text (`store.ts:927–955`). The base's endpoint-only rename leaves the accepted section and its key alone, so the pending document remains different and awaiting Apply. The new behavior conflicts with one undo step and held-input preservation in `docs/09-frontend-and-pwa.md:270–272`, and with that document's existing explicit Apply/Cancel contract at line 772.

**Required outcome.** An automatic remount or validation refresh must preserve the exact pending buffer and its explicit resolution, and leave the rename as one step. Verify one Undo and one Redo restore the right graph and held state without a new history step or erased redo. Use a held document with different formatting to verify its exact bytes. Explicit Apply of a differing raw document is a later whole-section edit. The rename analyzes the accepted graph, so its notice provides no separate diagnostics for that buffer. This finding requires fixing the automatic path and does not prescribe a new confirmation workflow or rewrite of raw JSON.
