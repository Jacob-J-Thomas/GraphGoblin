Read-only investigation. Candidate backend `77e14b393f9b1da8a1bff5502e8f27e304d8a33b` and pre-feature `308c6285d5f5c4dffaf82613d066aba67c4dcffc`. ## Finding

The synchronous computation regression is established. Claude's independent fixture showed 50.50 ms median and 60.81 ms p95 for 300 nodes with node-state reads. My paired probe measured the same direction on a different valid graph shape. It imported the actual public editor model from both worktrees, ran both on exactly the same data, verified equal successful results on the fixtures, warmed all methods four times, then rotated method order across 15 samples. Liquid call counts were obtained in a separate dry run with temporary in-process instrumentation removed before timing. Node was 22.23.4.

## Where the cost occurs

- `EditorPage.tsx:144-148` recomputes `validateDraft` on definition or system-binding changes. `model.ts:250-290` runs Zod before `validateLoop`. Node config edits normally commit a new definition per valid change. Selection and temporary pointer drag coordinates do not change this dependency. Initial load, undo/redo, rename, and committed graph/layout edits do. The save path currently calls the same validation on autosave/cleanup, and a validation view can call it again when comparing server issues.
- `Canvas.tsx:694-705` writes live coordinates to local React state. At drop, `Canvas.tsx:660-672` calls `moveNode` and may clear crossed manual routes. That committed definition triggers validation, as can keyboard nudges and manual route commits. Source supports a synchronous typing/drop bottleneck. Actual input-to-paint, drag-frame routing and drop latency need a served-browser measurement before a product latency claim.
- `graph.ts:307` calls `syntaxIssues` and `nodeReferenceIssues` separately. Both walk the settings and node schemas, and typed union arm discovery can run extra parses. `template.ts` calls the public Liquid string parser independently for syntax and reference discovery. The pinned LiquidJS engine's configured cache is for parsed files, while `parse(string)` constructs fresh tokens. Reference analysis can call syntax check again for uncertain sources. JSONata already caches compiled syntax and its regex safety check by expression text, but static AST traversal runs again. Liquid still analyzes a syntactically valid template that refers only to vars or trigger input, which explains the no-reference cost.

## Minimal domain change if dispatched

Start with one shared authoring-validation pass and a bounded cache of analyzed source facts. `validateLoop`, the public syntax checker and rename should still report the same issues and locate the same spans.

1. Discover typed fields once per definition validation, then pass those fields to syntax and reference checks. Retain the public `findAuthoredSources` and `syntaxIssues` API shapes. Fold existing custom schema and editor-input union rules deliberately. A prior defect would be reintroduced if field discovery normalized omitted values, skipped malformed siblings, or stopped reporting syntax for payload/child fields that have no current-loop reference scope. Keep syntax diagnostics ordered before reference diagnostics and retain the rules for blank expressions and sentinel `none`.
2. Reuse one syntax result and one reference analysis per source/scope in the validation pass. For Liquid, parse with the existing configured engine, run scope/token analysis on that same parsed result, and retain only immutable source facts. For JSONata, inspect the existing compile/safety-checked AST once on cache miss. A syntax failure and a conservative reference-analysis failure are different states. Keep existing malformed/syntax diagnostics and the uncertain warning for a valid source whose reference analysis cannot establish meaning. No raw-text exclusion for suspected unrelated fields. Escapes, literal lookup and nested language constructs make such a filter unsafe.
3. Retain bounded reusable facts across calls by exact language + full source string + reference scope, with explicit entry and retained source/result-size budgets. A capacity around 512-1024 small sources would cover the 300-node fixture, while long sources or large span lists can bypass the cross-call cache and still be analyzed once in the current pass. Budget by source length as well as count because the contract allows sources of 100,000 UTF-16 code units. Record bounded facts such as syntax message, immutable offsets, optionality and uncertainty. Keep graph IDs, custom output ownership, field location, issue objects, rename target, evaluator AST references and mutated plans outside the cached value. Don't cache whole-graph validation or mutate the compiled AST/parsed templates. No evaluator or UI changes needed. Recompute graph-dependent decisions on every call, including when the same source occurs under a different loop or execution scope.

If one-pass discovery alone yields enough improvement, the cache can stay small. It is acceptable to stage the deterministic measurement before choosing a capacity. If node-count cost remains after measured reuse, reprofile the schema/graph pass before adding incremental graph validation or moving validation to a worker.

## Acceptance

- On cold validation, no more than one Liquid parse per unique exact source requiring syntax, and no more than one parse/analysis for a one-field edit while unchanged normal-size sources remain cached. A location-only change or freshly parsed equivalent definition should reuse source facts. Cache eviction or bypass changes cost only. Never use timing thresholds as a default automated unit gate under nondeterministic load.
- In deterministic tests, carry equivalent text through trigger payload versus thread, parent versus child, injected shadow cases, and separate loops whose node IDs/producer/custom-output ownership differ. A cache hit must still turn a real missing gate/visit into an error and preserve inherited/dynamic/optional warnings. Verify repeated rename with different targets, escaped tokens, syntactically invalid and valid-but-uncertain sources, and edits changing the exact text. Use the existing public domain and API suites after the change, including coverage 90/90.
- Rerun the same warm paired probe with a one-prompt edit per sample and compare the median/p95 of absolute overhead. A proposed target for the 300-node fixture is recovering at least 70% of the measured added median and avoiding a 2× baseline increase. Also report cold load and unchanged geometry-drop costs. These are development acceptance diagnostics, not a cross-machine SLA.
- In the existing phase-2 Edge plan, compare base and exact integrated candidate with identical fixture/window and 20 controlled keystrokes and capture event-to-paint median/p95. Verify normal node drag routing and the post-drop commit separately. Treat a reproduced doubling or a new crossed frame budget as an integrated regression for follow-up. The current standalone timings establish avoidable CPU cost, without establishing how much of the end-to-end interaction it occupies.

No source, index, external state or protected service changed.
