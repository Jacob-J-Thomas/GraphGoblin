The exit appends `run.finished` before `finish()` projects terminal status ([run-manager.ts:2786–2802](https://github.com/Jacob-J-Thomas/GraphGoblin/blob/0d024bc4f8706846dfcd3da251899f4a6ea23a0d/packages/engine/src/run-manager.ts#L2786), [2885–2905](https://github.com/Jacob-J-Thomas/GraphGoblin/blob/0d024bc4f8706846dfcd3da251899f4a6ea23a0d/packages/engine/src/run-manager.ts#L2885)). Thus `row.lastEventSeq === terminal.seq` can coexist with `row.status === running`; a later delivery/audit row can also advance the tail without changing execution outcome. `lastEventSeq` is not a status-projection version. Existing recovery logic explicitly recognizes this gap and returns `RECOVERY_STALE` ([run-recovery.ts:41–58](https://github.com/Jacob-J-Thomas/GraphGoblin/blob/0d024bc4f8706846dfcd3da251899f4a6ea23a0d/packages/engine/src/run-recovery.ts#L41)).

In history mode, new live events advance `lastSeq` without joining the displayed window ([event-store.ts:6–31](https://github.com/Jacob-J-Thomas/GraphGoblin/blob/0d024bc4f8706846dfcd3da251899f4a6ea23a0d/apps/web/src/runs/event-store.ts#L6), [83–117](https://github.com/Jacob-J-Thomas/GraphGoblin/blob/0d024bc4f8706846dfcd3da251899f4a6ea23a0d/apps/web/src/runs/event-store.ts#L83), [129–170](https://github.com/Jacob-J-Thomas/GraphGoblin/blob/0d024bc4f8706846dfcd3da251899f4a6ea23a0d/apps/web/src/runs/event-store.ts#L129)). Its separate `finished` field can be from an earlier attempt; use the ordered lifecycle marker to invalidate it.

## Minimum safe options for root selection

**A — presentation-only header evidence, preferred small scope.** Keep a bounded, per-run latest lifecycle marker outside the browsed event window. Feed it from accepted live batches before cache trimming and from the whole-run observation; merge by validated run ID and increasing event sequence, with navigation/subscription generation guards. Current live evidence must outrank late older observation responses. Retain no large result/failure payload merely to display a badge.

For the latest *known current* terminal marker, show its actual execution status while the run refresh is held/in flight or returns a lagging status at an equal tail. A refused query can retain the existing error boundary in #386; later #416 owns outage retention. Do not overwrite the cached `RunSnapshot`. If the position label remains in the same header, suppress or qualify its stale active-node claim rather than displaying “succeeded at done” as a current execution position. A later `started`/`resumed` marker invalidates that terminal display immediately. A lone resumed marker establishes that the old terminal is superseded, not that the phase is running: use the recorded phase only when reconciled, otherwise a small synchronization indication until supported phase evidence arrives. Root must decide that exact wording/representation before implementation.

Explicitly track evidence provenance/coverage. A row tail higher than the known terminal cannot distinguish delivery audits from an unseen resume. If accepted live/history coverage or a newer whole-run lifecycle observation has not reconciled that boundary, do not silently assert that the old terminal is current. Likewise, persisted cached terminal evidence alone must not become an eternal terminal latch across reload. Initial loading/refusal without any current trusted evidence remains a loading/read error, not a fabricated outcome. A missing or oversized terminal payload needs a valid whole-run marker or honest unresolved state.

**B — a narrow server-derived execution-header observation.** If A cannot make the cross-read coherence rules small and explicit, expose a bounded read model containing the current lifecycle marker and enough provenance to distinguish the row projection from the latest execution outcome. The existing indexed lifecycle lookup is the reusable primitive. Keep it separate from authorization/recovery and do not change stored formats merely to repair a badge. This is wider API/contracts scope, requires root architecture selection and relevant docs/ADR review, and still needs live-event presentation for a delayed refresh; refused-query retention remains #416. It is not a reason to infer phase from a single resume event.

**Insufficient shortcuts:** refetch-only cannot make the header truthful while the response is held; `seq > row.lastEventSeq` misses the equal-sequence gap; replaying the visible timeline loses older context; always trusting `observation.finished` or latching any terminal ignores later attempts; a `StreamStatus`/EOF-derived status confuses transport, execution and finalization.

Under either option, `RunControls`, `ScriptRecovery`, session recovery, input/cancel choices, server recovery tokens, failures, `finishedAt`, `finalizedAt` and delivery state remain derived from their actual server contracts. A terminal badge must not grant a control, clear `RECOVERY_STALE`, declare cleanup complete, close/reopen SSE differently, or fabricate result/failure state. Existing controls use the unmodified run ([RunInspectorPage.tsx:203–227](https://github.com/Jacob-J-Thomas/GraphGoblin/blob/0d024bc4f8706846dfcd3da251899f4a6ea23a0d/apps/web/src/runs/RunInspectorPage.tsx#L203)); snapshots attach server recovery ([run-manager.ts:1261–1280](https://github.com/Jacob-J-Thomas/GraphGoblin/blob/0d024bc4f8706846dfcd3da251899f4a6ea23a0d/packages/engine/src/run-manager.ts#L1261)). Execution outcome precedes finalization; only the matching `stream.complete` confirms an observed tail, and EOF retries ([API doc:226–228](https://github.com/Jacob-J-Thomas/GraphGoblin/blob/0d024bc4f8706846dfcd3da251899f4a6ea23a0d/docs/07-api-and-streaming.md#L226), [ADR-0057:15–59](https://github.com/Jacob-J-Thomas/GraphGoblin/blob/0d024bc4f8706846dfcd3da251899f4a6ea23a0d/docs/decisions/ADR-0057-execution-and-delivery-finalization.md#L15)).
