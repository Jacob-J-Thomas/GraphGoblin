## R1 — Receiving a resume observation first loses the preceding failed attempt

**P2 · FIX-IN-PR · `header-lifecycle/predecessor-terminal-lost-on-overtaking-observation`.** The new event fold skips every event at or before its coverage cursor (`apps/web/src/runs/run-header-status.ts:93`). A resume arriving from the observation query advances the cursor to that resume before a pending stream can supply the preceding failure (lines 69–75, 110–113). The new selector then treats an active row older than the failed attempt as authoritative because the previous terminal sequence is absent (lines 137–141).

The first case in `review-witness.test.tsx` held the event stream until the real observation query cache contained `run.resumed #4`. Releasing the stream rendered both `run.failed #3` and `run.resumed #4` in the Timeline. The run cache still contained `running #2` at `stale-node`. The header showed **running** and **at stale-node**. Folding the identical inputs with the stream first gave **Updating status…**. The run can park on resume. At this point the lagging read and resume marker cannot establish an active phase or its position. The base rendered its row directly. Arrival-order-dependent loss of established predecessor evidence comes from the candidate reducer.

**Required outcome.** Both arrival orders must discard the pre-failure row as a source for the current phase or node while the current read is held. Preserve the newer resume as the latest marker and accept a subsequently reconciled parked or running phase. Exercise the observation-first order through the public inspector.

## R2 — Two failed attempts at different nodes are presented as one current position

**P2 · FIX-IN-PR · `header-position/equal-status-cross-attempt-record`.** The candidate's status-equality fast path returns `kind: 'record'` before checking the event sequence (`apps/web/src/runs/run-header-status.ts:132`). The new header then presents `run.currentNodeId` unqualified (`apps/web/src/runs/RunInspectorPage.tsx:108` and line 221).

The second case in `review-witness.test.tsx` rendered a failure at `first-node` in event #3, a same-run resume at #4, progress to `second-node`, and a new failure at `second-node` in event #8. The distinct failures and final event were visible in the Timeline. The actual run cache still contained the original **failed** row at #3. The header said **failed** and **at first-node**, without the event #8 qualification. The equality of the labels conceals a known mismatch between attempts. The base could already render an old row's node. The candidate introduces the classification that treats that row as current despite having observed the newer outcome and adds a position-suppression contract that the classification bypasses.

**Required outcome.** A row that demonstrably predates the latest terminal marker cannot establish its position merely by sharing its status. Show the observed outcome, hide or qualify the older position, and allow the fresh server row to supply its position when reconciled. Cover the repeated-status case.

## R3 — Revisiting a run revives a failure already superseded on screen

**P2 · FIX-IN-PR · `header-navigation/cached-observation-revives-superseded-terminal`.** A run switch discards the hook's lifecycle evidence, and the hook immediately accepts any observation query data for the returning run (`apps/web/src/runs/useRunHeaderStatus.ts:26–31`, `apps/web/src/runs/RunInspectorPage.tsx:122–129`). The resumed stream starts after its retained cursor (`apps/web/src/runs/useRunEvents.ts:118`). When that cursor already includes the superseding resume, it need never replay the marker. This stale-cache-derived terminal assertion is introduced by the patch.

`review-navigation.test.tsx` obtained a real cached observation of **failed #3**, then delivered **resumed #4**. With refreshed reads held, A's header correctly showed **Updating status…**. The test followed ordinary inspector links A → B → A. On return, it witnessed the new SSE request after cursor 4, the visible resume, the stored cursor 4, cached observation #3 and run row **running #2**. The header now showed **failed** and **Status from event #3; the run record is updating.** No new terminal observation or event had occurred. A reader returning to the inspector sees an outcome that the same view had already invalidated.

**Required outcome.** A returning inspector must preserve uncertainty when the available observation predates an acknowledged tail that may supersede it. The previous attempt must remain superseded while fresh reads are pending, including when the resubscribed SSE has no new event to send. Maintain run identity, small in-memory state, presentation-only semantics and the existing device-cache format. Cover A → B → A with a stale observation and the resume already behind the cursor.
