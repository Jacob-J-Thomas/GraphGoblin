# PR #478 native automatic-edge selection double-click probe

**Reproduced on the first fixture.** A single native click on an unselected automatic edge selected it and left the graph unchanged. A native double-click at that same naturally hittable point selected the edge on the first click and removed it on the second, after the selected-edge toolbar appeared under the pointer.

## Introducedness and separate Remove follow-up

Actual main `41bde22c` displays selected route handles and conditionally displays a toolbar only for a manual route. That toolbar has Reset route, with no canvas Remove button. Before #207 the pointer removal control belonged to the node dialog, with selected-edge Delete/Backspace also supported on the canvas. In the candidate an automatic forward edge gains the canvas toolbar on selection. Its HTML Remove button is placed over the still-clickable trunk and calls `editing.remove(edgeId)` on the second click. The dynamically introduced destructive hit is therefore a #207 behavior. This comparison is from the exact source, with no actual-main runtime run. [Main edge toolbar](https://github.com/Jacob-J-Thomas/GraphGoblin/blob/41bde22c80a796bf8c4bec8ab5dec8e755271f9e/apps/web/src/editor/OrthogonalEdge.tsx#L299) · [Main node dialog removal](https://github.com/Jacob-J-Thomas/GraphGoblin/blob/41bde22c80a796bf8c4bec8ab5dec8e755271f9e/apps/web/src/editor/NodeConnections.tsx#L117) · [Candidate toolbar](https://github.com/Jacob-J-Thomas/GraphGoblin/blob/e624a2f5b0eaeaf608d9dc66baaa38c9c81c07be/apps/web/src/editor/OrthogonalEdge.tsx#L330)

After the deliberately selected unique Remove control acted, its former center hit only the bare canvas pane. No node or other edge occupied that point, and the viewport had not moved. A separate double-click directly on already available Remove was not driven, because the observed underlay supplied no second actionable graph target and the requested selection reproduction was already confirmed. The fixture makes no claim about other underlying targets.
