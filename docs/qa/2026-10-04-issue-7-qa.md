## Defects

Severity: blocker/major means loss of essential operation or data; minor means a bounded usability, robustness or accessibility failure with a workaround; cosmetic means misleading presentation without blocking operation. There were no blocker or major findings.

### I7-QA-01 - Valid long loop name overflows the Editor toolbar (minor)

Steps: create a valid loop whose name is `W` repeated 120 times, open its Editor, and inspect at 1440×900 and 720×450. Expected: the title wraps or truncates within the shell and the page stays within its viewport. Actual: the heading is about 1864.48 px wide and the document scroll width is 1880 px at both 1440 px and 720 px. The name meets the contracts' 120-character limit. Controls remain usable, but the page has horizontal overflow. Both themes fail. Evidence: [dark-long-editor.png](2026-10-04-issue-7-qa/dark-long-editor.png), [light-long-editor.png](2026-10-04-issue-7-qa/light-long-editor.png); measured viewport/page widths 1440/1880 and 720/1880. Normal-length names passed the same layout checks.

### I7-QA-02 - Long text escapes shared primitive containers (minor)

Steps: render the actual Alert with 350 unbroken W characters, Badge with `long badge ` repeated 45 times, and Button with `long action ` repeated 45 times inside the 1334 px content area of a Card. Expected: content wraps, truncates, or stays inside a bounded scroller. Actual: Alert content scroll width 4304 px, Badge 3024 px, Button 3525 px; text and controls escape their container and produce page overflow. Inputs and Textarea retain the same long content inside their own controls. This is a supplemental primitive stress case, not a claim that ordinary short action labels overflow. Both themes fail. Evidence: [dark-long-primitives.png](2026-10-04-issue-7-qa/dark-long-primitives.png), [light-long-primitives.png](2026-10-04-issue-7-qa/light-long-primitives.png).

### I7-QA-03 - Reduced motion retains an infinitely running pulse (minor)

Steps: render the actual running RunStatusBadge, emulate `reducedMotion: 'reduce'`, inspect the glyph with `getComputedStyle` and `getAnimations`, and sample 12 animation frames. Expected: the decorative pulse is disabled, leaving a steady full-opacity status glyph. Actual: `gg-pulse` remains running with infinite iterations and a 0.01 ms Web Animations duration (CSS `1e-05s`), because the global duration override supplies a nonzero duration. The glyph's sampled opacity was constant at 0.489008 in dark and 0.891261 in light, rather than 1. The capture showed constant opacity; the failure is the retained active animation and faded glyph. Tokens' zero durations and transitions' collapsed durations separately passed. Evidence: [dark-reduced-pulse.png](2026-10-04-issue-7-qa/dark-reduced-pulse.png), [light-reduced-pulse.png](2026-10-04-issue-7-qa/light-reduced-pulse.png), the measured timing and opacity values above.

### I7-QA-04 - Empty optional heartbeat Until reports a compile error (cosmetic; existing D30)

Steps: create a fresh valid trigger → heartbeat → exit loop with heartbeat config `{intervalSeconds:60,maxBeats:30}`, select Heartbeat and leave optional Until empty. Expected: an omitted optional condition has no error preview. Actual: the preview says `expression failed to compile: Unexpected end of expression` while Validation says `Ready to publish`. Both themes fail; error text itself is readable. This reproduces D30 from the earlier [WP-D2 QA record](2026-10-03-wp-d2.md). Evidence: [dark-heartbeat-empty.png](2026-10-04-issue-7-qa/dark-heartbeat-empty.png), [light-heartbeat-empty.png](2026-10-04-issue-7-qa/light-heartbeat-empty.png).

### I7-QA-05 - Cold offline Loops state stays stale after reconnect (minor)

Steps: warm the production SW, reload Loops with the context offline, wait for the API-needed Offline state, then reconnect without navigating. Expected: the list refetches and replaces the Offline message. Actual after 5 s (also failed the earlier 15 s waits): `navigator.onLine === true`, an online event fired, direct `GET /loops` returned 200, and the top offline banner disappeared, but the Loops Offline message remained with zero table rows. Reopening the route recovered the list without data loss. This differs from editing a previously loaded draft offline, whose local save and later sync passed. Both themes fail. Evidence: [dark-offline-reconnect.png](2026-10-04-issue-7-qa/dark-offline-reconnect.png), [light-offline-reconnect.png](2026-10-04-issue-7-qa/light-offline-reconnect.png); measured state in each theme: `online=true, events=[online], API=200, offlineBanner=false, offlineQuery=true, rows=0`.

## Not tested and why

Five conditional scenarios were not run in either theme, accounting for 10 catalogue entries:

1. Native Select popup pixel colours: headless Edge's OS popup is outside the page DOM/screenshot. Keyboard option change, control colours and colour-scheme were verified.
2. Autofill with saved profile data: the fresh isolated context had no saved profile/form data, and the owner's profile was not used.
3. OS date-picker popup pixels and native scrollbar interaction: computed date/scrollbar styling and colour-scheme were verified; OS popup pixels were not inspected.
4. Real second-build SW activation: the documented simulateUpdate seam exercised the toast, confirmation and apply counter. A second production SW revision/deployment was not introduced; offline shell and font precaching were exercised live.
5. Populated domain-aware completion suggestions/tooltips: Liquid/JSONata use legacy modes without a supplied domain completion source. Control+Space on the actual JSON CodeEditor fixture surfaced no completion panel, so populated suggestions/tooltips could not be checked.

Additional confidence limits: this was Edge-only, not Firefox/Safari or a screen-reader audit; 200% used the explicitly permitted 720 px CSS viewport equivalent rather than changing Edge's browser zoom setting. Normal-content page overflow and focus were checked, but #41's responsive editor redesign was not implemented or assessed as delivered. Build used valid Turbo cache hits. Real external harness authentication, real inference-provider behaviour, and a before/after functional replay on the parent commit were outside this visual-foundation verification. The ErrorBoundary is tested through an injected malformed response; it is not claimed as an organically observed rendering defect. No defects were fixed and no Git commit, staging, branch change or publication was performed.
