## U1 · import selection ownership

**Design.** Each file choice gets an `ImportSelection` token (`{ key }`) when it is chosen, inside the change handler and before the file is read.

- `currentRef` holds the current choice.
- `retryingRef` holds the choice whose retry is being sent. It guards a second activation before the next render.
- The token travels in the mutation variables of the initial request and of every retry, and `HeldImport` stores it.
- Every choice-specific outcome checks `currentRef.current === selection` first. That covers a read failure, the stale-read return before parse/upload, initial success, initial refusal, initial other failure, and retry refusal or failure. The retry path also checks `now.selection`, replacing the earlier partial `document` identity guard.
- List refresh (`invalidateQueries(keys.loops)`) runs before the ownership check, so a stale choice still reconciles the list after a success, a refusal, any retry outcome, or a failure that may have committed.
- Cancel sets `currentRef` to undefined.
- The retry form is keyed by `held.selection.key`.
- `pending` is `importLoop.isPending && importLoop.variables.selection === held.selection`.
- `file.text()` is wrapped: an unreadable file reports `<file> could not be read.` only if that choice is still current. Before, the rejection was unhandled.

No workflow framework was added and the picker was not disabled.

**Final selection policy, for QA.** The picker stays enabled. The newest choice owns the result message and the **Import under another name** region. Choosing another file, or **Cancel**, ends the current choice. After that, an ended choice's unread file is never sent and its read failure says nothing. Its late answer, whether 201, 409 or another failure, only refreshes the loop list, so a late successful import appears in the list with no message. The form's typed text persists across the same upload's retries, and a second activation while that retry is sending sends nothing. Every attempt sends the parsed upload unchanged, with the explicit name only in the `name` query. Independent native QA should use `qa-mode=candidate` with picker B enabled during A, not the disabled-picker outcome. This is documented in docs/09 under "Loop names → Import".

**Small added behavior.** An initial (non-retry) import failure that may have committed (no answer or 5xx) now also refreshes the list. The current message text is unchanged.

## U2 · Try again ownership

**Design.** The permission and the busy display are now separate.

- **Type.** `NameRetry { loopId, generation, refusal }` is a new type in `store.ts`. `EditorNameConflict.retrying` stays boolean, is documented as display-only, and grants nothing.
- **Starting an attempt.** `EditorPage.retryName` builds `refusal = { ...nameConflict, retrying: true, retried: false }`, sets it in the store, and calls `flush({ loopId, generation, refusal })`.
- **Signature.** `useAutosave`'s returned function is now `(retry?: NameRetry) => Promise<boolean>`. Every other caller (publish, Overwrite, recovery and online events, the debounced timer) passes nothing.
- **Binding.** In `save(retry)`, the permit is kept only if it matches the `loopId`/`generation` captured by that call. Inside the queued job, the name hold is skipped only when the draft name is equivalent to `permit.refusal.name`. The permit is cleared as soon as one request is sent.
- **Settling.** `settle()` runs on every path: the early returns before queueing (`!enabled`, no `loopId`) and a `try/finally` around the queued job. It covers schema-invalid, draft conflict, a newer generation, the already-saved state, the hold, success and every failure. It clears `retrying` only if the store still holds the same `refusal` object it marked, so a newer refusal, an accepted save or a load is left alone.
- **Removed branch.** The generic failure branch that cleared another attempt's `retrying` is gone. `retried` on a refusal is now `deliberate`, meaning the refused request was this attempt's own.
- **Unchanged.** Stale-token precedence (`DRAFT_CONFLICT` clears the name notice, and the job stops on `state.conflict`), the unmount skip, the device mirror and undo.

**Consequence.** No other save (publish, recovery, the debounced timer) gets through the hold while a Try again is pending. Before, any save that ran while `retrying` was true skipped the hold. docs/09 "Rename" describes this.
