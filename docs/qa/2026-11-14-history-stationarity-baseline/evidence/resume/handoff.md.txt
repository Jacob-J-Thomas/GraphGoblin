## 3. Method and fixed conditions
Drivers: `scripts/measure.playwright.js` (m1), `scripts/measure-m2.playwright.js` (m2, primary), `scripts/measure-h2tune*.playwright.js` (H2 boundary), orchestrated by the prepared `run-case.mjs`/`gateway.mjs`. A per-frame sampler (rAF, ~8.3 ms median cadence) runs in the page and records: both buttons' boxes, group/header/frame/Publish/validation boxes, viewport, `visualViewport`, scroll position/height, save/validation/Publish/banner/badge labels, hit-tests at the rest centre and current centre of both buttons, plus a full frame on every pointer/key/focus/scroll event and on every banner DOM mutation. Real input: `page.mouse` down/hold/up, `keyboard`, `touchscreen.tap` (coarse), palette clicks/taps. Counts and effects come from node count, history titles, `aria-disabled`, REST PUT bodies and final server/device readbacks.

Configs (viewport CSS px; app theme set via `localStorage graphgoblin-theme`, because the app follows `data-theme`, **not** `prefers-color-scheme`):
- **D1** 1440×900, DPR 1, fine pointer, app light (buttons 32×32). **D2** 1440×900, DPR 1, coarse pointer (hasTouch), app dark (44×44, touch taps). **N768** 768×900 fine, light. **R512** 512×384 at DPR 2 (effective 200% reflow of 1024×768), fine, light. Root font 16 px in all.
- Pace: burst actions 150 ms apart; mouse press hold 60 ms; held PUT/validate 1000 ms, held publish 1500 ms; all holds/aborts/500s were applied only to this worker's own disposable requests via `page.route` (logged with times in each `raw/*.actions.json`).
- Latency was not measured; geometry only. Each config is compared only with its own rest box; nothing is claimed stable across configs, and no zero-scroll claim is made at any height.

Burst (12 actions): add Script, add Mutate, add Wait, Undo×3, Undo (aria-disabled no-op), Redo×3, Redo (aria-disabled no-op), Undo = 10 effective + 2 no-ops. Expected node deltas matched in **every** run (0 mismatches; no off-button click; disabled clicks had no effect and kept focus).

Run inventory (46): m1 ×9 (D1 only, app-dark, retained), m2 ×34, h2tune ×3 (§4). m2: `h12` ×4, `h12held` ×4 (120-char name, held PUT/validate/publish), `h3` ×4, `control` ×4, `h4offline`/`h4transportall`/`h4transportput`/`h4http500` ×4 each, `dialog` ×2 (D1, R512). 433 recorded add/history actions in total. Raw per-run data: `runs/<label>/raw/*.frames.json|actions.json`; digests: `analysis/`.

## 4. Correction ledger (budget: 2) — **2 of 2 used**
1. **m1 → m2 (correction 1).** After the first-of-each-case runs I found finite fixture defects: (a) the "light" configs did not produce the app's light theme (`data-theme`/localStorage, not `prefers-color-scheme`); (b) banner finder also matched the editor's own save notice ("Offline: the draft is kept…"); (c) fractional 0.5 px hit probes are below the engine's hit-test snapping, so a 1 px press shift was invisible, and there was no edge-press test; (d) coarse palette adds used mouse clicks. m2 fixes all four without weakening any assertion. All 9 m1 runs are retained unchanged as fine-pointer/app-dark/emulated-light-scheme measurements and agree with m2 geometry.
2. **h2tune → h2tune2 (correction 2).** `candidate-k70` in `h2tune-d1` failed (REST 409 `LOOP_NAME_CONFLICT`: the calibration probe had already created that exact name). The failed run is retained; h2tune2 reuses the probe's loop. Re-run clean at D1 and D2.
- **Known uncorrected m2 defect (cosmetic, disclosed):** `noticesText()` in m2 has `/s+/g` instead of `/\s+/g`, so the auxiliary `notices` text field has "s" replaced by spaces ("Publi hed ver ion 1."). It does not affect geometry, jumps, banner detection (raw text) or the save/validation/Publish/banner label fields. Not worth 34 reruns; no budget left to correct it.
- Rehearsal (not a product run): the sampler was rehearsed on a static synthetic toolbar on a loopback server (`scripts/rehearsal/`); run 1 failed on my own off-by-one assertion (retained), corrected in the rehearsal only; m1 and m2 samplers both passed, including integer-row hit semantics.

### 5.3 H3 — pressed movement (reproduced)
`m2-h3-*` (6 mouse holds + keyboard + 4 edge presses per config): `translate` is `none` at rest and `0px 1px` pressed (transform stays `none`, box y +1.000: D1 68→69, D2 66→67, N768/R512 100→101). Ramp: 0.52–0.75 px at 35–49 ms, 1.000 px by 157–181 ms (transition `translate 0.12s`); after release 0.13–0.35 px at +40 ms and `none` by +340 ms. Touch taps (D2) showed partial translate 0.48–0.94 px at event time; a CDP touch *hold* showed `:active` false and no translate → **unresolved**.

Integer rows [top-in, bottom-in, above-out, below-out]: rest true/true/false/false → pressed false/true/false/true (fractional 0.5 px probes cannot show this; all configs identical).

**Edge-click loss (all 4 configs, enabled Undo):** pointer on the top pixel row (y = box top), held 250 ms: `mousedown` on the button, the box moves to y+1, `mouseup` target is the header, `click` fires on the header, **history effect 0**. Held 60 ms (box at +0.87–0.94): click delivered, effect −1. Bottom pixel row and centre, 250 ms: delivered, effect −1.
