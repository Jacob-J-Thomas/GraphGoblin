## Findings

### MACUI-01 · P2 · Quit guidance promises cancellation until after the actual cutoff

The progress panel promises, “Quitting cancels the launch if GraphGoblin hasn’t started yet.” The engine marks spawn committed under the Quit guard, then publishes `.starting`, then submits the native spawn. If Quit reaches the guard after commitment and before submission, the detached gateway can still start after the launcher says it will cancel. The installation guide already describes the commitment cutoff accurately. [PresentationCopy.swift](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/apps/macos-launcher/Presentation/PresentationCopy.swift:121>), [Commit and cancellation guard](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/apps/macos-launcher/Engine/NativeLaunchEngine.swift:26>), [Spawn sequence](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/apps/macos-launcher/Engine/NativeLaunchEngine.swift:301>), [Installation guide](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/docs/guide/01-install-and-first-run.md:155>)

Make the progress text reflect that Quit cancels a pending start and that an already committed start may still finish. Preserve the existing Hide and detached-gateway semantics. Update the fixed-copy expectation. [Progress copy test](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/apps/macos-launcher/Tests/Presentation/OutcomeCopyTests.swift:391>)

### MACUI-02 · P2 · Store-blocked guidance asserts an unverified live owner

With the configured port refusing connections and a malformed store lock persisting through the launch budget, the API helper reports `held` with unverified ownership. The native engine emits `.waitingForStore` and can return `.storeBlocked` on expiry. The UI says the data is in use and tells the user to finish or close the other process. A malformed ownership record can produce this result with zero live owners. The current fixed-copy fixture asserts the misleading title and instruction. [Progress copy](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/apps/macos-launcher/Presentation/PresentationCopy.swift:139>), [Failure copy](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/apps/macos-launcher/Presentation/PresentationCopy.swift:231>), [Writer lock policy](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/apps/api/src/data-dir-lock.ts:63>), [Held-store progress](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/apps/macos-launcher/Engine/NativeLaunchEngine.swift:280>), [Expiry outcome](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/apps/macos-launcher/Engine/NativeLaunchEngine.swift:313>), [Failure copy fixture](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/apps/macos-launcher/Tests/Presentation/OutcomeCopyTests.swift:119>)

Describe store access as blocked or unconfirmed in both the waiting and failure text. Make any suggestion to close an existing GraphGoblin session conditional on the user recognizing one. Keep safe guidance for persistent blockage, the fixed log affordance, and the current sanitized outcome. Update the explicit copy expectations.

### MACUI-03 · P3 · A late Show Log resolution can win after the three-second cutoff

The presentation handoff specifies that Show Log availability waits at most three seconds and discards a later result. After those three seconds elapse, both the resolver and timer can be ready for the main actor. If the resolver continuation resumes first, `showLogResolved` checks only the phase, cancels the timer and includes Show Log. The current test releases the resolver after the expiry window is already presented, so it exercises only the opposite ordering. The button's directory revalidation remains in effect. [Resolver and timer](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/apps/macos-launcher/Presentation/LaunchPresentationController.swift:337>), [Show Log timeout test](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/apps/macos-launcher/Tests/Presentation/ShowLogTests.swift:75>), [Presentation handoff](<C:/Users/98jak/graphgoblin-qa/2026-11-13-aidlc-batch/launcher/macos-presentation-implementation-01/full-report.md:83>), [Action revalidation](<C:/Users/98jak/.codex/worktrees/gg-20261116-macos-launcher/GraphGoblin/apps/macos-launcher/Entry.swift:14>)

Use the same absolute monotonic deadline for both the timer and the resolver result. Discard a resolution at or beyond expiry even when the timer callback is still queued. Exercise the reverse completion order in a deterministic clock test.
