## 7. Decisions and parameters

| Condition/event                                                  | Protection and lifecycle                                                                                                            |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| New history                                                      | Retained; never inherits approval                                                                                                   |
| Queued/running/waiting/paused or unfinished finalization         | Protected                                                                                                                           |
| Parent/child and replay-source/fork records                      | Complete undirected dependency component must be selected together or already approved; foreign/missing dependencies refuse marking |
| Successful/failed/cancelled/exhausted, finalized                 | Same explicit-confirmation rule for each                                                                                            |
| Resume, new child/replay, relationship/event/finalization change | SQLite revokes affected component approvals transactionally, including old relationships                                            |
| Explicit withdrawal                                              | Selected history and its dependency component become retained                                                                       |
| Shared artifact referenced by retained runs                      | Resource remains protected; no resource deletion occurs in phase 1                                                                  |
| Cancelled/invalid/stale/protected review                         | No partial approval; cancel/review again                                                                                            |

The selection maximum is 500 unique IDs, matching the existing maximum run-history page. It bounds one human review and write transaction; it is an engineering parameter, not an owner-approved storage threshold. A component larger than 500 remains protected. SHA-256 token state plus monotonic consent revisions prevents stale/ABA confirmations; there is no time-based expiry or age-based eligibility. Nullable approval indexing avoids relationship traversal in lifecycle triggers while nothing is approved. Phase 1 uses migration 0021 only; 0022 remains unused/reserved for phase 2, so coordinate the migration chain if #256 needs its reserved 0023.

Capacity port, pressure thresholds and their justification: deferred to #322. They are not invented or described as owner-approved here. Cleanup must use a public injected capacity dependency with real statfs composition, safe thresholds, retained-reference/ownership checks and honest accounting in phase 2.

What is deleted/ownership: the new eligibility service deletes nothing. Existing explicit loop deletion still has its own clear history confirmation, deletes only loop-scoped database history and rows linked by run identity, and now refuses active, unfinished or required retained history. It deletes no workspaces or artifact bytes. Demonstrable filesystem ownership and phase-2 resource cleanup remain outstanding.

Interruption: confirmation and all eligibility/revision writes are one SQLite transaction; fault injection proves rollback. Interrupted automatic cleanup and paging/reference integrity after deletion belong to phase 2 and are not claimed.
