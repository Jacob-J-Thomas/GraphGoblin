## Root 1: run identity

**Finding.** With a verified push checkout and a complete stream, `GITHUB_RUN_ID=''` finalized
`complete`, exit 0, with the manifest listing `unavailable: ["runId"]`.

**Change.** `bindingRequirements` now also requires the run identity. Exact contract (docs/10,
Status): `repository`, `workflowRef`, `job`, `runId`, `runAttempt`, `event` and `ref` must each be
non-null in the validated manifest.
- **Missing or malformed values.** Validation against the existing patterns already turns a
  missing or malformed value into null. Any null adds one `binding-identity` marker, however many
  values are null.
- **Status.** A passing native step becomes `incomplete`, exit 1. The valid manifest, observations
  and result are still written and uploaded. A failed or cancelled step stays `native-failed`, and a
  skipped one stays `not-run`, each with the marker listed.
- **Not required.** The runner OS, architecture and image and the Node version are diagnostics and
  may stay unavailable. A push needs no event base. The event head and base count only through the
  checkout comparisons, which are unchanged.
- **Contradictions.** A known contradiction keeps `binding-contradiction` beside the new marker.

## Root 2: the closer's rejected count

**Finding.** A closer with `rejected: 1`, no `rejected` record and `omittedRecords: 0` was
accepted `complete`, with the summary showing `rejected: 0`.

**Accounting, inspected before the check changed.**
- `#rejected` is incremented only in `#rejection()`, and that record always reaches `#append()`.
  There it is either written or counted in `omittedRecords`.
- A file that contains a closer had no write failure: after `#stop()` nothing more reaches the file.
- So for every closed stream, *visible rejected ≤ closer.rejected ≤ visible rejected +
  closer.omittedRecords*. With nothing omitted, the closer's count equals the visible count.
- One gap: `#rejection()` incremented the count before stamping its timestamp, so a throwing
  clock counted a rejection that was never written. Production's `new Date()` cannot throw; only an
  injected clock can. The increment now happens after the record exists.

**Change.** `streamContradiction` now also rejects (`lifecycle`) a closer whose rejected count
exceeds the visible rejected records plus its omitted records. This adds an upper bound to the
existing lower bound.
- **Rejected streams.** Their bytes are not uploaded and the job fails, as before. A failed native
  step stays `native-failed`, and the manifest and result are still uploaded.
- **Overflow streams.** With omissions, the stream remains valid partial evidence. Its summary keeps
  the visible `rejected` count and the closer's `omittedRecords`, and it stays incomplete through
  `records-omitted`.
- **Not added.** A tighter sequence-number bound (`closer.seq ≥ written + omitted + rejected + 1`)
  holds for the genuine stream (1285 = 1018 + 265 + 1 + 1). It is not enforced because it would
  invalidate the existing synthetic overflow fixture, which is a previous regression.

## Existing test lines changed, and why

Only two existing lines changed. Both changes are forced by the corrected contract, and neither
weakens an assertion.

1. In "finalize and the recorder accept only the exact manifest…", a sparse manifest with no run
   identity expected `['observations-absent', 'binding-unverified']`. That list is the defect
   itself. It now expects `['observations-absent', 'binding-identity', 'binding-unverified']`.
2. In "complete evidence needs a verified revision binding…", the real-CLI init inherited
   `process.env`. It therefore had a run identity on hosted CI but none locally. It now passes an
   explicit identified push run (`...github, ...push`) before its unchanged values. The assertion
   `"missing":["binding-contradiction"]` is unchanged and now deterministic everywhere.

## New maintained regressions (28 → 33 tests)

- **Run identity, in process.** Each of the seven values, missing (`''`) and malformed, gives
  `incomplete`/1, `['binding-identity']`, three files and `unavailable: [name]`. Push and pull
  request with OS, architecture and image unavailable stay `complete`/0. Several missing values
  give one marker, and a contradiction keeps its own. Failed native gives `native-failed`/0 with
  three files; skipped gives `not-run`/0 with two files.
- **Run identity, real CLI on the real checkout.** One child init/finalize pair runs with a run ID
  and gives `complete`, exit 0. The other runs without one and gives `incomplete`, exit 1,
  `["binding-identity"]`. Both publish the same three paths.
- **Closer count.** Equal counts, and a rejection that was itself the omitted record, stay valid.
  Three over-claims are `lifecycle`: the QA shape, more than visible, and more than visible plus
  omitted. A real passing recording whose closer was rewritten to `rejected: 1` gives `incomplete`/1
  for success and `native-failed`/1 for failure. In both cases the observations are not uploaded.
- **Genuine overflow compatibility.** A real recorder overflow has one visible rejection and three
  omitted ones (closer `rejected: 4`). It stays `valid`, three files, summary `rejected: 1`,
  `missing: ['records-omitted', 'records-rejected']`. It is `incomplete`/1 for success and
  `native-failed`/0 for failure, and every case result is still reported.
- **Recorder accounting.** A rejection whose timestamp fails is neither written nor counted, and
  the stream finalizes `complete`.
