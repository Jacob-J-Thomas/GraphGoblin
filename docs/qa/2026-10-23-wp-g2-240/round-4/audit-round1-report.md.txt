## Blocking findings

1. **B1 — An obsolete Refresh can replace a newer reading snapshot (P2).** `apps/web/src/api/queries.ts:292` (unconditional cache write at line 296). Load 200 rows for a type, hold Refresh A's HTTP response, clear the type filter, go Back, post another matching event, complete Refresh B, and load its second page. Release A. The UI drops from **200 to 100 rows**, removes B's newest event, restores A's older first ID, and reports **“Showing the newest events.”** The clean-store proof records winner `01M5PNXFVFK9YF5X1DFEBXW1Z0` replaced by `01M5PNXDA6116V8NPJSH7JP1V9`. This violates #240's deliberate-refresh/reading-position requirement. `cancelQueries` cancels query reads, not the older mutation; leaving the filter removes the pending-mutation guard without preventing its later cache write. **Smallest fix:** supersede/abort obsolete refreshes and allow only the current refresh generation for that query scope to commit. Cover leaving/revisiting the same filter and remounting while a refresh is pending; merely keeping the existing distinct-filter test is insufficient.

2. **B2 — A loaded pending receipt stops updating after an arrival pushes it past the first-page boundary (P2).** `apps/web/src/api/queries.ts:315`–324. Load the first 100 of 101 Events with the 100th row pending. Insert one newer event and make the receipt admitted. Subsequent first-page reads omit the pending ID; the retained next-page cursor excludes that same boundary row. The merge therefore keeps its old pending value indefinitely. The clean-store proof observed repeated first-page and continuation reads missing `01M5PNXG9V3NF2TZ9KFP2VH05B`, while its displayed state remained **“Pending admission.”** A deliberate Refresh plus Load more immediately displayed **“Admitted.”** This regresses the automatic receipt-recovery updates promised in docs/07 and docs/09 and keeps otherwise unnecessary history polling active. **Smallest fix:** reconcile all pending loaded identities even when newer arrivals displace them from the live head page, while preserving displayed membership and cursors. Add this exact boundary regression.
