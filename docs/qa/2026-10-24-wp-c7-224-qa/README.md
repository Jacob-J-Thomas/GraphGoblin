## 3. Defects

### D1 ??? minor: a completed run's inspector ends before the entire gateway drain

**Reproduction:** run a multi-node parent with a child timer plus another active keeper, queue an independent run, open parent and queued SSE inspectors, request one drain, release the parent while the keeper still executes.

**Expected from the literal case-1 wording:** the open SSE stream ends only after the drain; all other active work still holds gateway drain. **Actual:** the parent stream ends at its `run.finished` event while the keeper remains active. The queued stream stays open through the drain. Parent SSE ended 101 ms before the final keeper release; queued SSE ended 227 ms after it. Overall drain lasted 6417 ms. Both completion and queued recovery were truthful.

Evidence: [01-drain-family.json](evidence/01-drain-family.json), record `drain-finish` with `releaseAt=1792829357284`, `streamClosedAt=[1792829357183,1792829357511]`; [parent SSE](evidence/01-drain-family-parent-sse.log.txt); [queued SSE](evidence/01-drain-family-queued-sse.log.txt).

**Qualification:** docs/07 line 132 already promises closure on a run's terminal event, and the live stream followed that contract. This is a minor discrepancy against the brief's literal whole-drain ordering, not evidence of lost events or an implementation regression. The orchestrator should explicitly reconcile that wording with the terminal-stream contract; QA does not silently waive it or propose keeping completed inspectors open forever. No code was changed.
