## Resulting rule and evidence

Before printing the locked manifest or `Removing:`, the command refuses a readable preview followed by an unreadable locked read, even if the preview matched no workspace. The error includes the read failure and requests a rerun. It also refuses if the locked plan keeps a preview-selected run workspace path or its parent, including when both reads succeeded with different run IDs. No target is removed, the acquired lock is released, and the existing database remains available to identify workspaces on a rerun. Both reads unreadable preserve the damaged-store reset; an unreadable preview followed by a readable locked read may proceed.

The tests use the supported public `runResetCli.readStore` dependency, check the actual lock state at each read, assert stdout/stderr and exit codes, and compare every database, sidecar, artifact, workspace, key and unrelated byte. The nonzero/timeout/signal cases also prove an unchanged readable rerun finishes. The native case first reads a seeded SQLite store through the built reader, then spawns that same built copy owner during the locked read and kills its own `ChildProcess` with `child.kill('SIGKILL')` only after a complete private copy equals the original bytes. Its process close result supplies the failure reason. No simulated kill, taskkill or private production seam is used. The reaper removes the killed owner's proven stale copy while preserving an unrelated similarly named directory.

A real PowerShell file holder with `FileShare.None` proves that stale-copy cleanup refuses with a single actionable line naming the copy and telling the operator to close the program holding its files, check permissions and run the reset again. The following line says `Nothing in the data directory was changed.` Cleanup may already have removed part of its own stale copy, and the ownership marker remains until all payloads are removed. Releasing the file lets the next reset clean the remainder and complete.

The first post-fix focused run passed every safety assertion but failed its final temp-root emptiness assertion because `tsx` had created its unrelated cache (`expected [ 'tsx-CodexSandboxOnline' ] to deeply equal []`); [fixed-tests.log.txt](fixed-tests.log.txt) preserves that test failure. The assertion now checks reset-copy directories and explicitly preserves an unrelated control. The corrected focused run passed all eight tests: [fixed-tests-corrected.log.txt](fixed-tests-corrected.log.txt). Initial lint found six `require-await` errors in the new test's immediate-value dependencies; those callbacks now return `Promise.resolve` directly.

The existing bigint root/ancestor/entry identity checks are unchanged. Node still has no handle-relative removal, so an external process can race between a check and `unlink`/`rmdir`; the reset lock prevents concurrent GraphGoblin changes. This follow-up does not claim to eliminate that race.
