**What I checked**
- **The fix:** both places that mark a run failed now clear its wait: `failRun` (live) and the rebuild from the event log in `completeFromLog`. These are the only two code paths that ever write a failed status. The explicit `waiting: undefined` is written to SQLite as NULL.
- **Effect on other code:** I traced every reader of a failed run's `waiting` (parent wake, timers, drain, input/signal, recovery, web wait panel, MCP). None changes behavior.
- **Effect on Resume (the important one):** a resumed failed subloop parent now finds its child from the event log instead of the old stale wait. The two give the same answer because a child and its start event are written together (#320). The existing #251 tests and the mapping-retry test already exercise this path and pass; the heartbeat beat count is also unchanged.
- **W2:** the gate held the parent's failed write before it reached SQLite. An independent reader confirmed `run.failed` was committed while the parent was still `running` with its original wait. Only then was the exact process killed. A normal restart of the same physical database (same file ID) finalized the parent with the wait cleared, one unchanged failure event and a single script marker (no rerun).
- **W4:** the genuinely old finalized baseline rows came through a restart byte-identical, stale wait included, so nothing was migrated.
