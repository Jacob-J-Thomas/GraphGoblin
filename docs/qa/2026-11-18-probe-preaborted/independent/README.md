## Resource ownership and interpretation

The runner's TEMP root and Vitest's own nanoid entry are distinct from case-owned roots. The worker's final observation retains only its unchanged beforeEach runner entry; `vitest.close()` removes that entry, leaving the runner TEMP root empty. The outer wrapper then removes its own root after recording the state. A still-existing runner directory before that last step is expected ownership, not a leaked test root.

The injected removal-fault control is the deliberate exception: its empty case root remains after Vitest closes, is observed by the passing successor, and is removed externally only after the raw failure and cleanup receipt are recorded. Every other case-owned root is absent before external cleanup. Environment restoration and native process absence are checked before disposal.

Forwarding only a past signal could stop child creation yet still turn cancellation into readiness failures. The real skipped statuses and zero root allocations rule that out. Conversely, converting later cancellation or timeouts into skips would hide real failures; the paired in-flight, ordinary and timeout results rule that out. No external finish hook or successor repair was added to make the maintained ownership pass.
