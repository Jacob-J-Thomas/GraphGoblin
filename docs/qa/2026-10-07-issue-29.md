## Behavior verified

- Exact raw-byte body HMAC matches GitHub's published vector; authentication precedes fatal UTF-8 decoding and strict JSON parsing. Malformed signatures, invalid JSON/blank body and secret rotation cases are covered. Timestamp signing retains its existing window behavior.
- Raw-content replay survives republish, filter changes and signing-header changes. Distinct bodies sharing an authored key consume a terminal `deduplicated` receipt and return `DUPLICATE_KEY`; repeating those bytes returns `REPLAYED`. Concurrent, restarted, filtered/pending and historical timestamp-run cases pass. Scope is owner/loop/node across versions.
- Red race cases originally spent cap 1 on an old key after recovery or while its allocated webhook intent remained pending. Atomic items admission now skips committed keys and pending reservations, preserving the cap for the tail without identity reuse/enqueue. The reverse ordering—poll commits before an old body claim—is also covered. Transient failure retains reservations; permanent failure releases them and cannot later dispatch that intent.
- SQLite tests prove run/initial thread/sequence-1 event/receipt/link atomicity, rollback and notification after commit. Recovery/deletion tests cover claim serialization, pending pins, lost acknowledgement, boot plus bounded periodic sweeps, safe permanent failure and persisted capped backoff.
- Items polling validates every candidate before I/O, caps candidate count/dispatch/stdout, drains the unseen tail and persists keys through restart. Legacy text/exit-code probes remain supported. Credential-bearing response headers and raw transport/process diagnostics stay out of saved trigger evidence.
- Five controlled recipe tests execute the exact documented Node wrapper with only its child CLI redirected: pagination/curation, cap/drain/restart, >200 refusal, byte bounds, safe failure and current-state limits. The unchanged wrapper also passed a CRLF/LF two-line proof. Root separately verified installed gh and the complete wrapper read-only: 23 curated items across at least 12 pages. This proves command compatibility, not real webhook delivery or a live poll-trigger run. No model calls or GitHub mutations were used.
