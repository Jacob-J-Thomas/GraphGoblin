# Preflight catalog fixture QA

The shared catalog fixture seeds SQLite in a unique staging directory, requires a complete TRUNCATE checkpoint, and closes the writer before copying only the main database to the inspection path. The exclusive copy requires a new destination. That destination has no writer from fixture setup whose native cleanup could remove its sidecars. [Issue #584](https://github.com/Jacob-J-Thomas/GraphGoblin/issues/584)

The original macOS API coverage run exited 1 with 2,292 passing, one failing, and 37 skipped. The missing Codex seed case passed preflight's result checks, then received ENOENT opening the WAL it had just listed. A native control reproduced that sequence with scheduled finalization and preserved the DB bytes. The DB-only copy passed under the same schedule, and a fresh path preserved a genuine 8,272-byte committed WAL. A control on the exact implementation base again passed both fresh-path cases. The WAL on the reused writer path survived that second run, so the original failure remains an intermittent observation. [Original native control](raw/lifecycle-original.json.txt) · [Control on implementation base](raw/lifecycle-exact-base.json.txt)

The installed libsql client returned one checkpoint row with named numeric values `busy=0`, `log=0`, and `checkpointed=0`. The test requires those values before copying. Source comparison confirmed byte equality for both snapshot helpers, the stored-row and migration readers, the URL setup, cleanup, and every test body. This preserves the percent-encoded external store, missing Codex and Claude seeds, ordinary startup seeding, catalog metadata and refusal checks, and the absent, explicitly empty, framed, and mutated WAL cases. [Checkpoint result](raw/checkpoint-shape.json.txt) · [Source and check binding](raw/source-and-checks.json.txt)

On Darwin arm64 with Node v22.22.2 and pnpm 12.8.1, the API dependency build passed and all 73 tests across the three focused preflight files passed. API typechecking, lint, scoped formatting, and diff checks passed. Full API coverage and applicable CI are required on the integrated candidate.
