# WP-F4 independent QA, round 3

Revision: `b80c9fdfb001e020bdfc1b9c7c15e5f910d33766` (confirmed before testing; detached HEAD). Windows PowerShell, Node `v22.14.0`, installed dependencies from this head. This is independent fake-provider QA. No provider turn, product/test source edit, Git index change, commit or branch operation was performed.

## Scope and evidence tiers

Systems exercised: inference handler and logical-visit provenance; schema repair; both harness families and their retryability rules; public session selection; SQLite event history and run projections; REST, generated api-client and MCP `get_run`; manual admission/authentication; replay and subloops; restart/recovery; inspector timeline; documentation and repository gates.

Manual API instances used `127.0.0.1:5890` (qualified matrix), `5891` (built inspector), `5892/5893` (native Claude result-only recovery) and `5894` (repair-start HTTP driver), with exclusively created `%TEMP%/gg-qa-f4-*` stores. The repository suites use their existing automatic disposable fixtures. The owner's app, ports and store were not contacted. Dependencies were present; none were installed or linked. [Environment](environment.json).

The matrix starts the real built `apps/api/dist/main.js`, creates its API key and verifies 401/200 authentication, then uses a separate built composition with public dependency injection for controlled turns. The repair driver uses the built API over real HTTP and SQLite, a key created by the binary, the public harness port and the real adapters. Codex synchronous refusal is injected through its public `clientFactory`; Claude synchronous refusal is a fake `HarnessPort` call. Asynchronous CLI scenarios run the repository's fake executables through the actual adapters. This establishes the observed engine/adapter protocol boundaries, not provider-side delivery or durability.

## Reproduction recipes

- **R1, repair:** publish a numeric-output inference B whose initial accepted result is invalid; previous/named policies first complete A. B persists its exact Unicode/multiline repair task on its completed session. Refuse the repair synchronously, asynchronously through the fake harness, or through the real adapter/fake CLI. Read the failure and events; compare REST, api-client and MCP; request Resume; check exact prompt/session and turn identity, or 409 with no further harness call. Accepted uncertain generic failures use the continuation text and the per-harness retry rule. A false-positive retry flag cannot permit pinned refusals.
- **M1, ordinary matrix:** publish/start the named harness/policy/scenario, with A before B for inherited policies; inspect B's turn/submission events and all three run projections; switch the fake to a successful response; request Resume and inspect its prompt/session or refusal. Every Claude init-only case must first prove a validated B `harness.session`, so a readiness failure cannot masquerade as a stream cut. The fake CLI alone gets a 60-second readiness startup allowance; production defaults are unchanged.
- **M2, lifecycle:** execute the specific action named in the row: kill the owned CLI or API at a durable checkpoint, restart the same store, replay/fork, create a child, revisit, cancel, or start concurrently. Assert visit isolation, exact call counts and the named recovery behavior.
- **N1, result-only recovery:** complete A; start B with previous/named session selection using the shipped scripted Claude result CLI. Wait for a validated successful result and durable `submitted / claude.result`, while usage and node completion are absent; hard-kill the built API and restart its same store. Assert one continuation on the recorded session, no fresh call, no missing-session/failure event and successful B completion.
- **B1, browser:** serve the built web/API with fake turns; open each actual Edge inspector; correlate REST visit/turn IDs and submission classification; select both timeline rows, use keyboard Enter, reload, and repeat at 390 px. Screenshots were viewed, hashed and removed for text-only retention. Provenance values are REST-only; the UI shows selectable event type/node rows, as docs 09 now states.

Copy a retained `.mjs.txt` driver into a `%TEMP%/gg-qa-f4-*.mjs` file and run it from this worktree with Node 22. Set `QA_REVISION` to this exact head for the matrix. The corrected repair driver can run all cases; the recorded affected-case replay used `QA_REPAIR_AFFECTED=1` and `QA_REPAIR_EVIDENCE=repair-start-affected.json`. Gate recipes are in [gate-driver.ps1.txt](gate-driver.ps1.txt). No product fixture was edited.

The original passing cases and corrected affected execution are retained separately. No product assertion was weakened: the real Claude CLI's normalized non-retriable refusal remains non-resumable, while explicit pinned codes are separately tested with `retriable: true` for both families.
