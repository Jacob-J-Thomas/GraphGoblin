## Remaining limits (no defects found)

1. **Startup not run for the disabled-row case:** the native script doesn't start the server for it, so startup accepting a disabled stored Codex row is only shown by tests.
2. **Physical checks only compare DB and WAL bytes:** the shared-memory file and other directory entries aren't compared. For the missing store, only the database file's absence was checked physically; the data directory staying absent is shown only by tests.
3. **Same-process connection lifetime:** the earlier review found that the SQLite library can keep a connection open until garbage collection, in both the base and the candidate. My physical evidence ends each preflight process, so it says nothing about that issue. The tests run in one process, and their byte checks don't prove the connection was released.
4. **"No provider turn" is inferred:** it rests on the fake CLI throwing on turn commands and no run being started, not on a process trace. No live models, accounts or Ollama were used.
5. **Unread logs and truncated output:**
   - The baseline JSON came from the packet; I didn't regenerate it.
   - Two of the #546 cases have no baseline row.
   - The test summary was cut to its last 24 lines, so I saw the totals but not all 97 test names.
   - The small stderr outputs from build and focused weren't readable with the four allowed commands.
6. **Possible difference for already-migrated stores (source observation only):** preflight reads the full catalog, while startup uses the read made before migrations. The Codex results matched in the real-process runs, and other row shapes weren't tested.
