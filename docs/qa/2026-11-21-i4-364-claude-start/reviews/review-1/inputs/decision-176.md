# D176 — Diagnose Claude process start refusals without false installation claims

Authority: owner-delegated blocker decisions, subject to the consolidated decision catalogue and owner QA. Source candidate is 99f1de7863dfc6a05b63a9140f7fc7a6833fcb20, tree 911b2400b7622b5b04b58b3b03092d9ea90f55a3, based on 02351e2fb932b3be44e7cc3fb3943a61d568226c. Actual Claude Opus 5.5 xhigh implemented it; this record is not independent approval.

Select bounded, post-refusal diagnostics only when no child PID was assigned. A proved missing absolute executable remains HARNESS_NOT_INSTALLED and restorable. A missing or non-directory turn working directory is HARNESS_INVALID_CONFIGURATION and pinned non-resumable. An ambiguous start refusal stays HARNESS_TURN_FAILED/unknown and does not assert a missing executable. A read-only stat failure cannot prove an existing directory startable. The Windows long-path fact may be mentioned as a limit without declaring it the proven cause. No PATH resolver, fallback command or trial launch is added.

Cancellation/deadline during the diagnostic settles without waiting for stat or inventing a timeout. Proven refusal remains definitely-not-started; termination/abort precedence is preserved. Native probing also exposed ENOTCONN on pipes for a never-started long-path child. Include guarded pipe error handling at this same process boundary: ignore a never-started child's pipe failure, but treat a started child's output loss as potentially hiding acceptance and terminate its owned process tree. Do not downgrade output loss to a safe refusal based on later stderr.

Alternatives declined: map every ENOENT to missing CLI (demonstrably false for existing binaries with invalid cwd); mark every existing cwd startable (Windows native evidence contradicts it); retry or fallback (could repeat effects); global path/environment changes (affect concurrent work); omit pipe error handling (native reproducer can crash the process); broadly change other process adapters based only on similar source (requires separate evidence and scope).

Author evidence includes the native baseline, focused tests, mutation checks and scoped Claude-folder coverage. The full infrastructure coverage attempt failed, including symlink EPERM failures; no aggregate coverage pass is claimed. Independent GPT review, fresh native/public QA, normal CI/coverage and final review are still required. Preserve the original failing probes and author report. No deployment, issue closure or owner acceptance is implied.
