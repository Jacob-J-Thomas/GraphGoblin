## 7. Decisions and parameters

The engine continues to own the per-completion deadline. A positive `LoopSettings.structuredTimeoutMs` is configured milliseconds, pinned per run; omitted/null is Unlimited with no finite default. Limited's 120000 ms suggestion is unchanged. This limit governs LLM decision evaluations and output-transform repairs through the structured port. Same-session harness schema repairs follow node/run deadlines. No cost, token or usage budget is added.

Choose a data migration to preserve existing retired-definition refusal/finalization behavior without a tolerant reader. The migration materializes only absent deadline fields as null across every stored copy listed above; explicit authored values remain intact. Snapshot protection is lifted and restored inside the migrator transaction. Migration 0020 avoids reserved 0018 (WP-D4) and 0019 (WP-C7); journal/snapshot metadata accompany it. These are implementation choices, not new owner-approved numeric defaults.

The schema-repair test uses a 50 ms structured limit, a one-second node limit and a two-second fake response to separate the two boundaries; it checks running at 999 ms and failure at 1000 ms. The cold-reopen runner uses 90-second startup and 30-second HTTP/shutdown watchdogs to bound its own native checks on this loaded host. These QA engineering parameters leave the product defaults unchanged.
