## Defects

### R1 (Medium): a retained template-directory run that never resolved its directory blocks all workspace reclamation

**Cause.** Migration 0022 inserts a `workspace_references` row `pending:<runId>` with a `NULL` path for every run whose loop uses a **template** working directory. The row is deleted only when that run records a workspace use, or when the run itself is deleted. `workspaceReferenced` treats **any** `NULL` physical path in the table as referencing **every** workspace.

The engine resolves the working directory only lazily, for script, inference, heartbeat and file-return steps. So a template run that ends before such a step keeps its unknown row for as long as it is retained. Examples: it exits early, it fails before such a step, or its template renders empty. While it is retained, no approved workspace anywhere in the store is reclaimed.

**Reproduction** (`template-unknown.mjs`, `18-template-unknown.log.txt`, `ui-notice-template-unknown.png`):

1. Create a loop with working directory `{ "kind": "template", "template": "{{ trigger.payload.dir }}" }` whose nodes are only trigger and exit. Run it once with `dir` set to an existing folder. It succeeds and stays retained.
2. Run a plain temp-workspace loop twice (2 files each, no links), wait for both to finalize, then preview and confirm them delete-ready.
3. Set pressure (0.5 GiB free of 100 GiB) and wait three timer passes.

- **Expected:** the two approved runs are deleted and their unshared, unaliased workspaces are reclaimed. The step-1 run never used any directory.
- **Actual:**
  - Pass 1: `pressure`, `deletedRuns: 2`, 90 bytes removed (their transcripts). Both workspaces stay on disk.
  - Passes 2 and 3: `no-eligible`, `pendingResources: 2`, `preservedResources: 2`, workspaces still on disk.
  - Edge shows "Storage is low. No approved eligible history could be cleaned. Review history you can remove or free disk space. Shared, linked, unproven or deferred resources are kept."
  - After the step-1 run is approved and deleted, the next pass removes both workspaces (4,000 bytes).
  - Variant V2: a template run whose directory renders empty fails ("working directory template rendered to an empty path") and blocks reclamation in the same way.
  - In the realistic store (phase D), one such run held three approved workspaces for three passes.

**By reading migration 0022 (not run).** Its backfill inserts the same `pending:` unknown row for every pre-existing run of a template-directory loop, and those runs never record a use afterwards. A migrated owner store with any such run would therefore reclaim no workspace until all of them are deleted.

ADR-0060's resource table says "unresolved retained template workspaces block removal". It does not say that the block covers the whole store and lasts as long as such a run is retained. The notice also gives the user no way to find the blocker.

**Severity: Medium.** No data is lost, but under pressure workspace reclamation (in practice the only file reclamation, see O1) stops silently in plausible stores. The user is invited to approve more history that will free no files.

### R2 (Medium, regression): a data directory reached through a junction or 8.3 short name makes runs fail

`OwnedRunResources.directory()` (new in this PR) throws "Managed resource root is a link" when `realpath(dataDir)` differs from `dataDir` after case folding. `config.dataDir` is not resolved to its physical path first.

**Reproduction** (`datadir-alias.mjs`, `19-datadir-alias.log.txt`; also `16-artifact-alias.log.txt`, last section):

1. Create a folder and start the API (QA composition, `GG_DATA_DIR`) with that folder spelled four ways:
   - its plain path;
   - the same path in different letter case;
   - its 8.3 short name (`...\Temp\GG1A44~1\PHYSIC~1`);
   - a junction to it.
2. In each case run a loop with a temp workspace and an inference transcript.

- **Expected:** the run succeeds in every case. `origin/main` composes `FsWorkspace` and `FsArtifactStore` with no such check (code reading; `main` was not built here).
- **Actual:**
  - Plain path and different case: `succeeded`.
  - Short name and junction: `failed`, `INTERNAL_ERROR` "Managed resource root is a link". Every run that needs a temp workspace or publishes a transcript fails.
  - A trigger-to-exit run with neither still succeeds.

**Severity: Medium.** The product becomes unusable for normal loops whenever the data directory path contains an alias. Plausible setups include a junctioned or redirected profile folder, a short-name path, `/tmp` on macOS (a symlink to `/private/tmp`), or a home directory that is a symlink. No data is lost: it fails closed.

### R3 (Low): focus is lost after confirming or withdrawing from the Runs selection

**Reproduction** (`ui-edge.mjs`, `ui-edge-2.mjs`):

1. In Runs, select one or more runs.
2. Choose **Review delete-ready history**, then **Confirm delete-ready selection**. Or choose **Withdraw delete-ready mark**, then **Confirm withdrawal**.

- **Expected:** focus returns to a sensible control, for example the review button as in the first QA, or the count or the table.
- **Actual:** `document.activeElement` is `body` ("focus after Confirm body", "after withdraw ... focus body"). The D4 fix clears the selection, which disables the dialog's trigger button before focus is restored to it. Keyboard and screen-reader users lose their place (WCAG 2.4.3). The inspector is unaffected, because its single-run selection stays.

**Severity: Low.**

## Observations (not counted as defects)

- **O1 (unchanged). Artifacts are not reclaimed at realistic size.** None of the approved transcripts in the 488-run store were removed (proof budget of 2,000 documents / 2 MiB). In store A, 61 approved transcripts stay pending, and the status reports them as kept. Small stores do reclaim them (`16-artifact-alias.log.txt`, control).
- **O2 (unchanged, ADR-0033).** Loop deletion frees no files. This was not re-measured.
- **Aliased artifact directories fail closed for new runs.** After the transcript folder or the artifacts root becomes a junction, every inference run that captures a transcript fails with `INTERNAL_ERROR` "Artifact directory is a link". This is safe, but the message gives the user no guidance.
- **Run failure details carry full stack traces with local filesystem paths.** They appear in `run.failure.details.stack` and in the API run read (seen in `16`, `17` and `19`). This predates this PR in kind and is outside its scope.
- **Unconditional sweep.** Each pressure pass starts a fresh reference sweep that realpaths up to 2,048 recorded references, even when nothing is pending. This is from reading `workspace-references.ts`. The measured latency in the realistic store was unaffected.
- **In-progress counts.** While `cleaning` is true, `GET /system/storage` shows zero counts for the running pass until it concludes. The first `pass` line in `12-latency.log.txt` was read mid-pass.
- **The race in case (b) leaves retained configuration dangling.** Later runs of that loop fail with `ENOENT`, as ADR-0060 accepts.
- **Dialog content (first QA O3) is unchanged.** It still lists bare ULIDs.

## Method and test seams

- **Composition.** `qa-server.mjs` is unchanged from the first QA. It composes the **built** API as `apps/api/src/main.ts` does: `createContainer`, `container.start()`, `buildApp` and `listen`, whose `onListen` hook starts the background cleanup as in production. It uses a file-backed SQLite store in a disposable data directory, the real clock and 60-second timer, real process scripts, the real filesystem and HTTP, and the web build. It differs only in two public `ContainerOverrides`:
  - **`storageCapacity`:** the public `StorageCapacityPort` (ADR-0060), fed from a JSON control file. Readings are fixed, the production `FsStorageCapacity`, or a throw.
  - **`harnesses`:** `FakeHarness` from `@graphgoblin/engine/testing`. No live provider calls were made, and no live-provider behaviour is claimed.
- **Pass marker.** `QA_CAPACITY_READ` is printed by the QA port; it is the only instrumentation.
- **Browser.** Microsoft Edge 156.0.4314.42 through Playwright 1.63.0 (`channel: msedge`, headless).
- **MCP.** The built `apps/mcp/dist/main.js` in HTTP mode.
- **Kills.** `child.kill('SIGKILL')`, which is `TerminateProcess` on Windows. `interrupt-phases.mjs` triggers kills from observed filesystem state of the quarantine folder and classifies each kill from the stopped store.
- **Store inspection.** `inspect-db.py` (python `-I`) runs on a copy of the stopped store. It is adapted for this re-check in two ways: quarantine names come from the original key of a staged `quarantine:` job, and it adds workspace-reference counts.
- **Reused and adapted scripts.** These were copied from the first QA record, which was not modified: `qa-server.mjs`, `qa-lib.mjs`, `integrated.mjs`, `interrupt.mjs`, `interrupt-reap.mjs`, `d1-repro.mjs`, `startup-latency.mjs`, `latency.mjs`, `ui-edge.mjs`, `ui-edge-2.mjs`, `ui-edge-3.mjs` and `inspect-db.py`.
