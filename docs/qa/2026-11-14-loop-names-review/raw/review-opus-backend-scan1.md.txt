## 2. Non-blocking follow-ups
1. **No test for reusing a deleted loop's name (P3, gap added by this PR, DEFER-ISSUE).** The code is correct as written: name admission (`admitLoopName`, `loop-names.ts:37-44`) only reads current `loops` rows, and `delete` (`loops.ts:502-531`) removes the row in its own transaction. But no committed test or QA artifact covers it. Smallest fix: one API test that creates "X", deletes it, then creates " x " and expects 201.
2. **The user guide overstates (P3, added by this PR, DEFER-ISSUE).** `docs/guide/02-build-a-loop.md:44` says GraphGoblin "never picks another name for you". System Chat loops do get an automatic "… copy" name (`chat.ts:192,328`, `loops.ts:560-562`). Only ADR-0073 documents that. Smallest fix: limit the sentence to loops you create, rename, import or copy.
3. **Three different name-matching rules (P3, mostly existed before, DEFER-ISSUE).** MCP's loop lookup (`resolveLoop`, `apps/mcp/src/tools.ts:52-53`) compares `ref.trim().toLowerCase()` with `l.name.toLowerCase()`. A loop stored as " Foo " or "Nightly  Triage" can't be found by its normal spelling. The web app also keeps its own copy of the comparison key (`apps/web/src/lib/loop-names.ts:8`). Moving `loopNameKey` into contracts, next to `isStorableLoopName`, would give one shared definition.
4. **One test proves less than its name says (NO-CHANGE).** The test at `loop-names.test.ts:48` would also pass under a deferred transaction, because the INSERT would still fail with `SQLITE_BUSY` in WAL mode. I confirmed BEGIN IMMEDIATE from the library source instead:
   - drizzle `libsql/session.js:61` calls `client.transaction()` with no mode;
   - `@libsql/client` `sqlite3.js:323` defaults the mode to `"write"`;
   - `@libsql/core` `util.js:3-5` maps `"write"` to `BEGIN IMMEDIATE`.

   No duplicate can be created either way.
5. **Old malformed draft names are refused on save, not at startup (NO-CHANGE).** An older build could store a lone surrogate in draft JSON while `loops.name` holds U+FFFD. Startup does not report this. Instead, the loop's next draft save returns 400 `LOOP_NAME_INVALID` until it is renamed. That matches the contract, which only requires startup refusal for duplicate and NUL names.
