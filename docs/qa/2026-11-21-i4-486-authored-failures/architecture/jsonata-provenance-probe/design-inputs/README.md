## Source-owned public causes

1. Reuse `TEMPLATE_ERROR`, `EXPRESSION_ERROR` and `MUTATION_ERROR`. Newly recognized authored errors are non-resumable because the run pins its definition and re-execution can repeat work. Refer the author to the field and a corrected version. Existing explicit Replay remains a separate run with ordinary observation and consent requirements. Preserve abort, stop, deadline and termination handling.
2. Each helper **calls a concrete evaluator** (`renderTemplate`, `evaluateExpression` or `evaluatePredicate`) with fully prepared arguments and catches only the matching rejection. No arbitrary function or promise parameter. Prepare views, bindings and JSON conversions outside. The manager's `services.render` routes through the concrete renderer; shared selectors report the site and item index at the predicate. For transforms reuse the narrow operation hook plumbing of `applyMutations`/`runMutations`/coerce repair. Implement a distinct inference mapper for safe public text; P01's Mutate mapper retains its existing message contract. No port catch or global dispatcher interprets a class, name or code as proof of author origin.
3. The public message includes a fixed field label and safe reason plus one-based ordinal when relevant. JSON details use fixed `boundary`, zero-based indices, finite `operationKind` where applicable and `cause:{code,message}`. For maps and headers, ordinal means the order of `Object.entries` on the pinned object: own enumerable string keys, array-index keys first in ascending order, other string keys in insertion order. Do not publish headers, user-chosen map names, file paths, templates, echoed values, schema data or exception details as locators. Receipt/beat count or completed file count may be reported only when observed. **Reserve top-level `details.childRunId`, `childNodeId`, and `childDetails` exclusively for the existing actual child-failure wrapper.**
4. Build the new cause from evaluator facts: Liquid parse/render reason and validated numeric token line/column if available; JSONata compile/runtime, depth/time/unsafe-regex, assertion/explicit error and known evaluator code/numeric position if available; safe fixed directions for an invalid target, patch, regex or schema operation. A supported fallback is “The selector could not evaluate this item. Check its input type.” Keep safe facts in memory separately from `DomainError.details` (the API emits that existing field). The only literal label exposed is the argument of a **root, direct built-in** `$error` call with one static string literal and corresponding runtime D3137. Require 1–128 ASCII characters, every character in `[A-Za-z0-9 _-]`, verified against the entire string including its last character. Use the AST literal itself, never the interpolated exception text. A conditional/nested call, dynamic `$eval`, `$assert`, overlong or otherwise ineligible label receives fixed copy. Decision route expressions retain their existing fixed message even with the same literal. Cap the composed cause at 1,000 UTF-16 units including ellipsis, and observe the existing 10,000-unit failure-message ceiling. No full inputs, prompts or raw diagnostic objects enter new details.
5. New authored/canonical internal diagnostics can carry the underlying error privately for one correlated run/node/field log record (plus turn ID where known). Do not serialize it into the row/event. General harness, historical rows, P01/P02 and B25 retain their existing text contracts. In particular, unknown harness errors can already publish adapter-supplied text, and the file-return channel can publish a bounded external error message. Those are explicit privacy limits of this change. Verify the new projections and the unchanged controls against different synthetic markers.

## Inference, in execution order

- Reconstruct the logical visit from events. Guard `delivery-uncertain && !canContinueTurn(pending)` **before** model resolution; that guard needs no model and retains the existing recovery failure. Otherwise resolve model/effort. `session-missing` then uses those resolved facts to form the existing actionable missing-session failure, before workspace/transforms/files. If the resolver itself fails, attach known prior turn provenance as **information only** to the existing typed/error projection. Preserve its code, text, details and resumability (restorable catalogue failure remains resumable). Do not manufacture model/effort or emit a missing-session failure without the required facts. A later eligible Resume can restore resolution and reach the original fresh-session action. [`inference.ts:295–367`, `run-manager.ts:1540–1559,2444–2492`, `inference-turn.ts:159–182`]
- Separate pre-intent preparation from invocation. For a known prior pending task attach its original `provenance(pending)` (IDs, kind, actual submission and session) to preparation failures without creating a new intent, submission/status write, acceptance marker or cleanup of an old handle. New visits omit that field. The existing earlier `run.failed.inference.retry` reconstructs the exact otherwise-unrecorded prompt, harness, optional context and selected session. A later failure without `retry` updates the existing pending task. Preserve the fold; no new retry object or `intentUnconfirmed` flag is emitted for preparation. Respect bypass on saved prompt, exact positive refusal retry, usable-session continuation, and explicit fresh-session selection both with and without a saved prompt. Eligible attempts still reconstruct transformed views and materialize files as today, including the context used by repair. Earlier successful coerce calls/file writes can survive a later authored failure; add no retry or compensating writes. Exactly-once prep across a crash before recorded intent is outside this contract. [`inference.ts:303–396,445–532`, `inference-turn.ts:36–80,109–136`]
- B17's two rare rerenders operate on recognized *system* prompt constants after the first render succeeded. Locally map the pure rerender rejection to the existing safe engine-owned `INTERNAL_ERROR` projection, current inference node, ordinary internal pre-turn resumability (true). Keep cloning, view construction and `window.fits` outside both concrete renderer catches. Retain the surrounding timeout-disposal/abort priority and existing `contextWindow`/`fits` provider mapping. A direct typed internal projection can pass the existing typed-error branch; no general harness mapper change is needed. Saved/fresh prompts remain ineligible for trimming. [`inference-context.ts:13–17,42–70`, `inference.ts:397–443`]
- At B18/B19 only, tag the **source-owned** failure when repair prompt rendering or output mutation fails after a successful provider result. Keep the last actual turn ID, kind, session and visit; B18 precedes establishing the next repair intent. If this mapped cause survives normal cleanup/timeout/evidence precedence, add fixed `details.phase:"after-result"` and a sentence such as **“GraphGoblin received the provider result before this step failed.”** Keep conservative `delivery-uncertain` for its unfinished graph persistence (a result cannot mean an unsent turn); store through the existing submission path. Never synthesize an acceptance marker or alter the durable-acceptance rules. The winner is non-resumable even with a usable session. For exactly that winning after-result cause omit the generic unusable-session uncertainty suffix, even if the harness reported no session. If a higher-ranked pinned refusal, missing-session, termination, cancellation, stop or timeout wins, it keeps its existing code, copy, metadata and recovery. Use source-specific ownership of the winning failure, never merely a `details.phase` key test on arbitrary port errors. Artifact publication, invalid provider output and post-result storage failures keep their current publication and submission policies. [`inference.ts:598–705,707–879`, `inference-turn.ts:136–182`]
- The harness evidence fold, adapters, provider text, retry, submission fallback and family-specific resumability stay intact. Verify actual same-class exceptions **and** name/code lookalikes at every callback against the explicit table. Synchronous throw before a handle, iterator/result rejection after a handle, prior stronger evidence and secondary cleanup are different observations. Preserve #427's recognized pinned refusal text and existing suppression of an automatic resend after acceptance. ## Workspace, child ownership and persistence

On a successful directory cache miss, RunManager passes `WorkspacePort.resolve(resolvedSpec,runId)` the existing temp or fixed spec union members only. For a template, on the engine side precompute the view, render directly, apply the identical `.trim()`, and convert a nonempty result to fixed. A genuine template rejection or empty trimmed result returns a local invalid-template value. Keep fixed paths as given, existing relative→absolute/mkdir behavior, temp ownership and fixed/shared canonical-use journal. No second public spec, stored schema, migration, format or history rewrite. Set the directory cache only after successful port resolution. Node callers convert the invalid-template value to the node's typed error. A thrown port exception stays outside that conversion. [`run-manager.ts:2506,3338–3351`, `infrastructure/src/fs/{workspace.ts:14–35,owned-resources.ts:92–124}`]

In the existing file-channel try block, an engine-local invalid-template result supplies the safe bounded delivery message and skips port resolve/write. Feed this one path into the **existing** failure-receipt catch (e.g. throw an ordinary error constructed solely from the local safe message). Keep the success receipt append inside the existing channel try, its existing catch with `describeError(error).slice(0,4000)` and the failed-receipt append where they are. Other channel inputs, logging/error text, receipt persistence/reconciliation and terminal run status retain their behavior. This adds no public run failure, duplicate receipt attempt or new delivery retry mechanism. [`run-manager.ts:2961–3038`, `adversarial.test.ts:379–417`]

Parent input evaluation precedes atomic child admission. Parent output mapping runs after the child's actual terminal result; retain bundled `child_run.finished` records with its own success/failure and deduplication by terminal sequence. Parent mapping faults use the parent subloop node, bounded location/cause and no child-failure keys. For actual failed children use the existing wrapper, unchanged. Follow its linked child snapshot for authoritative `failure.inference` including retry evidence, and follow the next link at depth two. No projection copies the child's turn into the parent. Existing `childFailureForPublication` and legacy sanitization/ownership stay intact. [`subloop.ts:188–231,238–326`, `failure-publication.ts:48–56,88–130`, `run-recovery.ts:61–83`]

Stored failure JSON and `run.failed` share one new projection, with current message bounds. REST snapshots and MCP full results can carry structured details; their reduced summaries and the inspector alert need useful standalone messages. The optional typed phase and bounded cause fit current JSON details. This scoped design avoids global error dispatch, replay of deterministic failures, a durable transformed-thread snapshot, changes to historical records, and changes to public/provider policy elsewhere. Independent QA, opposite-family review, exact-head/current-target CI, coverage and the reserved final audit remain separate gates.
