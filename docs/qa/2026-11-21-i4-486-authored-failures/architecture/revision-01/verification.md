## Positive and negative public-method matrix

1. **All authored branches.** Drive RunManager by publishing valid loop versions and starting/settling runs. For each changing row in the matrix assert the exact code, human-useful message, safe cause, field, ordinal, owning node and Resume eligibility. Test each distinct template and predicate site, both LLM/classifier arms, input/output selections for messages/artifacts and fresh/continued success paths. Include expression `$error("qa-381-output-mapping")`, ordinary filter arity/runtime failure, valid Liquid with a bad timestamp, blank rendered directory, bad custom patch shape and nonmutable patch. Validate operation index after at least one preceding valid mutation, including coerce repair prompt and target errors. Use runtime-valid failing fixtures where authoring validation rejects syntax earlier. For a canonical-only render that cannot fail through supported inputs, exercise the source-local renderer seam and separately use a real canonical loop to check trim/admission. Report the evidence tier.
2. **Semantic privacy and bounds.** For a direct literal author error assert the approved public label. For dynamic `$error`/assert/nested eval, a data-bearing Liquid error, rejected timestamp, illegal patch and unknown library message place independent synthetic private markers in payload/data, callback diagnostic, path, stack and arbitrary details. Assert new failure fields contain no marker, raw source or rendered value. A marker deliberately present in a *legitimately stored authored input, prompt or progress item* may be present in its own record; use independent tokens for private diagnostics and compare the correct projection. Test short, exactly 1,000 and over-limit cases including multibyte/non-BMP text; bounds count UTF-16 units with any ellipsis included. Verify new child projection rejects malformed/unexpected keys and still sanitizes legitimate historical internal/recording slots. Avoid attempting to redact ordinary authored JSON payloads globally.
3. **Foreign exceptions.** Inject real domain exceptions, Error objects with the same name, and ordinary lookalikes with the same code into external callback sites. Test model resolver, workspace resolve/journal, file writes, HTTP fetch, ordinary script runner, structured coerce completion, artifact put, event/session writes, harness contextWindow/fits/start/resume/iterator/result/cancel and final serialization/thread validation. Source and change scope determine exact expected code. Executor/model/FS/storage/serializer surprises retain safe `INTERNAL_ERROR` and existing recovery; after ordinary script dispatch retain `SCRIPT_OUTCOME_UNCERTAIN` and consent. Decision provider retains its fixed `EVALUATION_PROVIDER_FAILED` policy, and recognized HTTP overflow, structured timeout, missing-session, transport, pinned-model refusal and termination-unconfirmed keep existing precedence. Harness foreign diagnostic is private even when there is no recognized provider evidence; an unsafe prior submission cannot be made retryable by a generic failure. Keep private, correlated log witnesses where the logger presently receives raw exceptions. Where existing policy logs only a fixed provider summary, assert that summary and retain the injected private input in the controlled test fixture. Never require a raw secret in a production log that deliberately suppresses it.
4. **Prior effects and absent effects.** Count ordinary script runs and dispatch markers, HTTP/script probe calls and durable beats, child admissions/completion events, structured completions, context file writes, main and repair starts/resumes, artifact puts, session cleanup and timer deliveries. For a bad second context-file template expect one earlier file, zero failed/later file writes and zero new main turn. For successful input coerce followed by a bad later input transform expect one structured completion and zero new main calls; distinguish their providers. For heartbeat after a full/summary beat expect exactly one current probe and one beat, even if public Resume is attempted. At a failed parent mapping expect one child, its actual terminal outcome, one completion and no committed parent patch. Prove actual recovery refusal by a public Resume request and unchanged counters. An explicit new Replay has different semantics and can repeat effects; use disposable fixtures.
5. **Inference preparation and postprocessing.** Use real event histories or produce them through the existing controlled harness. Cover new visit; positively refused authored/repair exact retry; unsafe inherited init-only ID; usable accepted continuation; session-missing, explicit fresh choice with and without a saved prompt; and previous unreconciled intent whose only retry data is on the terminal failure. Put throwing prep hooks on blocked states and require zero workspace/structured/file/provider calls. On permitted preparation failure, assert the original visit/turn, kind, selected session and submission, zero new turn intent and no downgrade/cancellation of an old handle. Restart with the same ports/store and compare exact prompt, context, eligibility and eventual successful submit/continue on eligible *non-authored* control failures. For an accepted initial/repair result followed by direct repair rendering or output mutation failure verify phase, correct last task, no invented repair/second request, no “definitely not submitted” after successful completion, normal cleanup, and false eligibility. Include a coerce inside output transforms, a completed result without an acceptance marker, cancellation/run deadline/forced stop before failure publication, node timeout during admission and cleanup reporting unconfirmed termination during/after a completed result. Keep actor, existing deadline/cancel code, accepted evidence and private recording errors intact. Controlled clocks/barriers make order deterministic.
6. **Nested parity and finalization.** Compare the same failing loop inline, as a child and at depth two.
