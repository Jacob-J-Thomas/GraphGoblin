## Findings from QA

- **Q1 (P2, FIX-IN-PR, orchestrator to confirm scope):** the overflow of a run waiting for input at
  320/200 (above). Required outcome:
  - no horizontal document overflow;
  - the form stays inside its card;
  - the label is not cut short;
  - a waiting-input cell is added to the reflow matrix.

  The submit button lives in `forms/JsonSchemaForm` (outside the 30 write paths), so a
  wrapping-label fix needs a scope decision. A `WaitPanel`-only container constraint would turn the
  overflow into an ellipsized label, which the design rejects.
- **N1 (note, not admitted):** when a review closes while its own write is still in flight (S2b),
  focus goes to the status line while it is still empty. The line fills with the requested copy
  when the write settles. This matches the design ("otherwise to the status line"). There is no
  concrete user cost beyond a moment of focus on an empty element.
- **N2 (note):** a click that lands in the same turn as a key change, before React re-renders, is
  silently ignored for Pause (S3 delay −1). Nothing is sent and no copy is shown. This is the same
  as the existing #416 handling of spent-gate clicks, and the window is shorter than a frame.
- The REVIEW findings F1–F4 stand. F4 is now resolved as an improvement (above).

## Deviations from the brief and caveats

- **Queued writes in a real browser.** A real second tab's `storage` event is a separate task and
  cannot interleave between a click and its `fetch`. In the built app the mutation reaches `fetch`
  within the first microtask. The queued (chosen, not dispatched) tier was therefore produced
  in-page: a real `localStorage` write plus a same-tab `StorageEvent` delivered to the app's real
  listener inside the click's turn. The review-open and in-flight tiers used the real second tab.
- **Fresh session backend.** Start fresh session ran against the repository's built-API
  missing-session fixture (store2), not the plain built API. A real `HARNESS_SESSION_MISSING` needs
  a provider, and the plain API was provider-disabled.
- **The #563 baseline** came from a second disposable worktree at `origin/main`, route-served by
  Playwright for the same backend and runs.
- **First #562 run log lost.** It was not captured because the `qa/` folder did not exist when
  `tee` started. Its per-case `result.json` files and `562-results.jsonl` lines remain.
- **Harness failures** (S2 run 1, S3 delay −1, S4 run 1, R563 768/200 double click) are kept and
  labelled. Each re-run was a single labelled diagnostic or a corrected-expectation run. No product
  failure was replaced.
- **Lock time.** I held the heavy-suite lock from 12:56Z to 13:21Z, including script-writing
  intervals in that span.
