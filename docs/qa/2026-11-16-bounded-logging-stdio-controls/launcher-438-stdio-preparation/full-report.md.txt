## What the observer measures

1. Open the explicit PID once with query, memory-read, duplication and synchronization rights. Verify the handle is still live, its PID and raw creation FILETIME match, and Windows reports the same executable path. Require native AMD64 on both sides and equal process-token user SIDs. Refuse failed identity checks before target process parameters or handles are read. [Process access](https://learn.microsoft.com/en-us/windows/win32/procthread/process-security-and-access-rights) · [Creation FILETIME](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes) · [Image path](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-queryfullprocessimagenamew) · [Architecture](https://learn.microsoft.com/en-us/windows/win32/api/wow64apiset/nf-wow64apiset-iswow64process2) · [Token query](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-gettokeninformation)
2. Use the Microsoft-described x64 PEB link to process parameters. The documented parameters struct reserves the stdio fields. Calibrate on each invocation with the helper's own three distinct redirected pipe handles from `GetStdHandle`. Require a unique aligned match in the helper's bounded 96-byte prefix. Apply the same offsets to the same-architecture target, reading its 8-byte pointer and three 8-byte values. Re-read both after the metadata queries, then recheck target identity and liveness. [Current standard handles](https://learn.microsoft.com/en-us/windows/console/getstdhandle) · [Basic process query](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntqueryinformationprocess) · [x64 PEB layout](https://learn.microsoft.com/en-us/windows/win32/api/winternl/ns-winternl-peb) · [Reserved parameters layout](https://learn.microsoft.com/en-us/windows/win32/api/winternl/ns-winternl-rtl_user_process_parameters) · [Remote read](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-readprocessmemory)
3. Duplicate each source handle into the helper with `DUPLICATE_SAME_ACCESS` and inheritance disabled. Query its kernel type and granted mask. For character files, query its NT object name and require `\Device\Null`, also matching the helper's current DOS `NUL` mapping. Require concrete `FILE_READ_DATA` on stdin and `FILE_WRITE_DATA` on each output. The helper closes each local duplicate, token, process handle and unmanaged buffer. It performs no stream I/O through the duplicates. [Same-access duplicate](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-duplicatehandle) · [Object type and access](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntqueryobject) · [File type](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfiletype) · [DOS device mapping](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-querydosdevicew) · [File access bits](https://learn.microsoft.com/en-us/windows/win32/fileio/file-access-rights-constants)

Exit 0 is `matched`, exit 1 is an observed `nonconforming` slot, and exit 2 is `inconclusive`. Successful and nonconforming observations emit one JSON line with slot offsets, raw handle values, type, name where queried, and access mask. The observer skips pipe and disk name queries. Windows' published `NtQueryObject` contract omits the class-1 character-device name query used here. The positive and negative controls below must qualify both the internal query and the x64 offset transfer on the admitted OS. A name query or layout failure leaves the native claim unverified.

## Bind to the candidate and caller EOF

For the actual same-user disposable gateway, first retain the candidate launcher receipt, captured streams, fresh health PID/phase/instance, exact Node image and argv, and birth from the owned native evidence. Observe stdout and stderr EOF on the **launcher's** parent-side streams through explicit stream completion events, with byte totals and a distinct launcher exit event. Require launcher exit 0 and zero output bytes for the quiet successful case. Record that gateway health and the exact birth still match after EOF. Then run the observer against that gateway and repeat the health/identity readback. Running the observer after EOF avoids its temporary duplicates influencing the pipe evidence.

A passing probe establishes the three observed Win32 standard slots and granted access. It does not exercise actual device reads or writes, enumerate other inherited handles, prove the launcher's handle list, or inspect the retained CreateProcess handle in the launcher. Use source review and the exact early-exit cases for those separate requirements. A target changing or recycling a handle between samples can evade the double read. The evidence therefore applies only to the stable cooperative disposable process. Layout drift, inaccessible metadata, unequal identity, or unvalidated control results leave N-22's native standard-handle claim open.
