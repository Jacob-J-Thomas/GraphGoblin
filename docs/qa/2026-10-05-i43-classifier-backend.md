## Final table and public contract

Migration `0006_classifier_models.sql` creates `classifier_models` with primary key `(owner_id, id)`. Journal index is 6 and `when` is 1791185767298, after migration 0005's 1791152101266.

| Stored column  | Representation/public field                                                                   |
| -------------- | --------------------------------------------------------------------------------------------- |
| owner_id       | Owner scope, not exposed in catalog summaries                                                 |
| id             | Catalog id, `[A-Za-z][A-Za-z0-9_.-]{0,63}`; `jev` reserved                                    |
| display_name   | Nonblank displayName, at most 120 characters                                                  |
| source         | `builtin` or `custom`, server managed                                                         |
| provider       | `typesafe` for built-in Jev, `http` for custom                                                |
| provider_model | Nonblank providerModel, at most 256 characters; sent to the provider                          |
| primitives     | JSON list of `choice`, `noul`, `score`; nonempty and unique                                   |
| endpoint       | HTTP(S) API root, at most 4096 characters, no embedded credentials/query/fragment             |
| secret_ref     | Nullable secretRef; existing Secrets name syntax, at most 128 characters; no credential value |
| enabled        | Boolean integer, false by default for custom creation                                         |

Public summaries add `configured: boolean` and optional `configurationReason`. These fields are derived, never stored or accepted as input. Built-in Jev requires a usable `jev-api-key`; custom HTTP needs no secret unless secretRef is set. Missing/blank and unreadable secrets are distinguished, without exposing values or making provider calls. Configured status does not establish reachability or provider authentication.

| Operation                        | Input and result                                                                                                                                                                         |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET `/classifier-models`         | `{ items: ClassifierModelSummary[] }`, owner scoped, settings:read                                                                                                                       |
| PUT `/classifier-models/{id}`    | Strict displayName/provider=`http`/providerModel/primitives/endpoint/secretRef?; 200 summary. Creates disabled; replacement preserves enabled; omission clears secretRef. settings:write |
| PATCH `/classifier-models/{id}`  | Exactly `{ enabled: boolean }`; 200 summary. Built-in and custom; settings:write                                                                                                         |
| DELETE `/classifier-models/{id}` | 204 for custom only; leaves secrets and loop references intact. settings:write                                                                                                           |

Invalid input gives 400 `VALIDATION_FAILED` with paths. Missing PATCH/DELETE targets give 404 `CLASSIFIER_MODEL_NOT_FOUND`; built-in PUT/DELETE give 409 `CLASSIFIER_MANAGED_BY_SYSTEM`. Authentication/scopes run before body parsing. Credential/status/ownership fields in metadata inputs are rejected.

Decision `jev.model` is a catalog id; omission defaults to `jev`, never materializing that field in stored definitions. Explicit selection resolves only that entry. The engine registry skips unavailable configuration with its specific code in `tried`, continues the strategy chain, and retains low-confidence fall-through and `DECISION_NO_ROUTE`. Provider errors retain current engine failure behaviour; cancellation reaches the actual request. Successful classifier events include `classifierModel`, strategy stays `jev`, and lastOutput is unchanged. Exit predicates retain the built-in Noul facade without a selector.

The HTTP request is exactly `POST {endpoint}/v1/systemone` with `{ model: providerModel, state: context, questions: { answer: { type: 'choice', instructions: question, criteria: { label: description } } } }`. It sends Content-Type JSON and bearer auth only for a resolved secretRef, rejects redirects, uses a 10-second deadline and executor signal. The response requires `answers.answer` type Choice, a declared selected label, and exactly every submitted probability key with finite values in `[0,1]`. Optional confidence has the same bounds and defaults to the selected probability. Provider metadata may accompany this contract. Fixed transport diagnostics distinguish authentication, rate limit, HTTP status, malformed/invalid response, unreachable endpoint and timeout; they never retain credentials or provider error bodies.

## Decisions and scope adjustments

- Applied the orchestrator's clean default: omission selects built-in Jev; no compatibility schemas, tolerant parser or substitution path was introduced. Migration 0006 is additive; earlier migrations still perform their intended changes.
- Used 0006 and ADR-0021 because the prerequisite takes 0005 and ADR-0019/0020. Native fetch in infrastructure and composition in API preserve layer boundaries; no dependency was added.
- API-root validation also rejects query strings/fragments, avoiding ambiguous path appends and credential-bearing query strings. Exact probability-key coverage rejects undeclared extra labels as well as missing labels.
- Verified Kev-4B's owner source/model card and Apache-2.0 licensing, documenting the recommended `kev.serve` deployment. No weights, inference server or installer was run or bundled. A deterministic compatible endpoint verifies GraphGoblin execution; no live Kev deployment is claimed.
- Corrected the prerequisite's stale Edge test fixture only: it seeded IndexedDB version 1, which the already-merged application intentionally clears on upgrade to version 2. Both full and isolated runs timed out at the missing restore button before this correction. No web application behaviour changed.
