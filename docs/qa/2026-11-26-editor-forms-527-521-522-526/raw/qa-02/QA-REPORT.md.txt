| F1 | P3 | DEFER-ISSUE (orchestrator decides; NO-CHANGE is defensible) | **#527 residual: a typed member whose string value equals the form's internal unset marker is dropped without refusal.** Steps: in Variables value 1, enter `{"type":"string","title":"sentinel","default":"\u0000graphgoblin:unset","examples":["\u0000graphgoblin:unset","kept"]}`. Observed (run-01 and run-02): no field refusal; PUT 200, SQL and GET hold `{"type":"string","title":"sentinel","examples":[null,"kept"]}`. Mechanism (source reading): `entryValueRefusal` only refuses an own `__proto__` once `stripUnset` diverges; `stripUnset` drops the `UNSET` string. `ARCHITECTURE-CRITIQUE.claude.md` proposed refusing "any other divergence, such as the unset sentinel string", and `DESIGN-DISPOSITION.md` declined it. The impact is bounded (527-E: a stored marker survives unrelated edits), and the author must type a NUL-prefixed internal string. It is still a literal gap against the brief's "preserve every admitted JSON member". docs/09 claims nothing about this case. |
| OBS-1 | P3 | DEFER-ISSUE (outside the slice) | **Clearing a required Variables Value deletes the variable from the saved draft without feedback.** Select-all + Backspace in "Value *" of `topic`: no field error, PUT 200 with `variables: {other: …}`, status "All changes saved", header "Ready to publish"; after reload the `topic` row is gone (Undo is offered). In run-01, select-all + Backspace followed by pasting a refused `__proto__` value left the server without `topic`: the empty intermediate commit was the last complete value (`edge-qa/run-01/527-B-trace.zip`, `527-C-first-failure.png`). By source reading the code path is unchanged by the patch; not reproduced on a baseline build. |
| OBS-2 | P3 | DEFER-ISSUE (outside the slice) | **Reload while an older tab still blocks device storage never reaches the blocked state.** After reload the editor shows the correct server draft but stays on "The editor is available. Checking the server and this device before saving changes." with toolbar "Checking…" for at least 30 s, never shows "Changes are not kept on this device", and reads "All changes saved". Hypothesis, not confirmed: the 3 s grace in `drafts/local-drafts.ts` starts only on `request.onblocked`, which may not fire for a request queued behind the unloaded page's pending upgrade. The file is unchanged by the patch. |
| OBS-3 | – | Orchestrator (known) | The candidate has no `CHANGELOG.md` entry (repository rule gap recorded by the brief; not a QA failure). |
