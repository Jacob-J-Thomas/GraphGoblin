## What changed

**#527 — the `__proto__` member is refused before the form takes the value**
- In `structure.tsx`, the record-value check keeps the existing explicit schema reason first, including #429's Codex message.
- Only when that check names no rule does a new fallback walk the value's own entries. It stops at the first own `__proto__` member and returns `<path>: This member name cannot be saved. Rename or remove it.` (for example `properties.__proto__` or `anyOf.1.__proto__`).
- The text stays in the existing held-input channel with the Discard button. Nothing narrowed is reported, and the last complete schema is kept exactly.
- Discard now puts focus back in the editor after its button disappears. This applies to every JSON field's Discard, not only Variables.

**#521 — a nested issue shows on the Value that owns it**
- `SchemaForm` now keeps each issue's raw path segments, so a record matches issues to its entries exactly. A sibling entry named `a.b` no longer takes member `b` of entry `a`, either in its message or its focus.
- The new context replaces `RecordKeyIssueContext` (now removed). The Value shows the first nested issue as `<path from the value>: <message>` through the existing field error, marked invalid and described by it. It is never turned into held text.
- Each Value lists its nested issue paths as data, and `focusIssuePath` checks that list after an exact Key match and before the old parent-path fallback. Paths are only compared as strings.

**#522 — JSON view validates as it opens**
- `JsonText` checks the opening text with the same validator as typed text. An invalid result shows at once and disables Apply.
- It holds and reports nothing, adds no undo step, offers no Discard, and the structured editor stays one click away.
- Text that only differs by whitespace or key order stays passive. Cancel restores the passive message with focus on Cancel. If Apply's forced recheck refuses the committed content, it stays passive.

**#526 — the indicator shows held input separately from the draft**
- Derived only from `fieldErrors`; save state, drafts, API and IndexedDB are untouched.
- The same status element gains a second, wrapping segment: "Field input kept in this window only". While it is shown, "All changes saved" becomes "Draft saved", and device/offline wording names the draft (e.g. "Draft kept in this window only"). Idle never becomes saved.
- One polite announcement fires when held input begins: inside the node dialog's notice slot while the dialog is open, on the page otherwise. Further typing, moving between dialog and page, and the end of held input announce nothing; the region empties when held input ends.
