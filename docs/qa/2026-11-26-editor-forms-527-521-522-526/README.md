# Editor forms: #527, #521, #522, #526

Four structured-editor fixes ship as one web-only candidate. A record's JSON Value refuses an own `__proto__` member at the Value instead of saving the value without it ([#527](https://github.com/Jacob-J-Thomas/GraphGoblin/issues/527)). A schema error inside a committed JSON Value is shown on, described for and focused in that Value ([#521](https://github.com/Jacob-J-Thomas/GraphGoblin/issues/521)). A section opened as JSON shows the diagnostic for its committed content from the first render ([#522](https://github.com/Jacob-J-Thomas/GraphGoblin/issues/522)). The header shows field input kept in this window apart from the saved draft, instead of **All changes saved** ([#526](https://github.com/Jacob-J-Thomas/GraphGoblin/issues/526)).

GPT formal review 1 found the exact candidate **READY**. The independent Claude Edge QA verdict is **PASS WITH LIMITS**: #521, #522 and #526 pass, and #527 passes with one limit (F1). The CHANGELOG commit was written after both and has not been reviewed. The fresh Astra MAX final audit (2026-11-28), hosted CI and owner acceptance are separate and pending.

## Behaviour

- **#527.** In the structured editor, a record's JSON Value, such as a declared variable's JSON Schema, with an own member named `__proto__` at any depth is held exactly as typed, marked invalid and described by `<member path>: This member name cannot be saved. Rename or remove it.` beside Discard. The draft keeps the entry's last complete value, neighbours save, Publish is refused, and Discard returns focus to the Value's editor. `__proto__` inside a string and members such as `constructor`, `prototype`, `__proto` or `proto__` are ordinary. A rule the record's own schema gives (#429's Codex key rule) still takes precedence. Before, the form's object copy dropped the member and autosaved the narrowed schema. This was the FUP-014 design decision: refuse the demonstrated own member rather than widen the route.
- **#521.** A Codex override whose Value nests a refused key (`{"outer":{"team docs":true}}`) marks the owning Value invalid with `outer.team docs: <rule>`, and the dialog and canvas issue links focus that Value, not a valid dotted sibling such as `example.outer`. A Key's own error stays on the Key.
- **#522.** **Edit as JSON** over refused committed content shows the rule inline at once, marks the editor invalid and disables **Apply JSON**. The diagnostic is passive: no held input, Discard, undo step or save change. It follows sibling changes and returns after **Cancel JSON**. Valid content opens with ordinary controls.
- **#526.** While a field holds input apart from the draft, the save status shows **Field input kept in this window only** as a second segment, and the draft part reads **Draft saved**, **Draft saved on this device only**, **Draft kept in this window only** or an offline variant. One polite announcement is made as held input begins, in the node dialog while it is open and on the page otherwise. A reload restores only the complete draft.

The numbered design text is in [09 - Frontend and PWA](../../09-frontend-and-pwa.md#what-shipped-in-m5-first-pass-draft) ("Held field input beside the draft", the record Value and section JSON bullets).
