## Blocking findings

1. **B1 — A completion event does not prove that the checkpoint has no open visit.** [run-manager.ts:1079](%USERPROFILE%/source/repos/GraphGoblin/.claude/worktrees/codex-audit-wp-g1-116/packages/engine/src/run-manager.ts:1079) supplies `{ strict: true }` for every `node.finished` checkpoint. A delayed duplicate completion for A can occur while B remains open; full replay ignores A's duplicate and retains B. The bounded reader forgets B and silently skips its subsequent durable completion patch.

   Persisted reproduction: `run.queued → started(A) → finished(A, items=["a"]) → started(B) → duplicate finished(A) [checkpoint] → finished(B, append "b")`. The checkpoint is an honest full replay through sequence 5. At sequence 6, full replay and the actual Edge inspector return `items=["a","b"]`; REST `GET /runs/{id}/thread` and MCP `get_run_thread` return `items=["a"]`. Both read only sequences 5–6. Run/event bytes remain unchanged. A second reproduction lets actual recovery write the `node.finished` checkpoint after a durable failure and delayed prior-node completion; the reader subsequently omits `completed:true`.

   This violates both #116 acceptance criteria and ADR-0053's equivalence to full replay. Delayed duplicate completions are explicitly supported by the existing domain replay tests. These are controlled durable-history fault cases through public storage ports, not a claim that an ordinary single executor creates the ordering.

   **Smallest correction:** use the existing full-history replay-state fallback wherever the open visit cannot be proved; retain the bounded path only with adequate proof or explicitly persisted replay state. Add the delayed duplicate / different open node / recovery-checkpoint regression and correct the proof in ADR-0053 and docs/07.

   **Reproduction:** with Node 22 on PATH, set `AUDIT_ROOT` to this worktree and run `node duplicate-browser-corrected.mjs` from this report directory. [Driver](duplicate-browser-corrected.mjs), [complete REST/MCP/browser evidence](duplicate-browser-corrected.json), [screenshot](duplicate-browser-corrected.png), [recovery driver](supplement.mjs), [recovery evidence](recovery-duplicate.json). The six-event case also reproduced through `RunManager.getThread` using public engine test ports.
