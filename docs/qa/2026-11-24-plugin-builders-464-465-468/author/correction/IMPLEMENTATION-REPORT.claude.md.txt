The write failure now stays primary when closing the staged file also fails. The fix is in `tooling/plugin-output.mjs`, with new public-method regression tests in `tooling/plugin-output.test.mjs`. Those are the only two of the 11 paths I edited. Every check in the contract passed and all changes are unstaged.

## The fix
- **Before:** the staged-file `try { writeFile } finally { close }` let a close failure replace the write failure, so nothing kept the write error.
- **Now:** if the write fails, the handle is still closed through the existing cleanup `attempt`, so a close failure is recorded as a cleanup failure and the write failure is rethrown as primary. If the write succeeds, `close()` runs as before and any close failure is still thrown, not swallowed.
- **Structure:** the existing `failures`/`attempt` code moved above the staging `try`, unchanged. The rest of the outer cleanup is unchanged. It still attempts every owned cleanup step, deletes nothing new, and still can't claim publication or rollback here, because this failure happens before anything is moved or published.
- **Result:** the error uses the existing `AggregateError`, with `cause` set to the write error and `errors` = [write, close, any other cleanup failures]. There is no new public API.
