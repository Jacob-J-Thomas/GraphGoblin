## What changed

**#464: refusal and recovery messages** (`tooling/plugin-output.mjs`, `.d.mts`)
- The old single "not owned" refusal is now four distinct messages. Each names the destination, the affected entries and a recovery step: use an unused destination, or inspect the output and move it aside.
  - **Changed inventory:** a valid marker from this builder lists different file names. The check compares names, so it still fires when the count is the same. It reports what is "listed only by the marker" and what is "generated now but not listed". Marker names are only quoted in the message, never read or removed, and the list is capped at 10.
  - **Invalid marker:** the marker is missing, malformed, null, the wrong format or builder, or has no proper file list.
  - **Foreign or modified entries:** an unexpected entry keeps the "is not owned by this builder" wording; a changed file says it "does not match the content this builder recorded".
  - **Missing entries:** missing generated files or folders are listed. A missing folder no longer surfaces a raw `ENOENT`.
- **Cleanup after a failure:** each cleanup step (close the metadata helper, restore, remove the old or new staged tree, remove the staging folder) now runs even if an earlier one throws. Nothing removes more than before, and a restore never goes into a destination another writer has created.
  - If nothing is left behind, the original error is thrown unchanged.
  - Otherwise the builder throws an `AggregateError`. Its `cause` is the original error, its `errors` list adds each cleanup failure, and its message says what is actually still on disk (checked, not assumed): the previous output, the unpublished new tree, or the staging folder itself.
  - If cleanup fails after publishing, the message says the complete new output was published.

**#465: unsupported source files**
- A new `checkSourceInventory(root, files)` lives in the same helper. It refuses any file, folder or link that isn't in the builder's list, and links are never followed.
- The Codex builder checks its plugin folder against the manifest, the MCP file the manifest names, and one `SKILL.md` per skill it finds.
- The Claude builder checks its `plugin` folder (manifest, runtime guard, `design-draft.md`), the three shared `SKILL.md` files, and that `README.md` is a regular file.
- Both checks run before `writePluginOutput`, so nothing in the output changes on a refusal.

**#468: Claude run-loop text it adapts**
- `adaptSkill` now fails, naming the missing text, if either `## 1. Find the loop` or the sentence ending `only if they agree.` is gone. The rewrite itself and the CRLF handling are unchanged.

**Docs:** docs/02 (the tooling helper), docs/07 (allowed inputs and outputs, what the marker's hashes do and don't authorize, the refusal types, recovery and cleanup), guide 05 (the missing recovery steps after adding or removing a skill), and a new Unreleased CHANGELOG entry with an upgrade note.

## Open gaps and risks
- **Platform coverage:** everything ran on Windows only. On Linux/macOS the link tests use a directory symlink instead of a junction, and that path hasn't run.
- **Not exercised here (left to QA):** native Codex marketplace install/load and native Claude validation.
- **Not run (left to CI):** full repository CI and other packages.
- **Behaviour change for users:** stray system or editor files (for example `.DS_Store`) in plugin source folders now stop assembly. This is intended and is in the CHANGELOG upgrade note.
- **Claude needs explicit support for new skills:** a fourth shared skill makes the Claude build fail, while the Codex build packages it.
- **POSIX race (already present, not fixed):** between the "destination is vacant" check and the rename, an *empty* folder another writer creates there can be replaced. Non-empty folders fail the rename, and Windows refuses an existing folder. Node has no rename-without-replace call.
- **Concurrent deletion race:** if a generated folder is deleted at the same moment the builder lists it, a raw `ENOENT` can still appear; the refusal is still safe.
- **Link checks are per entry:** links inside each input folder are refused, but the folder itself and its parents aren't checked. The source check isn't a security boundary against changes made between checking and reading.
- **CLI display of combined failures:** the Claude CLI prints `String(error)`, so wrapped failures appear as `AggregateError: …`. The combined-failure message is asserted in the tooling tests, not at CLI level.
- **Conservative close failure:** if the metadata helper fails to close after a fully clean publication, the build still exits as a failure, with a message saying the output was published.
- **Codex branch coverage** is 91.66%, near the threshold. The Codex assembler change adds no branches, but I didn't record the apps' coverage before the change.
- **Commands outside the contract:** early on I ran read-only `ls`, `cat` and `head -c` to explore, which aren't on the exact command list. One `git log` attempt was denied. Everything after that used only the listed commands.
