## 2. Defects

### QA-186R2-002 - major - browsing older history drops the recorded cancellation actor

1. Start the retained fake-harness cyclic workload; allow it to exceed 700 events while still running.
2. Cancel through `POST /runs/{id}/cancel` using the fixture's API key. In the decisive reproduction, run `01M5S33YPB7AA4FFCD7F8B65G0` ended with **723 events**: event **721** is `run.cancel_requested` with the API-key actor, and event **723** is `run.cancelled`.
3. Open the inspector at the live end. Execution context correctly names the actor.
4. Enter **50** in Event sequence and choose **Go to event**. The window freezes at **1-50** while the acknowledged run history remains 723 events.

Expected: whole-run Execution context retains the recorded cancellation identity while browsing another event/window. Actual: it replaces that identity with **"Cancelled. Cancellation history is incomplete; actor not available yet."** The completed durable history and the actor did not change. The condition persists in the frozen window; there is no pending cancellation read that will resolve it.

Evidence: [exact observed context, window and cancellation events](cancellation-defect.json), [recorded events 721/723](long-cancel-events.json), [reproduction script](merged-followup.mjs.txt), [results](merged-followup-results.json), [browsed accessibility snapshot](long-cancel-browsed.aria.txt), and screenshots at [1440 dark](verified-cancel-1440-dark.png), [1440 light](verified-cancel-1440-light.png), [390 dark](verified-cancel-390-dark.png), [390 light](verified-cancel-390-light.png).

A separate synthetic post-terminal suffix makes the statement stronger and false: with the cancellation and actor evicted but the retained suffix reaching the run's last sequence, the inspector says **"terminal cancellation event not recorded"**, even though it is durable. [Synthetic case and exact actor](merged-fixtures.json), [rendered text](cancellation-outside.aria.txt), [screenshot](cancellation-outside.png), [script/results](merged-inspector-results.json).

Location confirmed from current source: `RunInspectorPage.tsx:204` supplies only `log.events` to ExecutionContext; `ExecutionEvidence.tsx:35-38` derives the cancellation summary and its history claims from that retained slice. No fix was made.

### QA-186R2-003 - minor - maximum safe newer cursor returns an invalid older cursor

This is an adversarial numeric boundary, not an ordinary UI-generated cursor sequence. Using the public built `historyCursor` helper, encode `{runId, seq: 9007199254740991, direction: "newer"}` for an existing run. GET `/runs/{id}/events?cursor={cursor}&limit=1` accepts it with HTTP **200**, `items: []`, and `nextAfter: 9007199254740991`. Its returned `olderCursor` encodes **9007199254740992**. Following that server-returned cursor receives HTTP **400**, `INVALID_CURSOR`, **"Choose a cursor returned by this run history."** The neighbouring accepted value 9007199254740990 returns a valid continuation and event 1778.

Expected: an accepted page supplies a valid continuation to the durable tail, or rejects the unsupported boundary up front. Actual: its own emitted continuation is unusable. The input cursor is constructed for this adversarial test and passes the API's canonical/safe-integer validation; no normal browser navigation is claimed to produce that initial extreme value.

Evidence: [both numeric cases and complete responses](numeric-edge-results.json), [reproduction script](numeric-edge.mjs.txt), [log](numeric-edge.log.txt). Source: `events.window` adds one to the empty newer position for `olderThan`, while the cursor decoder requires a safe integer. [Retained source excerpts](source-excerpts.txt). No fix was made.
