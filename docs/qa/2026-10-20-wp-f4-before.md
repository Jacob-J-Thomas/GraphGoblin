# WP-F4 before record: prompt submission and resume (#244)

Date: 2026-10-20. Baseline: `453aee676882f188429080e948dcd7918f09adfd`, branch
`codex-wp-f4-prompt-provenance`. Node `v22.14.0`; Windows PowerShell and `pnpm.cmd`.
All inputs were synthetic. No installed provider session or paid turn was used.

## Observed engine behavior

A temporary test drove `RunManager` through the public test-engine helper with the fake
harness. It failed one inference, resumed it, and printed the failure and submitted request.
The authored prompt was `Keep the entire authored task.`. Every failed turn had a session
announcement; the original fake could not represent a failure without one.

| Controlled failure                          | Recorded failure                                                                 | Explicit resume observed                         |
| ------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------ |
| Startup cause `HARNESS_NOT_INSTALLED`       | `HARNESS_NOT_INSTALLED`, resumable; no submission field                          | Same recorded ID, continuation prompt, succeeded |
| Death after init only (no items)            | `HARNESS_TURN_FAILED`, resumable; no submission field                            | Same ID, continuation, succeeded                 |
| Death after first assistant item            | `HARNESS_TURN_FAILED`, resumable; no submission field                            | Same ID, continuation, succeeded                 |
| Missing-session cause under previous policy | `HARNESS_TURN_FAILED`, `details.adapterCode: HARNESS_SESSION_MISSING`, resumable | Same ID, continuation, succeeded                 |
| Missing-session cause under named policy    | Same generic failure                                                             | Same named ID, continuation, succeeded           |

The first measurement's previous-policy seed was a different run, so that row was **not**
selected as a previous session. Its missing-session cause was scripted. The final regression
matrix seeds the previous conversation in the same run through the repository port, and the
named conversation by scope key. Do not interpret the first measurement as native missing-session
verification. The startup-cause row likewise measures engine handling of a startup error after
the old fake's unconditional session announcement, not a real successful process start.

The exact continuation submitted was:

> The previous turn was interrupted before GraphGoblin recorded its result. Continue the task from where you left off and finish it.

Command: `pnpm.cmd --filter @graphgoblin/engine exec vitest run src/prompt-before.test.ts --silent=false`.
The temporary measurement test passed and was replaced by durable regression tests.

## Fake CLI process boundaries

Added `claude/submission.test.ts` and `adapter-codex/src/submission.test.ts` and their
`fixtures/turn-cli.mjs` processes. Claude uses its public runner injection with the real
`runClaudeProcess`; Codex uses its public SDK-client injection backed by a real Node child
that yields the fake CLI's JSON lines. The latter verifies adapter translation, not the SDK's
native executable-launch implementation. Startup failure, rejected CLI arguments, init-only
stream death, first assistant/accepted-turn death and an explicit missing-conversation refusal
were exercised. All processes exit without calling a provider.

For the before run, only the five owned implementation files (`inference.ts`, Claude
`harness.ts`/`protocol.ts`, Codex `harness.ts`/`events.ts`) were temporarily loaded from
`git show HEAD:<path>`, with the in-progress files restored in a `finally` block. No Git state
mutation, branch change or commit occurred.

| Adapter boundary                                           | Before result                                                                               |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Claude confirmed spawn failure                             | Error event with no `submission` field                                                      |
| Claude arguments/init-only/assistant/missing refusal       | Error event with no `submission` field; no `submitted` marker, even after assistant content |
| Codex startup/arguments/init-only/accepted/missing refusal | Error event with no `submission` field; no `submitted` marker, even after `turn.started`    |

The new assertions demonstrably failed on those implementations:

- Claude: **5 failed / 5**, including `expected [] to deeply equal [{ type: 'submitted', marker: 'claude.assistant' }]`.
- Codex: **5 failed / 5**, including the same missing marker at `codex.turn.started`.
- Engine: **3 failed / 3 selected** fresh/previous/named refusal regressions, with `expected undefined to match object { submission: 'definitely-not-submitted', promptKind: 'authored' }`.

## Baseline control with actually selected prior sessions

A final read-only baseline audit injected a sibling copy of the original inference handler
through the public handler registry, leaving the final implementation untouched. Its temporary
files were removed afterwards; `%TEMP%/gg-wp-f4-before-selected.log` retains the output.
Command: `pnpm.cmd --filter @graphgoblin/engine exec vitest run src/prompt-before-audit.test.ts --silent=false`.
The single audit test passed all three observed scenarios:

| Policy / controlled failure                    | Actual original submission                          | Failure and explicit resume                                                                                                                                                    |
| ---------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Fresh startup with **no session announcement** | `complete authored task`, no ID                     | `HARNESS_NOT_INSTALLED`, resumable; retry submitted the complete authored task fresh and succeeded. This control was already safe before the fix.                              |
| Previous with a same-run prior ID              | Confirmed `resume('selected-prior', authored task)` | Missing-session cause became generic `HARNESS_TURN_FAILED`, resumable; explicit resume sent the continuation prompt to `selected-prior` and succeeded with the next fake turn. |
| Named with the matching scope key              | Confirmed `resume('selected-prior', authored task)` | The same generic failure and same-ID continuation behavior as previous.                                                                                                        |

This closes the first measurement's previous-policy seed limitation. Native CLI missing-session
refusals remain the controlled process-boundary evidence above; no live provider was contacted.

## Interpretation

The defect is reproduced: unfinished-session identity alone chose the continuation prompt,
including a startup refusal, losing the authored task. Neither adapter exposed input acceptance
as a distinct event, and neither represented missing sessions as their own failure class.
An init-only death cannot safely be called definitely unsubmitted; the correction must keep it
uncertain while distinguishing a positive pre-send refusal. The later explicit fresh-session
recovery action remains #265; own-session continuity remains #33.
