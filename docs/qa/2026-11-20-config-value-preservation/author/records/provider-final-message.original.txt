**Cause.** The member wasn't only lost in `stripUnset`: react-hook-form's own value copy also drops it, so a helper-only fix would not have worked.

**Fix (the "refuse" option).** The Value is checked at the existing JSON validation step, before anything is written to the form, using the record's own schema for that one entry (no Codex-specific code):
- If the form would keep the value unchanged, it is accepted as before. That keeps the existing behavior for `"bad key"`, ordinary objects and arrays, and other JSON fields.
- If the form would lose part of it and the schema refuses it, the text stays as typed. The editor is marked invalid with a message such as `rows.0.__proto__: Codex config overrides require …` and a Discard button.
- While it's refused, nothing is saved or sent and the draft is unchanged. One blocking issue shows and Publish refuses.
- Renaming the member saves the whole value, which survives reload.
- Under an invalid Key such as `team docs`, the Value shows the Key's message, which becomes the member's message as soon as the Key is fixed.
