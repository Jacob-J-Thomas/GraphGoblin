## What is implemented

**Store action** (`store.ts`): `spaceCards(measured?: ReadonlyMap<string, number>) → 'applied' | 'ineligible'`.
- It reads `get()` now and checks `spaceCardsEligible` again. With no draft, or a draft that no longer qualifies, it returns `'ineligible'` and never calls `set`, so the state object is the same reference.
- Heights: the private `heightsByIndex` maps the id-keyed measurements onto the *current* nodes by index. An id used by more than one node gets `undefined`, which means the footprint. The pass is linear. Measurements for ids no longer in the draft are ignored.
- It calls `withSpacedPositions(def, spacedPositions(def, heights))` in one `set`: `revision + 1`, `saveState: 'pending'`, and `recordStep` labelled `space cards` with no merge key.
- It does **not** call `edit()`, because `decisionRouteEdges` can rewrite edges. `decisionRoutes`, `fieldErrors`, the selection, the dialog, `renameReport`, `conflict`, `nameConflict`, `baseToken`, `formEpochs` and `historyEpoch` keep their references. Undo and Redo are the existing `travel`, so Undo restores the exact earlier object and Redo the exact spaced object, with no recomputation.
- No Chat protection check: geometry is not protected, and no other protection is relaxed.
- The helper's count-mismatch `Error` is not caught. The positions come from the same `def`, so it cannot fire.

**Offer** (new `SpaceCardsOffer.tsx`):
- Wrapper `nokey pointer-events-none absolute inset-x-0 top-3 z-[5] flex justify-center px-4`. The xyflow wrapper is `relative; z-index: 0`, so the panel paints above the flow without layout displacement.
- A `<section aria-labelledby>`: "{n} cards are stacked in one spot", then the muted help line from the design.
- Then **Space cards** (outline `sm`: 32 px, 44 px under a coarse pointer, `aria-describedby` the help line) and **Dismiss suggestion** (ghost icon, 32 or 44 px). They share one row, so DOM order equals visual order and there is no CSS reordering.

**Canvas** (`Canvas.tsx`):
- The root gains `relative`. The offer renders first inside the root, before the flow, so Tab goes palette → Space cards → Dismiss → cards.
- `offered = spaceCardsEligible(definition) && !moving && dismissedOffer !== generation`, with eligibility memoised on the definition.
- Dismissal is Canvas state keyed by the store `generation`. A load (reopen, Reload server draft, set-aside restore) or a remount offers it again. Dismiss focuses the canvas root and announces "Suggestion dismissed." The design did not specify this; it is there to avoid losing focus to `<body>`.
- Press: builds a `Map` of xyflow-measured heights (`offsetHeight`, which zoom does not scale, so flow pixels) and calls `spaceCards`. It then focuses the existing root (`tabIndex=-1`) and announces through the existing polite region. On success: "Spaced {n} cards. Undo puts them back." On refusal: "Cards were not spaced: they are no longer all in one spot." No focus on Undo, no global key suppression, no synthesized gestures.
- Fit: on success, a ref holds `{definition: spaced, generation}`. A passive effect over `[definition, generation, measured, fitView]` calls `fitView(INITIAL_FIT_VIEW_OPTIONS)` once, when the rendered draft is that object and every node id has a measurement. It drops the pending fit if any other definition or generation renders first (an edit, an undo, a load). Unmount discards the ref.
  - Why this works: in xyflow 12.12, `fitView` queues and resolves on the next `setNodes`. Child passive effects run before Canvas's, so xyflow's `StoreUpdater` has adopted the spaced nodes first.
  - Undo, Redo and ordinary edits never set the ref.

## Honest limits, and what still needs native, CI, review or owner gates

1. **Double click.** jsdom cannot hit-test. After the first click, React unmounts the panel and the cards move in the same discrete event. A native second click lands on whatever is then under the pointer: often the pane, which can xyflow-zoom on `dblclick`, or a card in column 0 above the first card, which it can select or open in the node dialog. It cannot space again, since the store refuses. No draft edit or delete follows from the click itself, but selecting or opening a card is possible, and a later deliberate Delete would act on the selection. This needs the root's native check; I added no gesture suppression, by instruction.
2. **Space-to-pan** shielding rests on reading xyflow 12.12's `isInputDOMNode` (`.nokey` match). It is not natively verified.
3. **Measurement.** Flow-space `offsetHeight`, larger-text spacing, coarse 44 px targets, panel wrapping at narrow widths, and both themes need native and screenshot evidence.
   - A pile can sit under the panel on a short canvas before the action. Cards under the panel cannot be clicked until it is dismissed or used. Not measured.
4. **Fit.** It needs every node id measured. A card xyflow never measures (for example, hidden) means no fit until the next definition change drops it; that has not been seen natively.
5. **e2e churn.** Playwright specs that build all-origin loops through REST will now show the panel at the top centre of the canvas. Clicks there may hit it. Not run.
6. **Gates.** Still to come: coverage, build, the full `pnpm check`, current-target CI after root integration, opposite-family (GPT) formal review within the three-scan budget, native QA, the fresh sign-off, and owner acceptance. #208 stays open, and PRs should say "Part of #208".
