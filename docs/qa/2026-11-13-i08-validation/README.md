# I08 validation evidence

The baseline was `b3b5e1874a8252cc01c065d18fef42cbfbe075b4`, on Node v22.23.4. The worker added the regression tests before changing either validator. These are implementation checks. Independent QA, Claude Opus review and the final Astra audit are tracked in the delivery register.

## #228 — JSONata evaluation

| Case                        | Observation on baseline                                                                                                                     | Implementation verification                                                                                                                                                   |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Flat literal objects        | 99 succeeded. 100 and 200 raised `expression exceeded max depth 200`. Equivalent projections produced the expected JSON at all sizes.       | Literal and projection return the same values at 99, 100 and 200 items.                                                                                                       |
| Wide object                 | A flat object with 200 properties exceeded depth 6.                                                                                         | The evaluator returns all 200 members at depth 6.                                                                                                                             |
| Real nesting and cycles     | A genuinely nested literal and a recursive `$eval` reached their configured depth limit.                                                    | Both still reach the configured limit. Existing finite recursion, tail-recursion timeout, dynamic evaluation error bounds, lexical context and regex safety regressions pass. |
| Concurrent identical source | A strict depth call succeeded under the sibling's looser depth budget. A short-deadline call succeeded under the sibling's longer deadline. | Each restrictive call fails with its own limit. The sibling finishes with its own binding value. The two concurrent evaluations keep distinct timestamps.                     |

The first baseline Vitest run also failed its 99-item projection equality assertion because JSONata attaches sequence metadata to its returned array. The parallel read-only baseline probe confirmed the expected projection lengths. The retained test compares the array's elements using `Array.from`, which matches the public JSON value it represents. This fixture correction is separate from the product defect.

The pinned JSONata 2.2.2 patch awaits sibling array and object evaluations in original order. JSONata and GraphGoblin both track depth across active evaluator calls, so starting siblings in parallel counted array width toward depth. The patch also places timestamp functions and symbol-keyed invocation hooks in the per-call frame. Existing caller depth/deadline error messages and inspected nested source checks are preserved.

## #229 — JSON Schema reference scope

| Case                                  | Observation on baseline                                                                                                          | Implementation verification                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Same ID with distinct schema contents | Compiling the second validator failed after the first for both type orders.                                                      | Both schemas accept their own type, reject the other, and keep their required properties and local references.                                                                                                                                                                                                                                                       |
| Unsupported external reference        | A schema could consume a separate validator's previously registered ID.                                                          | The error names the unresolved reference even after validating the target schema independently.                                                                                                                                                                                                                                                                      |
| Local references and metadata         | Local pointer and ordinary format cases were accepted.                                                                           | JSON Pointers, embedded resource IDs, the draft-07 meta alias, and reference-shaped example values remain supported.                                                                                                                                                                                                                                                 |
| Caller edits                          | Read-only compiled API probe found that mutating `const` or `enum` data changed a validator retained under an earlier cache key. | The cache uses an independent JSON snapshot, preserved under its original key when the caller edits the input.                                                                                                                                                                                                                                                       |
| Public selected-version route         | Same-ID conflict reproduced in the public domain validation function.                                                            | The REST manual-run entry point via Fastify injection and a disposable file SQLite store checks distinct scopes across two loops and three published versions in both orders. It reports a precise type refusal, pins the requested version for accepted runs, and returns the accepted input from the completed run. The test closes/reopens the store and repeats. |

The selected-version API regression initially used `input.value` in its fixture exit expression. The API admitted the valid input and completed the run, and that expression yielded null. Correcting the fixture to use the documented `trigger.payload.value` enabled the intended completed-result assertion. The focused command filters to that one regression and leaves the three unrelated tests in the file outside the selection.

The first candidate created a fresh Ajv compiler per cache miss. Under full root coverage, the existing cache-eviction test took 5,378 ms and failed its unchanged 5,000 ms limit. The corrected implementation reuses the synchronous compiler and clears its authored schema registrations after each compile, including failure. A registered meta-schema retains the generic draft-07 URI alias across cleanup. The retained package run passed all 377 tests, with 99.49% lines and 98.10% branches. Its schema cases probe 260 compiles with both built-in URIs, reuse after eviction, failure cleanup and local recursion in a cached validator across other compiles.
