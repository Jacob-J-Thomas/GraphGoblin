### R3 · P2 · Require an authoritative identity for a case-only match

The native guard now distinguishes the original NTFS example. Its case-only branch treats matching volume and nonzero 64-bit file index as proof that both handles describe one object. Microsoft explicitly excludes that uniqueness guarantee on ReFS and documents the full 128-bit file ID for this comparison. The NTFS admission check applies to the log root. A configured database can be on a different volume. For a case-only target difference on such storage, an equal low identifier can admit distinct objects. This is a documented limit of the chosen API and a source-level inference. The review observed no collision. The installed Microsoft fsutil message resource identifies local ReFS and NTFS as examples supporting case sensitivity. The controlled same/different 64-bit examples in the current test cannot detect truncation. This finding is confined to an unverifiable equality on the case-only branch and merits P2 on that reachability. ### R6 · P2 · Check the deadline after the last proxy-path lookup

The shared clock now starts before window discovery. Handoff refuses a spawn below 200 ms remaining, and caps sleeps to the remainder. In the production binding, the admitted operation performs synchronous `File.Exists(config.ChromeProxy)` before `Process.Start`. An admitted boundary click can spend its remaining 200 ms waiting on filesystem I/O and then launch Chrome after the deadline. The decision is made before a separate, avoidable I/O operation. The issue can be corrected at the application’s call site while leaving scheduler delay and time spent inside an already-issued OS call outside the guarantee. It can report a missing window and release the mutex before that newly launched window appears. The controlled clock records the start at entry to the injected callback, so it cannot detect elapsed time inside the production preparation step. [Budget check](G:/ggq/gg-followups-20261124/GraphGoblin/apps/windows-launcher/Launcher.cs:2156) · [Proxy lookup and process start](G:/ggq/gg-followups-20261124/GraphGoblin/apps/windows-launcher/Launcher.cs:2173) · [Boundary control](G:/ggq/gg-followups-20261124/GraphGoblin/apps/windows-launcher/NativeChecks.cs:664)

Move the admission check to the point of issuing process creation after preparatory I/O, or eliminate the redundant existence check and retain the existing classified start failure. Exercise a slow preparation at the threshold, with an assertion on the actual start callback. Keep the ordinary launch, existing-window activation and capped sleep cases.
