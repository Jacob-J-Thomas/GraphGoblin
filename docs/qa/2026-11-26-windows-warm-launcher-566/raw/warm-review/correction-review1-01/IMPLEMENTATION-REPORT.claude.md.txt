## Findings
**R1 – drain only a verified owner**
- **Where:** in `windows-launcher.acceptance.mjs`, `ownedAliasGateway` (2236) now also checks the enrolled launch digest and named lease files. `releaseAliasGateway` (2292) refuses any listener without a verified owner. It revalidates the owner before and after reading the shutdown token, then drains with that token, never following a redirect. `manualGateway` (685) settles a failed start through its own child handle.
- **Applied to:** the manual, transient, retarget and quota fixtures, plus the alias test's release path.
- **Regression:** `owned cleanup refuses a replacement listener with zero drains`.
  - Rejections: changed lease bytes, creation time, PID, or no owner on a live gateway are refused, and its shutdown token stays the same. A replacement listener copying the owner's exact headers gets 0 drains. A redirect target gets 0 requests. A second real gateway on the same port is refused for the old owner.
  - Positives: 2 owned drains succeed.

**R2 – owned control job lifetime**
- **Where:** `NativeChecks.cs` `JobLaunch` (1064). Every outer job is now kill-on-close. The new `--job-owner` mode reports, then holds the job until stdin closes or 150 s pass. `--await-exits` (1141) holds exact process handles. In the acceptance file, `ownJob` (375) and `exitWitness` (453); the quota case starts the control under `ownJob` (1808).
- **Positive:** `owned compatible control remains alive until explicit release`. The gateway is in the job and survives and is reused warm after the job owner reports. After the owned drain and release, only the owner and its sibling remain and the sibling is settled.
- **Cancellation:** `cancellation before health settles owned startup descendants`. A stub gateway that never listens is cancelled through the abort path. The launcher, gateway and a detached descendant exited within 8 ms, an unrelated process survived, no listener appeared and the gateway started only once.

**R3 – actual object identity on case-only differences**
- **Where:** `Launcher.cs` `Resolve` (1589) and `ResolvesTo` (1611). The canonical-path check stays. A case-only difference is accepted only if the enrolled target opens to the same volume and file index; an unverifiable identity is refused.
- **Regression:** `native case-only target comparison preserves object identity`. Real handles accept a case-insensitive alias of one directory and refuse a different directory.
- **Limit:** distinct `Store`/`store` objects are covered only by an injected comparison, not a real case-sensitive directory, because I changed no host settings. It uses the 64-bit file index, not ReFS 128-bit IDs.

**R4 – one sanitized fixture environment**
- **Where:** `fixtureEnvironment` (48) is now the single source for `env`. The separate `hostEnvironment` is gone, and enrollment, launcher, manual and job-owner starts all take it.
- **Regression:** `mixed-case Jev sentinel is absent from fixture children`. A deliberately unsanitized child does see the mixed-case names (detector check). Children from enrollment (1), launcher (3), manual (1) and job owner (3) show no Jev or mixed-case `GG_*` names, exactly `GG_OLLAMA_ENABLED=false`, and the ordinary control variable present. Only names are reported, never values.

**R5 – definite HTTP refusal**
- **Where:** `Launcher.cs` `Get` (1491) returns and disposes completed HTTP errors; `Observe` (1522). A matching gateway with `/app/` 404 or 410 is refused as `web-unavailable` before the mutexes. Other HTTP errors and `/healthz` errors keep their previous ambiguous handling.
- **Regression:** readiness case `a definite missing web shell is refused…` (1613). Both statuses are refused in under 10 s with the startup mutexes held. Each makes exactly one `/healthz` and one `/app/` request; the listener, lease records and `gateway.log` are untouched. Control: an `/app/` that never answers waits for the mutexes, then is refused as "not ready".

**R6 – one window deadline**
