## 8. #499 Cloud Files run: skipped, because the procedure is not clear enough to repeat under a new folder

The brief allowed a CFAPI run only if the existing tooling has a clear register/unregister
procedure. It does not, for reuse under a new folder:

- **Compiled-in binding.** The provider's root path, nonce, provider GUID and the root's NTFS

  `PREPARED-MATRIX-ROOT.json`.
- **Writes into historical evidence.** The controllers write journals and outputs into their own
  historical evidence folders, which I may not modify. They also bind to source `631d16e3` and a
  frozen manifest.
- **Self-authorization.** Activation requires an exact coordinator approval file, which I would
  have to write myself.
- **Unbounded failure path.** The first qualification's cleanup failed and needed a separately
  reviewed recovery. Its failure path is "retain and adjudicate", which I cannot bound in this
  brief.

Repeating it would mean authoring new provider tooling, not reusing a procedure. So the following
remain **not established** on this candidate:

- placeholder non-hydration under the new early source check;
