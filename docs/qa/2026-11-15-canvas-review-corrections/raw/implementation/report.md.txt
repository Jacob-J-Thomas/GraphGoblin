## What changed
- **F1 (shared ID):** `removeEdge` now removes exactly one stored record.
  - The new `edgeRemovalRefusal` in the store checks for a shared ID first, then voice protection. The shared-ID message is `More than one connection uses the ID "e1"; this action cannot choose just one.`, whichever order the protected holder is stored in.
  - A refusal sets only `connectionError`: definition, history, revision, save state and route ownership stay exactly as they were. A missing ID changes nothing and shows nothing.
  - The toolbar's Remove button is disabled with that same text, and it outranks the pan state. `onlyEdge` moved to `model.ts` and the stranded-edge recovery imports it.
- **F2 (stale selection):** the canvas selection records the loaded draft, the ID and the stored ends of every edge holding that ID.
  - It is cleared on any load (even the same ID and ends), a renamed end, or a missing port, and Undo doesn't bring it back. Moves, route, label and config edits, issue refreshes and their Undo keep it.
  - Remove, Reset, nudge, Delete and route-drag release all re-check it when they act.
  - A route drag is tied to the selection it started from, so a load mid-drag or a reselect before release writes nothing.
  - A stale action changes nothing, announces "That connection changed since it was selected; nothing changed.", clears the selection and moves focus to Undo. A refused live removal keeps the selection.
- **F3 (card drag):** `onNodeDragStart` now calls `gesture.move(event)`. Installed xyflow starts a drag on exactly the mouse move that also makes d3 block the next click, so the gate is armed only for drags that need it. Touch and keyboard moves are ignored. The gate's single mount-time listener, two-task settle and interface are unchanged.
- **A real bug the new tests found:** Reset route refocused the edge *after* resetting. On a stale reset that pulled focus back into the canvas, so a following Delete could reach a selected node. It now focuses first, then resets.
- **Keyboard behaviour:** a stale edge selection in the same key press swallows the key with nothing removed. After the canvas has cleared the selection, Delete removes the selected node as usual. That covers the Control-click, blank-route-ID, close sequence, and the Loop issues path; the hidden edge is never removed on its own. The handoff has the full table.
- **Docs:** docs/09, ADR-0076, guide 02, the CHANGELOG #207 entry and code comments no longer say card drags aren't gated, and describe the new refusal and selection behaviour.
