## F2

JSONata 2.2.2 places filters and groups on function and block nodes, generic containers, and path steps. Path steps and sorts can carry stages. The visitor analyzes those attachments against the selected item or group, retaining access through the explicit original root or injected thread binding. Tests exercise actual compiled expressions and evaluate the results before and after renaming. They cover unchanged local bare and current-item references, duplicated source spans from a coalescing expression, preservation of outside-key text, original-root shadowing and direct versus composite existence checks.

The installed evaluator implements a special case for a function directly on the right of ~>. It calls evaluateFunction rather than evaluate, so decorations on that function itself are skipped. Explicit authored references in those decorations produce a conservative uncertainty warning without claiming a repair or a runtime missing reference. Evaluated function arguments still participate in repairs, and an applied direct $exists remains optional. The exact installed evaluator SHA-256 is in identity.json. The 17-case [probe](jsonata-attachment-probe.mjs.txt) and [readback](jsonata-attachment-probe.jsonl) record the AST shapes and observed execution. The probe ran from packages/domain by piping the script to node --input-type=module.
