[before-metrics.json](2026-10-22-wp-e1-186/before-metrics.json) and the portable
[before-summary.json](2026-10-22-wp-e1-186/before-summary.json). Full and slow replay

late replay matches its durable suffix hash; the interrupted prefix plus reconnected
suffix matches the full hash. Every reader reports zero gaps. Run ids and timestamps
are fresh per invocation, so before/after hashes need not equal one another.

Source confirmation: `apps/api/src/sse.ts` on the base reads the entire replay in
one `store.read(runId, after)` before writing headers; the full replay's one read
took 1,161.63 ms. It ignores both event and heartbeat `res.write` return values and
pushes every concurrent live event into an unbounded array. SQLite's public
`read(runId, after, limit)` already supports bounded pages.

The harness completed correctness and profile checks but recorded a cleanup error:
`TypeError: container.repos.runs.listByStatus is not a function`. The obsolete cleanup
call is corrected to public `listRunReferences` for the after invocation; workload,
profiling and observers are unchanged. This first invocation is retained with that
limitation. It does not prove graceful harness shutdown. Captures over 1,000,000 bytes
are recorded by size and SHA-256 in [before-NOT-KEPT.md](2026-10-22-wp-e1-186/before-NOT-KEPT.md).

Outstanding wire bytes include kernel/client buffers and are sampled; they are not
isolated JavaScript writable-queue bytes. Zero sampled writable bytes on the baseline
does not establish zero temporary buffering. History browsing follows in #186 round 2.
