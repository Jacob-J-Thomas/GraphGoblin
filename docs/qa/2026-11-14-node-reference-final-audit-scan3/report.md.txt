When the first argument identifies a node map, the special `$lookup` branch records the outer key and immediately returns. For a computed key it records uncertainty, but never visits the key expression that JSONata actually evaluates. The uncertainty of the outer lookup does not make a structurally known read inside its key ambiguous.

Reproduction through public domain exports on the frozen compiled runtime:

- Renaming `start` to `renamed` in `$lookup(outputs, outputs.start.value).value` leaves the entire source unchanged. Only the edge endpoint is counted as repaired. The authored exit-return path is reachable in ordinary loops. Both editor `validateDraft` and API `loopPublicationIssues` consume `validateLoop`; `apps/api/src/routes/loops.ts:385` blocks publication only when those issues block publication. This is introduced by the new reference walker and directly defeats its repair/publication contract. It is distinct from original F2's evaluated attachment traversal: these are ordinary evaluated function arguments skipped by the `$lookup` early return.

Do not propagate the optionality of an outer `$exists($lookup(...))` into a key read that must execute, and do not replace the parser or infer the computed outer identity.
