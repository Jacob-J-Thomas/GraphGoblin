## Defect QA423-01: `__proto__` escapes the default server disable set

**Severity: Medium (P2).** This is a valid but unusual server name. It violates the central isolation guarantee and permits an inherited server to remain enabled without a node opt-in. No live model turn or extension launch is claimed.

Reproduction through the built product:

1. Point `GG_CODEX_BINARY` at this record's recording fake, in a disposable `gg-qa423-*` store. Its readiness answers satisfy version, help and login probes without contacting any provider.
2. Make its `listing.json` return `[{"name":"__proto__","enabled":true,"transport":{"type":"stdio","command":"qa423"}}]`.
3. Create and publish a trigger → inference → exit loop through `POST /loops` and `POST /loops/{id}/publish`. Select Codex, `gpt-6-luna`, `low`, with no config overrides.
4. Start it with `POST /loops/{id}/runs` and inspect the recording fake's listing and turn arguments.

**Expected:** `mcp_servers.__proto__.enabled=false` precedes the six feature defaults and `notify=[]`; alternatively, fail closed before exec if the name cannot be represented.

**Actual:** the product accepts the listing, invokes exec, and succeeds. It emits `mcp_servers={}` instead of disabling the named server. With `normal`, `__proto__` and `other` listed together, it disables only `normal` and `other`, silently omitting `__proto__`.

Evidence:

- Single-name run `01M60KF31VV61QQ124N8JWA0MN`: [run/events](server-__proto__.json), [listing and exec](server-__proto__-requests.log.txt).
- Mixed-list run `01M60KF6V6BCFZE65VJBK4A2GK`: [run/events](server-normal-__proto__-other.json), [listing and exec](server-normal-__proto__-other-requests.log.txt).
- `constructor` and `toString` controls retain their disable switches: [matrix](server-names-results.json).
- Three **no-turn** checks of the bundled real CLI 0.160.0 under an empty disposable `CODEX_HOME` establish the name's validity and configuration semantics: it lists `__proto__` as enabled; `mcp_servers={}` leaves it enabled; `mcp_servers.__proto__.enabled=false` disables it. The configured command does not exist and is never started by these listing commands. No credentials or personal Codex configuration are used. [Raw outputs](real-cli-name-validation.log.txt), [driver](validate-server-name.mjs).

To reproduce the complete fake-name matrix after the initial matrix has created its disposable store, run `node docs/qa/2026-10-28-wp-423-qa/edge-cases.mjs`. It uses the built gateway, published loops and the real SDK, and records both failing configurations. No product fix was attempted.
