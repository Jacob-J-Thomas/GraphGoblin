## What changed (only within the original eight files)
1. **A failed evidence preparation no longer skips the native tests.** Preparation now runs after Build and needs only checkout and Node, so it also runs after a failed install or build and records them as not run. The native step runs after any successful build. It only gets an evidence folder, and finalize only runs, when preparation succeeded; a failed preparation turns the job red and uploads nothing. The native, install and build commands are unchanged, and there is no `continue-on-error`, retry or deadline change.
2. **The manifest must be exactly what `init` wrote.** Finalize rebuilds it from its validated values plus the fixed limits and file names, then compares byte for byte. Unknown fields at any depth, duplicate keys, a byte-order mark, reformatting or inconsistent derived fields are refused before anything is uploaded. Legitimately unavailable values are still accepted. An observation file starting with a byte-order mark is now rejected, without claiming it leaked anything. This checks shape, not authenticity.
3. **Contradictions and repeats can't count as complete.**
   - Any applicable checkout comparison that is false gives `binding-contradiction`; a missing one gives `binding-unverified`.
   - Only the recorder itself can write its open, close, overflow and fixture-state records, and it rejects a second statement of a once-per-run fact.
   - Finalize rejects streams that break the recorder's lifecycle or repeat a fact.
   - Complete evidence now needs the actual trials 1–3 and both alias/direct releases per link kind, each from its own test case. Honest incomplete or failed evidence still uploads.

**Decision for you:** `complete` now also requires a verified binding, which is stricter than contradiction-only. Local runs without GitHub variables therefore report `binding-unverified`. If you'd rather block only contradictions, it's a one-line change.
