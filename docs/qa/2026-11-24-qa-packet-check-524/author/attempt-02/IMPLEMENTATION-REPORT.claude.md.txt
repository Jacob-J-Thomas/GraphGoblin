**What `pnpm check:qa --base <ref>` does** (`tooling/scripts/check-qa-packet.mjs`)
- **Selection:** it picks the `docs/qa` paths changed from the merge base of `<ref>` and HEAD to the working tree: committed, staged, unstaged and untracked, each listed once. Files Git ignores are left out.
- **Markdown:** it checks Markdown in memory with the repository Prettier config, even when `.gitignore` or `.prettierignore` hides a page from `pnpm format:check`.
- **Other files:** files Prettier would normally check are checked the same way. Everything else, including `.md.txt` originals and ignored JSON, is left untouched and listed with its SHA-256.
- **Originals:** a newly added Markdown file whose name ends in "original" is refused. Historical files, directory names and other uses of the word are not affected.
- **Missing paths:** a path that existed at the merge base and is now gone counts as a deletion. Any other selected path missing from the working tree (sparse checkout, skip-worktree, or an addition that was later removed) is reported as not checked and fails.
- **Exit codes and read-only:** 0 means passed, 1 means a path failed, 2 means it couldn't run, with no partial report. Git runs without optional locks, and the test confirms the index and file bytes are unchanged.
- **Unchanged:** `format` and `format:check` in `package.json` are the same, and `check:qa` is not part of `pnpm check` or CI. The behaviour is documented in docs 10 and 15 and the CHANGELOG.
