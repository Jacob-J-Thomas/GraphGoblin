**Why the flag alone wasn't enough**
`--no-optional-locks` only governs `git status`. `git diff` rewrites the index whenever it finds an index entry whose timestamp is stale but whose content hasn't changed. The setting that stops that rewrite also stops the content check, so such files start showing up as modified. In the test repository this selected 8 paths instead of 6 and reported a historical raw original as `UNFORMATTED` (exit 1). That breaks the "only changed paths" scope.

**What changed**
- **`tooling/scripts/check-qa-packet.mjs`**:
  - Every Git call now passes `-c diff.autoRefreshIndex=false` on its own command line. No repository or global Git config is touched.
  - The checker then runs `git ls-files --modified` and drops any unstaged `M` entry it doesn't list. That command compares content and never writes the index, so a file with only a new timestamp is still left out. Other statuses (`D`, `A`, `T`, `U`) are untouched.
