## Finding

**[P2] Prevent the unstaged diff from refreshing the index** — `tooling/scripts/check-qa-packet.mjs:117` (Git helper at lines 58–67).

The checker invokes ordinary `git diff` to find unstaged QA paths. On supported Windows Node 22.23.4 with Git 2.49.0.windows.1, a clean tracked file whose timestamp changed but whose contents did not causes that diff to write a refreshed `.git/index`, despite both `--no-optional-locks` and the helper's `GIT_OPTIONAL_LOCKS=0`. The frozen CLI then exits 0 and claims a successful read-only check. This violates the brief's read-only/index-byte invariant and the documentation's promise that no index stat refresh is written.

This is the checker itself, not a test-side `git status` or post-check diagnostic side effect. The original public-command test failed 9/10 at `check-qa-packet.test.mjs:330`; a targeted repeat failed the same assertion. In an independent disposable reproduction, immediately reading `.git/index` before and after the actual frozen CLI shows SHA-256 changing from `31092e93271a6d35b70efd411aa2791f4ccfc1212c3d5ffc962dca481c1ebe3e` to `24d464cbea8d2016ade849b82bb04ef7c923648bbd98bde6187e7635940e9ad7`. No Git helper runs between those reads. Selected source bytes are unchanged.

Sequential snapshots around the individual CLI Git commands isolate the mutation to the unstaged diff: its index SHA changes from `24d464cbea8d2016ade849b82bb04ef7c923648bbd98bde6187e7635940e9ad7` to `ff74d56826d553367313775de5bea2ef579c1c88fd19fe7eb35f532bd76f216d`; top-level resolution, base resolution, merge-base, cached diff and untracked listing leave it unchanged. The Git Trace2 events for the diff explicitly record `do_write_index` on `.git/index.lock`. A control with `-c diff.autoRefreshIndex=false` preserves the index hash after rewriting the same clean page with the same bytes. This supports disabling automatic index refresh (or another genuinely read-only selection strategy); the required outcome is unchanged source and index bytes while retaining the same selection.

Disposition: **FIX-IN-PR**. P2 is appropriate: this does not change staged content or lose data in the reproduction, but it directly breaks an accepted authority invariant and an existing delivery test. Do not fix by relaxing the assertion or weakening the documented read-only contract.

Minimal reproduction retained in `readonly-repro.mjs`: initialize a disposable repository, commit a clean historical `docs/qa` page, prepare the staged/unstaged/untracked publication changes, rewrite the clean historical page with identical bytes, snapshot `.git/index`, run the actual CLI with `--base main`, snapshot `.git/index` again. The script retains per-command binary snapshots, results and Trace2 data. The fixture remains at the path recorded in `readonly-repro-result.json` for inspection.
