## Finding

**[P2] Exclude Git-equivalent content when filtering unstaged paths** — `tooling/scripts/check-qa-packet.mjs:127–129`.

The new `ls-files --modified` set does not fully remove the false modifications exposed by disabling `diff.autoRefreshIndex`. In a disposable repository with the project's exact `* text=auto eol=lf` attribute and `core.autocrlf=true`, a previously committed historical Markdown page rewritten from LF to CRLF has the same normalized Git blob as HEAD/index. Ordinary pre-correction `git diff --name-status` selects nothing. The corrected checker nevertheless selects that page as `UNFORMATTED` and exits 1. It therefore checks a historical page with no publishable change and asks the delivery operator to format it, violating the accepted changed-path selection scope.

The executable reproduction `autocrlf-check.mjs` creates that one-page repository and runs the actual corrected CLI from the fixture's working directory with isolated Git configuration/environment. `AUTOCRLF-CONFIRMED.json` records:

- normalized worktree hash and indexed blob both `1a6d5b21ef7f862ce98ec5e42aa38e1ac7f18ef6`;
- `git diff` with automatic refresh enabled: no changed path;
- automatic refresh disabled: `M docs/qa/historical/README.md`;
- `ls-files --modified`: the same historical path, so the new filter retains it;
- actual corrected CLI: one selected `UNFORMATTED` historical page, exit 1;
- index SHA-256 unchanged across the corrected CLI: `61c70fe6d7dbf8324bedca84d90d92289aa59ba60f8ad8971df6d7f799a1e7a7`.

This explains the precise limit of the author's content-comparison claim. Git's [`ls-files` implementation](https://raw.githubusercontent.com/git/git/v2.49.0/builtin/ls-files.c) calls `ie_modified`; [`ie_modified`](https://raw.githubusercontent.com/git/git/v2.49.0/read-cache.c) can return immediately for `DATA_CHANGED` with a nonzero cached size, before reaching its filesystem content comparison. That shortcut covers this LF-to-CRLF size change. The timestamp-only control has equal bytes/size and passes, but does not establish full normalized-content equivalence. The implementation comments and docs should describe the eventual behavior accurately.

Disposition: **FIX-IN-PR**. It is introduced by this correction and directly violates the approved selection contract. The required outcome is byte-identical index/source data and exclusion of normalized-equivalent paths under ordinary settings and the repository's EOL attributes with autocrlf, while still selecting real committed, staged, unstaged and untracked changes. The review does not prescribe a filter algorithm. Preserve a meaningful public-command regression for this case; do not weaken the historical scope or byte-preservation assertions.
