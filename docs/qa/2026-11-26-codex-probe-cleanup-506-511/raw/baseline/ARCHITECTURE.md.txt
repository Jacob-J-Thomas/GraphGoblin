## Architecture disposition

1. `runCli` owns settling the exact child it spawned. Ordinary completion still resolves from close. Timeout or cancellation preserves the first failure and requests termination, then waits for close within a separate two-second cleanup allowance. If the child remains alive, allow a single stronger termination request within that same allowance; do not extend the total allowance, walk unrelated process trees, or treat a kill request as proof of exit. A missing binary without a child must not wait unnecessarily. Register listeners and timer state safely for immediate error/abort races. Drain bounded existing output semantics and preserve per-turn listing cancellation. This is an orchestration deadline, not a guarantee against arbitrarily stalled synchronous OS calls.
2. Preserve timeout/auth/missing-binary states and existing public readiness classification. If termination or removal still fails, retain a distinct bounded cleanup diagnostic alongside the original failure; do not replace the primary cause or expose arbitrary CLI output, credentials, paths or raw error messages. Prefer a narrow internal result field and an additional safe existing readiness problem string over a public schema change. A successful inspection whose cleanup fails remains `unknown` as today. Do not retry removal indefinitely. Wait for process settlement before the one ordinary removal; any bounded removal retry requires a demonstrated separate filesystem mechanism, not speculation.
3. #511 allocates the live fixture during the enabled suite lifecycle, not test collection. Cleanup must run for the allocated fixture on supported suite completion/failure. No directory is allocated when disabled. Keep the live suite's opt-in semantics and test behavior. Independently exercise actual collection with `LIVE=0`, plus an enabled lifecycle with test-controlled adapters and a selected no-turn case; no real Codex/Claude model request or owner configuration is permitted.

Rejected alternatives: ignore leftover directories, sleep a guessed number of milliseconds, broaden filesystem retries, raise command deadlines, skip native assertions, or introduce a general process-supervisor subsystem. Waiting for the actual child close directly addresses the observed race. The two-second cleanup bound is a delegated implementation decision for later owner catalogue review; it is not a claim that every OS failure can be recovered.
