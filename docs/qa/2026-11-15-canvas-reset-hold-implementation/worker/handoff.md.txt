## What the production change does (`OrthogonalEdge.tsx`, `RouteHandles` only)

- **State.** A local `hold` is `{ at, crossing, reset }`. `at` is the label the toolbar was centred on when Reset route was accepted. `crossing` records whether the Crosses a card note was showing. `reset` is the manual route's `points` array until the automatic route has been drawn.
- **Click.** The Reset click runs `event.stopPropagation()` first, like Remove connection, so Control or Meta cannot reach xyflow's edge wrapper and toggle the selection off. It then refuses when the gesture gate is not ready or the route is not manual. Otherwise it sets the hold, focuses the edge, then calls `editing.reset`. The focus-before-reset order and the refusal priority are unchanged.
- **Anchor.** The toolbar `<g>` uses `hold?.at ?? labelAt`.
- **Slot.** Reset renders when `manual || hold`. It is `aria-disabled` when settling or when the route is not manual, with the title "The connection already routes automatically." It stays a real, focusable, `nopan` hit target. `data-gesture` and the 32/44 px classes are unchanged.
- **Crossing chip.** It is the same `<span>` slot. While held it gets `invisible` and `aria-hidden="true"`, so the width is kept and nothing is announced.
- **Lifetime** (settled while rendering, as the canvas does for its selection):
  - While the route is not manual, the automatic route has been drawn: `reset` is cleared.
  - When the route is manual and `points !== hold.reset`, the hold ends. After the automatic route `reset` is `undefined`, so any manual route ends it, whatever array it arrives as. Before the automatic route, only a different array does.
  - The hold is also gone when `RouteHandles` unmounts (deselect, load, stale-refusal, removal).
- **Not added.** No timer, click-count guard, event suppression, redispatch, global guard or new gate. No change to the route-editing interface, the canvas selection or xyflow. No new dependency (`@testing-library/user-event` was already a dev dependency).

### Lifetime evidence against the real store and channel

The root asked that the lifetime not rest on an assumed point-array identity. A throwaway probe was a copy of `Canvas.test.tsx` with one added test, run once and deleted. It was never tracked, and `git status` shows no untracked file. It recorded, for the real store, route channel and Undo (`scratch/probe-identity.jsonl`):

| Connection | Route object after Undo the same as before Reset | `points` array the same |
| --- | --- | --- |
| loop-back `return` | no | no |
| forward `start-work` | no | no |

Today's Undo therefore does return new arrays. The design does not depend on that, and a unit test pins the case where Undo returns the same array. A mutation that implements only the point-reference comparison (`identity-only` below) fails exactly that unit test, and passes the real-Canvas tests, as this probe predicts.

## Rationale and limits

- A hold rather than a click-count guard: the second press then lands on the same unavailable Reset instead of Remove connection. A placeholder alone, or the held anchor alone, would still leave Remove under the point. This follows the Opus design and the root admission.
- What this guarantees (and what the jsdom tests check): the same attached Reset element, the same toolbar transform, no write, no removal and an unzoomed viewport for any press that targets the held Reset. It does not prove native hit-testing or timing. The native double-click, the revised native checks in the design and the preservation matrix are for the root's independent QA.
- Bounded tradeoffs, documented in `docs/09`:
  - The held toolbar can sit apart from the automatic label, or from a card moved since. It can cover a handle or the label until the hold ends.
  - There is no optional release on a pan or card drag.
  - A stray press in the 8 px gap reaches whatever is under the toolbar, never Remove.
- Not covered (separate work): selecting a connection then pressing Remove (report 64dbcc54), the Fit placement of #479, shared route ownership #481, and the effect of Remove's own unmount on a third press.
- The `e2e` edit is typechecked, linted and formatted but not run.
- `logs/08-candidate-v2-hashes.txt` is an intermediate hash list taken before the final docs sentence edit. Use `final/final-manifest.json` for the final hashes.
