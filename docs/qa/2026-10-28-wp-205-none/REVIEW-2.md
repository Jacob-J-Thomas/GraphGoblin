## Finding

1. **P2 — The catalog and run UPDATEs do not guard every JSON source they read.** `CHANGELOG.md:22`, `CHANGELOG.md:23`; generated by `scripts/effort-sql.mjs:105` and `:106` in this record folder.

   Their `json_valid` checks guard individual **WHERE** predicates, but a different predicate can select the row while an unguarded **SET** expression still reads malformed JSON. The recipe then aborts with `SQLITE_ERROR: malformed JSON`, contrary to the generator comment and README's assurance that damaged rows are skipped rather than failing a statement.

   **Reproduction:** Run [review2-scripts/sql-checks.mjs](review2-scripts/sql-checks.mjs). It parses the recipe from the CHANGELOG, not the generator, and reproduces each case separately on disposable SQLite stores:

   - A catalog row with `default_effort = 'minimal'` and `efforts = 'not-json'`: the default-effort predicate matches, then the SET's `json_each(model_catalog.efforts)` fails.
   - A run with valid `pinned` containing an owner default effort `minimal`, and `failure = 'not-json'`: the pin predicate matches, then the SET's `json_extract(failure, ...)` fails.
   - A run with `pinned = 'not-json'` and a valid missing-session failure whose effort is `minimal`: the failure predicate matches, then the SET's pin expressions fail.

   The SELECT itself completes in these three cases. All three UPDATE failures also reproduce on copies of the **real, base-created current-format stores** used by my history fixtures, with the actual schema, through [review2-scripts/real-guards.mjs](review2-scripts/real-guards.mjs). This is not an inference from source alone. Evidence: [review2-sql-checks.log.txt](review2-sql-checks.log.txt), [review2-real-guards.log.txt](review2-real-guards.log.txt).

   **Expected:** Guard each JSON source used in SET, or skip a row unless every JSON source that statement touches is valid (while allowing nullable `runs.failure`). Preserve unrelated damaged data for separate hand repair. Correcting one typed `minimal` must not cause an unguarded read of a malformed sibling column. Keep the discovery predicate, generated recipe, CHANGELOG and stated damaged-row behavior consistent. This needs no automatic migration, converter or compatibility parser. Since the first eight statements run before the snapshot transaction, a failure here can interrupt the operator's recipe after earlier statements have committed and leave later valid history rows uncorrected.
