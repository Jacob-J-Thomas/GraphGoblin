## Original failure and offline warning correlation

The native supervisor completed every behavior wave and both ordinary drains, then exited **1** at its strict warning-correlation assertion for `corrected-lone-P3`. It compared a gateway warning timestamp to a separately received probe timestamp. In the preserved initial log, lone P3 and split P3 warnings appear at lines 164 and 165, each 1 ms before that probe-reception timestamp. The unmodified [execution receipt](corrected-preparation-v3/execution-completions.json) records native exit 1.

The separate offline checker used each gateway's `armed.nextPollAt` as the causal lower bound and the next inert request as the exclusive upper bound. Its 21 windows were disjoint and assigned all 20 warnings once; the two disputed warnings were 30 and 31 ms after due. It checked the gateway PID, loop ID, trigger node, exact warning fields and sizes without adding tolerance or changing the fixture. The offline command exited 0. Root read and accepted this reanalysis while preserving the native failure and making no rerun.
