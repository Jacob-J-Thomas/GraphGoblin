## 7. Decisions and parameters

**Proposals for the engineering-parameter register; not owner-approved numbers.**

| Parameter                       | Implemented proposal and reason                                                                                                                                                                                                                                         |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Attempts                        | Five total, including uncertain interrupted attempts. Small finite recovery budget; restart never resets it.                                                                                                                                                            |
| Request/acknowledgement timeout | 10 seconds per attempt, including complete response-body acknowledgement.                                                                                                                                                                                               |
| Backoff                         | After failures 1–4: 2, 5, 10, 20 seconds. Nominal uninterrupted total is 87 seconds plus local scheduling/storage overhead. Fixed delays keep the single-process local schedule reproducible; no jitter. Downtime may extend elapsed time.                              |
| Identity                        | Standard `Idempotency-Key` header, stable opaque identity for one distinct return channel. New completions allocate a ULID atomically with `run.finished`; retries/recovery reuse it. No recipient deduplication is assumed.                                            |
| Eligible                        | Connection refusal, timeout, HTTP 408/429/5xx, unknown transport acknowledgement.                                                                                                                                                                                       |
| Permanent                       | Invalid/unsupported destination, URL credentials, 3xx without following redirects, other 4xx.                                                                                                                                                                           |
| Positive acknowledgement        | Complete 2xx response, drained without retaining its body, within the same timeout and 64 KiB bound. Truncation/overflow/lost EOF is unknown.                                                                                                                           |
| Run field                       | Optional `RunRecord.deliveries[]`; pending/delivered/failed, consumed/max attempts, in-flight flag, next time, acknowledgement, sticky effect-possible flag and typed last error.                                                                                       |
| Events                          | `delivery.queued`, `delivery.attempted`, `delivery.attempt_finished`, `delivery.finished`; each carries a complete state snapshot. Attempt intent is durable before network I/O. Final state is projected from the same event, with no second fallible status write.    |
| Lifecycle                       | Background delivery does not consume an execution slot. Orderly idle waiting drains delivery tasks. A terminal run remains unfinalized until all delivery outcomes exist; recovery restarts pending workers without blocking API startup on acknowledgement or backoff. |
| Historical conversion           | SQL 0015 rewrites completed old receipts once. An unfinished old return consumes one unknown attempt and receives a new identity with four retries; that key cannot retroactively deduplicate the pre-upgrade request. Current schemas reject retired receipt shapes.   |
| Inspector refresh               | Poll the run once per second while delivery is pending. Execution-terminal SSE closure remains separate; JSON event pages expose later delivery events.                                                                                                                 |
