## Blocking finding

**[P2 · FIX-IN-PR] Omit leaves native incomplete number text in the field while excluding it from the request.**

In an optional integer field, press `-`, then submit. The form correctly shows the numeric error and emits no request. Focus the field, press Shift+Tab to reach its Omit button, and press Enter. Omit and the message disappear and focus returns to Count. The control still displays `-`, retains `validity.badInput === true`, and fails both field and form native validity. The submit action remains enabled. The form uses `noValidate`, so the browser allows submission and the UI omits Count. I reproduced this through both New run and Wait, with real HTTP 202 and 200 responses and successful persisted run output. The entered/omitted form display no longer agrees with the request. [Exact browser record](focused-repro-attempt3.json) · [New run before](newRun-before-omit.png) · [New run after](newRun-after-omit.png) · [Wait before](wait-before-omit.png) · [Wait after](wait-after-omit.png).

The change introduces both the edited-empty state for native `badInput` at [JsonSchemaForm.tsx L399](../../../../apps/web/src/forms/JsonSchemaForm.tsx#L399) and the action that removes it at [L380](../../../../apps/web/src/forms/JsonSchemaForm.tsx#L380). That action focuses the control and deletes its map entry at [L210](../../../../apps/web/src/forms/JsonSchemaForm.tsx#L210) and [L474](../../../../apps/web/src/forms/JsonSchemaForm.tsx#L474). An incomplete native input already exposes `element.value === ''`. The React number update only assigns `element.value` when the passed value differs (plus a numeric-zero special case), while this form passes string `''` both before and after Omit. The actual native edit buffer survives. The form skips the deleted map entry at [L494](../../../../apps/web/src/forms/JsonSchemaForm.tsx#L494) and accepts the remaining schema-valid object at [L524](../../../../apps/web/src/forms/JsonSchemaForm.tsx#L524). react-dom@19.3.0 updateInput implementation.

The current native test creates `badInput` and recovers with a value, then omits a separate text field. The neighboring-touch regression covers text and JSON. The jsdom simulation uses a supplied validity property so it does not exercise the browser’s native editing buffer. [Native regression L328](../../../../apps/web/e2e/form-controls.spec.ts#L328) · [Component simulation L194](../../../../apps/web/src/forms/JsonSchemaForm.test.tsx#L194).

Clear the existing native input value explicitly on numeric omission, before restoring focus and deleting the map entry. A numeric-only callback or equivalent local reset preserves the shared action, neighboring inputs and layout. Extend the native regression with the incomplete-then-Omit sequence and assert `badInput` clears, focus returns, Count is absent in the actual request and a neighboring edit survives. A value getter alone cannot catch this case because it reports the empty string throughout the failing sequence.
