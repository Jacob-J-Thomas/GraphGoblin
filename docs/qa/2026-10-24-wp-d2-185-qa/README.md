## 2. Defects

### QA-185-01 - minor - heartbeat bypasses the 250 ms quiet-finalization check interval

Steps: copy [cost.mjs.txt](cost.mjs.txt) to `%TEMP%/gg-qa-d2-185-cost.mjs`, run it with Node 22 from this worktree, and drain three real HTTP streams for a minute. The built SSE handler receives an explicit EventStorePort plus a consumed terminal lifecycle and a finalization callback that remains false. There are no delivery or lifecycle notifications. Expected: after initial catch-up, finalization/store rechecks are at least 250 ms apart; closing releases them. Actual: 227 finalization checks per stream by the 60,071 ms checkpoint, including initial confirmation, with short gaps aligned to the 15-second heartbeat. Minimum observed gaps: 0.0296, 31.8644 and 31.9470 ms for streams 1-3. There are 5/4/4 intervals below 249 ms inside the measurement window.

Evidence: [cost.json](cost.json) (raw call times), [cost.log.txt](cost.log.txt), [sse-source.txt](sse-source.txt). The pending branch leaves `needsConfirmation` true while its 250 ms timer is armed; heartbeat completion also calls `flushLive()`, which can run the confirmation before that timer. This remains bounded overall and did not cause premature completion, hence minor severity. The precise read counts are a public-port/component measurement, not direct instrumentation of SQLite.

Focused isolated confirmation: [cost-isolated.json](cost-isolated.json) and [cost-isolated.log.txt](cost-isolated.log.txt); minimum gap 0.943 ms across three streams; all subscriptions released; no further reads after close.

The real built gateway measurement is separate: three subscriptions plus a pending real webhook for 60094 ms consumed 1969000 CPU microseconds (3.28% of one core). All three remained unfinished, REST stayed succeeded/pending with no marker, and the acknowledgement uncertainty survived timeouts. [adversarial/results.json](adversarial/results.json) and [adversarial.log.txt](adversarial.log.txt). No CPU SLA is inferred from this workload.
