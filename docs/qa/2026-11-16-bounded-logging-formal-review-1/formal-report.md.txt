### P1 · FIX-IN-PR · Managed trace logs retain malformed HTTP packet bytes

**Root cause** `managed-http/client-error-bypasses-access-projection`  
**Location** `apps/api/src/gateway-logger.ts:42–45`, reached through `apps/api/src/serve.ts:36,83` and `apps/api/src/app.ts:40–48`.

The supported launcher override `GG_LOG_LEVEL=trace` enables Fastify's default parser-error logging before a Fastify request or reply exists. Send a short raw HTTP request for `/healthz?parserQueryCanary=1` with a synthetic authorization header and an invalid header name in the same input buffer. Node 22.23.4 assigns the parser's current buffer to the error's enumerable `rawPacket`; the pinned Fastify 5.12.5 handler logs the error with `this.log.trace({ err }, ...)`. Pino 10.3.1 retains its default `err` serializer when supplied the managed `req` and `res` serializers. Its pinned serializer copies enumerable fields, so `err.rawPacket` becomes a JSON Buffer representation containing the URL, query, headers and any other bytes from the current buffer. A short packet fits the per-record ceiling. The encoded numeric byte array can evade a search of the log text for the original canary. At the default `info` level this particular trace log is suppressed. [Pinned dependency readback](pinned-source-readback.md) · [Node parser error construction](https://github.com/nodejs/node/blob/v22.23.4/lib/_http_common.js#L266-L269) · [Node parser error dispatch](https://github.com/nodejs/node/blob/v22.23.4/lib/_http_server.js#L859-L890)

The default handler predates this PR. The new managed projection is the code under review and leaves that reachable path outside the newly required access privacy boundary. Contract §1 and ADR-0081 allow method, registered route template and status for managed access records and explicitly exclude raw URLs, query strings, headers and request bodies. Core and supplemental cases show ordinary routed access and the four canaries reaching the controlled request serializer. Those tests exercise a later stage than the HTTP parser or socket handler.

Apply the managed access restriction at the parser-error logging boundary while preserving response/close behavior, the configured level, ordinary shell behavior and the full private engine error diagnostic. Verify a malformed wire request at managed trace level, inspect decoded structured log fields or their byte representation, and check the expected HTTP error plus an ordinary request afterward. Retain the routed access and private engine error controls.

### P2 · FIX-IN-PR · Coalesced writes retain two copies of encoded payload

**Root cause** `gateway-writer/coalesced-batch-duplicates-retained-bytes`  
**Location** `apps/api/src/windows-log/gateway-log-writer.ts:400–428` and the awaited write at lines 433–439.

`writeBatch` removes the selected `Pending` items from the queue and charges one `length` to `inFlightBytes`. For a multi-record selection, `Buffer.concat` creates a full copy. The `batch` array stays live across the name check and file write because the completion closure still iterates it for acknowledgments. The original items still reference their `bytes` buffers. With an empty remaining queue, the cap is crossed at a coalesced batch of 131,073 B, which retains 262,146 B of encoded payload while the counter reports 131,073 B. For example, queue three complete JSON records of 65,536 B, 65,437 B and 100 B while a prior write is blocked, then release that write and hold the next one. Supplemental C-3 already reached the larger coalesced write of 196,608 B after releasing its first held 65,536 B write. Its transition retains 393,216 B across the awaits by source inspection. During a stalled rotation before dequeue the queue can fill to 262,144 B and yield up to 524,288 B of coalesced payload copies. [Node Buffer concatenation](https://github.com/nodejs/node/blob/v22.23.4/lib/buffer.js#L542-L578)

The finding concerns strongly referenced encoded payload across asynchronous I/O in the new writer. The logical pending count and the observed one-operation limit hold. The source argument excludes temporary encoder allocations, buffer allocator overhead, and whole-process heap metrics. The unit checks at `gateway-log-writer.test.ts:383–397` and supplemental C-3 assert logical accounting, write size and order. They do not distinguish the duplicated backing bytes. Contract §4 sets one combined 256 KiB encoded budget for queued and in-flight data, including markers.

Keep one retained copy per encoded record across I/O, or account every simultaneously retained copy under the same cap. Verify the multi-record held-write transition, preserving write order, per-record acknowledgment, short-write rollback, and eventual drops at the bound. A single-record stalled write cannot catch this regression.

### P2 · FIX-IN-PR · Destination contention guidance attributes ownership without evidence

**Root cause** `launcher/destination-conflict-overstates-owner`  
**Location** `apps/windows-launcher/Launcher.cs:347–351,361–366,817–844` and `docs/guide/07-troubleshooting.md:14–17`.

Both a child reservation conflict and a parent file-sharing violation use the same introduced text. It states that another GraphGoblin gateway is already using the log folder and directs the operator to shut it down. Neither predicate identifies a process. Supplemental N-9 demonstrated the child-70 case with a cooperating plain Node pipe holder and empty slots. In that case there is no gateway to shut down and the prescribed recovery cannot clear the conflict. The parent observes only Windows sharing error 32 on the validated file. Contract §3 specifies reservation unavailability without attribution. ADR-0081 records the same distinction. The guard itself uses the correct closed code and the launcher still fails safely.

Keep the refusal code and explain the observed reservation or file-sharing conflict with conditional GraphGoblin shutdown guidance and a retry once the holder releases it. Keep the same evidence boundary in troubleshooting. Verify the holder-only and actual legacy writer cases with the existing native controls.
