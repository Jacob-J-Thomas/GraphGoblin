## 2. Blocking findings

1. **B1 / P1: A durable uncertain-script failure can be advertised and admitted without consent while its run-row status is still older.**

   **Locations:** `packages/engine/src/run-recovery.ts:64` derives uncertainty only from `run.status` and `run.failure`; `packages/engine/src/run-manager.ts:1188` checks sequence advancement but not disagreement between the row and the durable lifecycle event. The normal failure path deliberately appends `run.failed` at line 2954 before projecting status at line 2955. Paused Resume's claim at lines 1441-1457 checks only status and can append a newer `run.resumed` in this window.

   **Observed behavior:** after the real script produced one marker, SQLite durably contained `run.failed` sequence 7 with `SCRIPT_OUTCOME_UNCERTAIN`. GET returned `status: running`, `observedSeq: 7`, and Replay at `effect` as allowed, with no `scriptConsent`. POST Replay with only `{nodeId: 'effect', observedSeq: 7}` returned **202** and its new run succeeded, producing marker **2**. After the original failure acknowledgement was released, the original run became failed and required consent at the **same observation 7**. Matching the observed tail therefore did not bind the command to a consistent failure/consent decision.

   The component variant also covers a paused source. Resume was accepted after its uncertain failure was durable, appended `run.resumed` after `run.failed`, and then lost to the delayed failed-status projection. The source remained failed after a new public RunManager started, but recovery reported **RUN_ACTIVE** and refused supported Resume. Dispatches stayed at one in this variant; it establishes an invalid accepted action and persistent liveness/refusal problem, not an observed automatic script retry.

   **Requirement:** #256 controls must represent valid recovery, #321 requires deliberate recovery of uncertain effects, and ADR-0061 binds consent to the reviewed failure. These are ordinary public storage-acknowledgement interleavings, not an unsupported private-state mutation.

   **Smallest fix:** make eligibility use a consistent durable lifecycle/failure observation, or fail closed with a refreshable reason while its projection is incomplete. An equal `lastEventSeq` is insufficient. Also make the paused Resume claim observation-aware/atomic (including the parked-wait branch), so a failure winning after eligibility cannot append an unconsented Resume. Keep reads free of execution-state mutation and retain bounded queries. Add regressions for the failure append/status gap and for a failure winning between policy and the paused claim; assert consent, exact accepted IDs, marker counts and recoverability after restart.

   **Reproduction:** [failure-projection-native.mjs](failure-projection-native.mjs), [its public-port fixture](failure-projection.fixture.mjs), [native results](failure-projection-native-results.json), [native log](failure-projection-native.log.txt). The fixture uses the built API, real SQLite and a native marker-producing script. A SQLite trigger refuses progress persistence; an EventStore dependency delays only acknowledgement after the resulting failure append is committed. It does not patch RunManager internals. [Component probe](failure-projection-race.mjs), [three-scenario results](failure-projection-race-results.json), and [paused/restart result](failure-projection-paused-results.json) isolate the ordering with controlled script ports.

   To reproduce from the built worktree with Node 22 first on PATH, set `GG_AUDIT_REPO` to that worktree and `GG_QA_ROOT` to a fresh child of the current system temp directory whose basename starts `gg-audit-422r3-`, then run `pnpm.cmd --config.verifyDepsBeforeRun=false exec node "$report\failure-projection-native.mjs"`. The script uses port 6655. Run `failure-projection-race.mjs` for the controlled variants; `GG_PROBE_SCENARIO=paused-resume` retains the restart-specific result. **Exit zero means the defect was reproduced, not that the product passed.**

2. **B2 / P2: Unreadable definition JSON now hides a readable run behind a generic HTTP 500.**

   **Locations:** `packages/engine/src/run-manager.ts:1180` newly decodes the pinned definition before returning a run snapshot, outside a definition-decode fallback; its catch at line 1200 handles only `UnreadableRunHistoryError`. `packages/engine/src/run-recovery.ts:21` has the same decode-before-`safeParse` boundary. `packages/infrastructure/src/sqlite/loops.ts:87` returns a Drizzle JSON-decoded version.

   **Observed behavior:** create and finish a valid run, then change only its stored `loop_versions.definition`. With syntactically valid but invalid-shape `{}`, GET returns 200 with `DEFINITION_UNAVAILABLE` and both recovery commands return 409 with that code. With malformed JSON `{`, GET, Resume and Replay all return **500 INTERNAL_ERROR**. The run row and its event history remain readable. On the pinned target main, the same two damaged definitions both leave GET `/runs/:id` returning **200**. The new recovery read has therefore introduced a read-availability regression.

   **Requirement:** #256 says unavailable controls must be explained; ADR-0061 explicitly defines `DEFINITION_UNAVAILABLE` for a pinned definition that is unavailable or cannot execute. D-016 preserves readable evidence when related stored data is damaged. The audit expressly includes malformed on-disk input. This does not request legacy-format compatibility or automatic repair.

   **Smallest fix:** distinguish a stored-definition decode/validation failure at the repository boundary and translate it to the existing unavailable-definition action. Keep the otherwise readable run visible, refuse commands consistently, and do not catch arbitrary database/transport failures as corruption. Extend the current deleted-definition test (`apps/api/src/recovery-eligibility.test.ts:359`) with malformed JSON, not just a missing row or valid JSON of the wrong shape.

   **Reproduction:** `pnpm.cmd --config.verifyDepsBeforeRun=false exec node "$report\unreadable-definition.mjs"`; [script](unreadable-definition.mjs), [head results](unreadable-definition-results.json), [head log](unreadable-definition.log.txt). [Baseline script](unreadable-definition-baseline.mjs), [baseline results](unreadable-definition-baseline-results.json), [baseline log](unreadable-definition-baseline.log.txt) perform the read comparison against the exact target source using the isolated baseline emit described in section 5. The SQL change is confined to a disposable file-backed database and the original definition is restored.
